# 路由配置与执行事务契约

原生配置树、提交协调、执行能力和备份的唯一详细契约；服务拓扑与依赖见[领域所有权](dependency-owners.md)。

## 复合网络执行批次

network-protocol::configuration::batch 拥有唯一的网络执行外层版本 1：u32 版本、u64 接口正文长度、u64 完整 FIB 正文长度，随后顺序放置两段正文。
接口段为零表示没有接口变化；FIB 段为零表示保持原受管集合，非零的空集合则撤销该来源与具名定义。两段都没有、未知版本、长度溢出/截断与尾部拒绝。
内层接口和 FIB 仍各用原领域 codec，不复制字段模型、成员数组或逐路由解析对象；编码器接管接口前缀存储并直接追加 FIB 字段，不再创建第二份完整 FIB 编码。
Writer::from_bytes 只接管已初始化前缀，framing 由该领域保证；into_bytes 移交唯一存储。两者不添加 RPC 头、分配或校验，也不建立额外缓存。

Installer 只有 PREPARE_CONFIGURATION(2) 接收该正文，控制字段为 u64 逻辑长度及一个只读 VMO。
旧 PREPARE_ROUTES(3) 及其客户端入口已移除；无接口的 FIB 替换也只调用 prepare_configuration，没有独立内联/旧完整集合分派。
ConfigurationBatch::encode_forwarding 从冻结组/路由迭代器复用同一字段 codec，不收集整份逐前缀 DTO；slice 构造委托同一实现。
RIB 完成选路编码后把 Vec 移交 NetworkInstaller::prepare_configuration，后者只负责只读 VMO 传输，发送前释放编码副本；服务端仍完整验证。
具名单槽更新仍是不同语义的独立操作。
服务先捕获独占字节并完整验证两段，才进入 NET；回复能力容器在副作用前预留，失败不留下事务或部分发布。router-config/RIB/netstack 必须配套交付该布局。

预备只取得一份写租约：接口前像、新地址/MTU 事实、小规模邻接候选和完整受管集合进入同一个最终 FIB 候选，只编译一次 Poptrie。
下一跳/显式源的准入共用 admit_with，读取候选设备事实，并合并未受影响的活动前缀和新邻接；将撤销的旧地址、旧受管路由不能证明新输入有效。
新邻接草稿只含自动接口路由，默认路由只来自 RIB；不追加受管全表，不为每个受管前缀线性扫增长候选表，也不构造第二个完整中间根。
活动和邻接候选共用 StoredRecord 的成员/设备选择，不维护另一套 eligibility 或结果缓存。
事务同时拥有受影响接口和受管下一跳依赖：激活前全部检查；同一临界区交换根并发布接口；撤销先恢复存活接口再恢复原根、过滤热拔出并报告 NoDevice。
接口不变、FIB 不变及两者同时变化均沿同一事务 owner 和发布/撤销机制，没有第二份活动状态。接口与静态来源已接入 RIB，完整多表/双栈配置仍待接入。

## 原生 RIB 配置来源

`routing-rib` 已有原生 bin、bootfs 成员、启动角色及 component-manager 监督；配置 owner 只获 `liteos.routing.Configuration`，NET Installer 只授予 RIB。
`network-protocol::routing` 的配置来源能力复用设备安装、复合正文与事务 codec：操作 1 安装，2 接受接口与可选静态来源意图，6 创建可委托的独立来源能力，7 派生只读跟踪能力；接口重选不经配置来源转发。
直接 FIB 段、独立下一跳操作与正文指定来源身份均拒绝；没有给 Linux 域新增接口，也未把工厂能力授予普通应用或协议生产者。

sources::Routes 拥有已确认接口默认来源、协议来源及实例内身份水位；身份是不复用的非零序号，接口/协议类别不编码进 ID。
Source 的泛型元数据 M 在捕获时冻结，由来源 owner 提供，不要求 Clone/Ord；前缀记录与八字节目录引用大小不变，不按前缀复制元数据。
每个接口保留一份完整默认声明；偏好/代价由配置 owner 提供，不由 RIB 固定数值或从 ifindex 推导。
候选先按偏好，再在 owner 授予的代价比较范围内按 metric 裁决，最后以稳定来源身份/声明顺序打破平局。
接口与静态配置属于同一配置 owner 比较范围；协议会话各用自身独立范围，不把不同协议的 metric 直接比较。
直接网关只用冻结候选接口的 LOCAL/connected 事实证明，不能借旧 FIB 或旧地址证明新输入。
协议生产者可以声明直接/递归下一跳、共享属性与终止动作；同一来源更新、撤回及接口变化都进入原 select_resolved，不另设选路器。
本轮接口事实覆盖待提交计划后生成临时 Observed 来源（偏好 0），LOCAL/connected 提供递归出口，广播 /32 作为终止依赖阻断父前缀绕行。
Observed 不保存在原始声明目录，但由同一次冻结解析图保活，供跟踪读取实际直连事实；不导出到受管 FIB，不发送无用观测组定义。
该视图不是第二份活动 FIB，也不是跨轮可达性缓存；默认 IPv4 实例的下一跳跟踪已接通，完整多表规则/VRF 与 IPv6 原生执行仍待实现。
最终接口/网关/MTU 准入仍由 NET 执行；RIB 捕获完整默认路由值后，只把 route=None 的纯接口事实及已选集合一起交给 NET，NET 拒绝残留路由意图。
本机/直连/广播等自动地址路由仍由 NET 接口执行事实派生，不重复安装。

配置预备(2) 的 VMO 使用 RIB 意图外层版本 3：u32 版本，接口/静态来源/准入策略各一个 u64 长度，随后顺序放三段。
内层为 interface 版本 3、routing::Batch 版本 1、policy 版本 1；缺席段表示保持，显式空来源表示撤回，显式缺省策略表示清除限制，三段同时缺席拒绝。
策略段先以可失败分配完整捕获并验证，再预备任何执行效果；原生 RIB 不解析 JSON。旧外层拒绝，不保留版本 2 的接口/来源双段入口。
执行侧 ConfigurationBatch 外层仍为版本 1，不接受它作为 RIB 输入；删除旧接口预备入口，没有布局回退或直接 FIB 旁路。
静态来源的身份由 RIB 启动时预留，观测 protocol 固定为 STATIC(4)、最低偏好 1；正文不能选择身份/表/授权。
来源不因配置 RPC 连接关闭而撤回，因为它承载已持久决定；RIB 重启后由配置 owner 重放，同普通协议会话寿命分开。
接口、完整静态来源与准入策略在同一候选图中求解、同一 NET 事务发布，捕获新来源前删除同身份旧声明，不能借旧静态 FIB 证明新输入。

来源工厂请求为 u32 版本 1、u8 观测 protocol、u32 最低偏好（非零），无附带句柄；回复一个独立 channel。
工厂由获授权配置 owner 使用，可把结果能力交给协议进程；本期范围固定为默认实例 IPv4 main 表，来源正文不能扩大范围或选择身份。
来源 channel 的 REPLACE(1) 请求为 u32 版本 1、u64 正文逻辑长度和一个 VMO，内容为唯一 router-protocol::routing::Batch 版本 1；回复空且无句柄。
版本/尾部/句柄数与完整正文先验证，任何属性低于授予的偏好均拒绝，IPv6 不能经此能力提交到 IPv4 执行域。
空声明撤回路由但保留会话；成功回复前完整预备、激活并确认 NET，再无分配交换来源。失败不发布部分来源，确认不确定结束实例。
传输失败可能已完成提交，不能假定失败即未执行；重交完整来源是替换语义。此能力不是跨进程重启恢复或持久来源配置。
最后一个客户端关闭后，服务 worker 按 RAII 释放会话；Drop 只将预先分配的登记置为 Retiring 并 signal，不分配、不发 RPC。
登记只保存身份/待撤回阶段，不持 Session 强引用（避免 RIB→Session→RIB 环）；授权由 Session 与不可变来源头部携带。
主 Port 新增来源 Event，合并撤回后经原 NET 事务下发；在途接口租约期间保留工作，租约释放后重试，资源不足则有界延后，不丢弃撤回或空闲轮询。
新会话不得在预备租约期间创建，避免旧候选确认覆盖身份分配水位；创建/服务启动失败也走同一析构撤回，登记仅在执行确认后退休。

1. RIB 的状态锁串行捕获已确认来源与一次预备租约；候选只在独立事务能力中持有，不提前覆盖已确认目录。
2. 激活/撤销直接委托 NET 原事务；确认成功后无分配交换来源。RIB 不复制 NET 阶段和逆向资源，旧目录在状态锁外退休。
3. 关闭未确认能力只关闭 NET 对端并归还 RIB 租约，Drop 不发 RPC；NET 自动撤销期间的新预备仍由原 NET 写租约排斥。
4. 确认结果不确定时退出 RIB 实例，避免用旧来源冒充已与 FIB 同步。配置 owner 观察关闭后重放持久决定；本期不恢复协议进程或连接状态。

锁顺序为配置 owner → RIB 状态 → NET；NET 不反向同步调用前两者。RIB 单事务锁只接管自己的能力，不被 RIB 状态锁反向获取，分配失败的 guard 不在状态锁内析构。
NET 退出会结束对应 RIB 实例，配置 owner 丢弃旧 ifindex 并重装网卡；单独 RIB 退出只重连/重放配置，不重复打开存活设备。
NET 安装入口拥有设备身份到实际接口/寿命能力的登记；配置服务重启或安装回复丢失后，同一授权身份与描述重新取得原接口，不重复打开队列。
登记只持原始身份/描述、ifindex 与实际 lifetime，不镜像地址或链路状态；安装前预留容量/复制能力，发表后不再分配。重复描述冲突拒绝，关闭的寿命不可重交。
安装冷路径独占登记锁，NET/设备事件不反向获取；下次安装或 NET 退出退休已关闭项，滞留量受安装峰值限制，没有后台轮询。管理重交仍受同一 Installer 能力授权，不向应用扩大权限。
NET 安装能力的 WATCH_INTERFACES(5) 返回合并 Event；安装、移除、MTU/地址/广播/管理状态变化及事务发布/回滚通知，预备与纯 FIB 发布不通知。
该 Event 在 NIC 发布前装配，安装时把独立链路回调绑定到同一通知源；没有接口状态副本、逐包检查或额外线程，控制面 clear/arm 后读取完整快照。
RIB 主线程以一个 Port 等待 NET 关闭、接口变化、来源撤回和租约释放；持久提交期间保留 WaitingForLease 工作，释放后再求解，不轮询竞争的租约。
资源/执行暂态失败只为未完成工作设置重试截止，成功归空闲；纯 FIB 更新不回馈通知，避免重算自激。初始重算清理旧实例的无来源执行集合，配置 owner 重放持久意图。
配置来源的旧 REFRESH、配置服务中的路由重试字段及热拔出中转调用已删除；配置服务仍用 lifetime 清理界面记录和 DHCP，会话不再充当选路通知 owner。
设备发现的瞬态失败声明先入队再推进游标，不阻塞其他网卡；永久畸形/不支持/拒绝授权只报告，已消失声明退休。持久策略不能匹配设备属于待处理配置，不当作坏设备跳过。
接口容器、名字和委托能力在安装前预留；安装重试复用实际接口，配置应用失败只交原接口重试 owner，不重复建立设备或 DHCP。
目录等待持有独立登记句柄；重连先关闭旧句柄取消旧 observer，再 clear/arm/list。登记失败保留工作，重试时不重复武装仍存在的登记，不镜像 kernel 的 armed bool。
载波不可用只暂退本轮来源，不删除默认意图；载波恢复自动恢复优先候选，断线时仍可提交有效配置。来源撤回已接入主 Port；IPv4 静态意图已接入配置树，协议状态机、VRF 和 IPv6 静态执行仍未实现。

此链路为冷配置，不进报文热路径；沿既有 RIB/NET 冷编译诊断，不增每包门限。原生 RPC/VMO 时延、服务监督与真实设备切换留到计划统一验收。
链路通知每物理会话一个 Event/回调，没有逐包分配或新后台线程。观测快照临时保留 O(接口数) 设备 Arc，在 NET guard 外读硬件并立即释放；不新增常驻在线缓存。
现有 host 夹具直接运行生产来源/NET 事务，覆盖接口发布/回滚通知、断线切换/恢复、无自激与拔出；同一用例扩展验证授权偏好、递归直连出口、广播阻断、来源替换/备用/撤回和无观测组泄漏。
这些行为跨越选择、流式编码和真实 NET 准入，静态审查不足以证明组合结果；只扩展原用例，不另建 fixture 或生产诊断入口。原生 peer-close/Port/VMO 仍待统一运行验收。
性能决策：来源头部 O(来源数)、登记 O(存活/待撤回来源数)，观测来源 O(接口数)，编译时结果组有临时 used 标记；无每包新增工作或逐路由常驻字段。
来源意图保留原始 Source；观测与有效声明合并后只构建一次候选索引，NET 正文与跟踪读取共用此图；导出标记使用组，避免无用组成员分配。
解析图在确认后保留为权威 RIB，内存边界与跟踪成本见下节；百万冷编译沿既有基准统一评估，不把 host 正确性检查当成吞吐达标。

## IPv4 下一跳跟踪

router-protocol::tracking 拥有查询、状态、路由证明、立即出口/权重与唯一 wire v1；resolution 复用其 Adjacency/Member，不复制领域类型。
原生工厂 TRACK(7) 或已授权来源 TRACK(2) 派生同一默认 IPv4 实例的只读能力；不授予写入、其他实例或其他地址族，普通应用无入口。
查询是有序 IPv4 地址与 resolve_via_default；拒绝 unspecified/multicast/limited-broadcast，允许空集合与重复项。默认路由必须显式允许，不能暗作可达证明。
结果区分 NoRoute/DefaultExcluded/Unresolved/Forward/Discard/Unreachable/Prohibit，携选中前缀、来源、偏好/代价及共享组的立即出口/相对权重。
直接成员 gateway=None 表示邻居就是被查询地址，不是未知网关；终止动作无成员，Forward 必须非空。不可解析/终止选择不绕向父前缀。

1. TRACK 请求/UPDATE(2) 是 u32 版本 1、u64 正文长度及恰好一个只读 VMO；查询正文为 u32 版本/项数和每项八字节。
   查询行为 IPv4 四字节、u8 默认路由允许位、三字节零保留；完整 framing/字段先验证，再登记/原子替换定义。TRACK 返回 channel 和 Event，空回复正文。
2. SNAPSHOT(1) 无参数/句柄，回复 u64 长度及一个只读 VMO；初始化没有确认图时返回 ShouldWait，不把它冒充空表。
   正文头为 u32 版本/项数与非零 u64 代际，数值 little endian；每结果 32 bytes、每成员 16 bytes，地址按网络字节序。
   结果行为查询地址、默认允许位、状态码〔上述顺序 0–6〕、前缀长度、零保留字节、前缀地址、u32 偏好/代价/成员数、u64 来源。
   成员行为 u32 ifindex/weight、u8 flags〔gateway/on-link〕、三字节零保留、IPv4 网关；未置位字段为零。长度、范围、引用及隐藏字段全部验证。
   流式编码只创建最终缓冲；客户端捕获后完整验证一次，OwnedSnapshot 保活不可变正文，借用 view/成员迭代不重复扫描或建立解析数组。
3. 同一 State 锁下捕获查询定义 Arc 与解析快照 Arc，锁外编码/传输；只读者可保活旧代际，不阻止新配置确认。
   NET 确认后的唯一 publish 入口交换完整 Routes 并比较可见证明；预备、激活、撤销及仅代际增加不通知，无关来源变化不自激。
   首次登记已有电平；首次确认从未就绪转为就绪通知。更新为不同集合也通知，相同集合不通知；Event 合并变化，调用者 clear → arm → snapshot。
   还须观察 channel PEER_CLOSED；代际仅属于该 RIB 实例，不能跨重启比较。独立只读能力不随父来源能力关闭撤销，后者的路由仍按原寿命撤回。

登记只保存 id、Arc<Vec<Query>> 与 Event，不缓存答案，不持 Session；Session 单向持 RIB，无引用环。
创建先准备正文/能力/返回容器，登记后启动失败由 Session 析构移除；关闭只在短状态锁内移除，查询/句柄在锁外释放，无分配或 RPC。
发表时只做无分配比较及合法自有 Event 的 USER_0 signal；kernel observer 在武装时预留 port 槽，通知走 deliver，不在确认后触发可失败的队列分配。
State 锁不反向调用 Session 或 NET；查询、更新、关闭与发表均沿原锁串行，不新增锁、全局状态或后台轮询。

benchmark 决策：每批观察有一个 worker/Event 与 O(Q) 查询数组；提交比较至多遍历全部注册查询及其组，代价为 O(Q × 前缀查找 + 比较成员数)，不进入报文路径。
确认图保留原 Catalogue/Poptrie、选择行、来源字典结果和唯一解析组；O(候选/前缀/字典/组成员) 常驻空间是权威控制面状态，不能再称仅临时分配。
无策略时复用原 Source，有策略时保留有效行/属性且共享不可变来源定义；不重复编译索引或保存第二份 FIB，旧图在锁外退休，慢读者只延长其冻结代际寿命。
沿既有冷编译/规模验收测量更新延迟和峰值内存；本轮未执行运行时 benchmark。现有生产事务用例验证主备变化、默认排除、广播阻断、准备隔离及无关代际不触发变化；codec 用例检查完整截断/隐藏字段。
原生 Event/peer-close/VMO、观察规模与端到端仍待统一验收；IPv6/VRF 跟踪、协议状态机和高级策略未完成，不据此关闭阶段 6。

## 原生接口执行事务

`router-protocol::interface` 拥有复合批次内层版本 3 的 IPv4 意图/执行描述：u32 版本、u32 项数，随后每项 28 字节。
每项为 u32 index、u8 flags〔up/address/route/MTU〕、u8 prefix、u8 route protocol、零保留字节、IPv4 地址/网关各四字节、u32 MTU/preference/metric。
DefaultRoute 将 gateway/protocol/选路属性作为同一个可选值；没有 route 时相关 wire 字段全为零，拒绝隐藏元数据；有 route 时偏好非零且需要已启用的 IPv4 地址。
MTU 的 presence 位独立于值：None 保持实际设备配置，Some(0) 仍可表达回环禁用；未置位值必须为零。只接受当前版本，不保留旧布局。
整数为 little endian，地址按网络字节序；空批次、未知版本、非法保留位、字段矛盾及多余字节拒绝。
解析视图只借用输入；完整 route 是 RIB 输入，纯执行投影为 None；字段检查不混入接口存在性或 Linux ioctl 的 classful 地址推导。
当前只表达一个 IPv4 地址，不据此宣称最终双栈配置 schema 完成。

1. RIB 配置来源的 PREPARE 向 router-config 派生事务能力；RIB 再从 NET 安装授权派生唯一执行能力，Linux 域 channel 不提供该操作。
   外层消息与 FIB 组合方式由上节唯一复合批次定义；接口变化不单独申请另一个写租约。
   netstack 在唯一 NET owner 内校验完整批次、重复身份、实际设备 MTU 范围与候选网关，准备完整候选 FIB、设备身份与可复用等待者。
   候选路由准入与源地址校验使用新 MTU，不读取旧值；低于 IPv4 下限的候选退出全部相关成员。
   准备失败保持原接口/FIB；空闲域只保存一个空 Option，不常驻配置数组或 FIB 副本。
2. ACTIVATE 在一次 NET 临界区替换整批 MTU、地址、管理状态、自动路由及受管默认路由，交换整个 FIB 根并由事务保留原根。
   设备 MTU 与协议分段能力只由 NetworkInterface::configure_mtu 同步发布；写租约和不复用的 ifindex 保证预备后范围不变，发布无分配。
   正常发布不逐路由处理；未受影响的标量记录只在 PREPARE 复制，不能把冷准备成本算作已消除。
   未确认期间排斥接口/路由配置写入（EAGAIN），读取、socket 与协议推进继续使用当前已发布状态。
   新 DOWN 空接口仍可安装且不改 FIB；实际设备移除不能被配置租约阻止。
3. CONFIRM 释放原根与租约；ABORT 或能力关闭恢复原根、别名顺序、原 MTU/协议能力与接口状态，不重建索引。
   热拔出后的 ABORT 先恢复其余接口、释放租约并报告 NoDevice，不复活离线设备或其路由。
   已发布后的 CONFIRM 只确认配置决定并退休原资源，设备随后离线不撤销其余接口的新配置。
   事务能力的 waiter Mutex → NET 为单向锁序；NET 不反向取得能力锁。预备 waiter 防止竞争 + OOM 阻止最后关闭时的回滚。
   事务前像与候选数组只在冷配置寿命中存在，退休根在 NET guard 外释放，不在每包路径增加锁、分配或状态副本。

安装、配置切换、租约绑定/失效已使用这条唯一执行路径；DHCP 准备失败时撤销 tentative 网络变更，旧会话在确认前仍保留。
当前 SET/RENAME/IMPORT 的提交 owner 是 `router-config::transaction`；所有入口先产生同一候选树，再调用唯一 commit_configuration。
原生接口对象的 mtu 是独立于 IPv4/启停的持久策略，缺省/删除覆盖都使用以太网默认 1500；schema 与完整校验共享 68..65535 的通用范围，实际 adapter 可更窄。
旧 JSON 缺失字段按同一默认语义读取，当前编码生成明确值，没有第二份 MTU 配置文件；设置/租约投影不新增 MTU 字段或应用私有 ABI。
policy::resolve 产生短寿命的 IPv4 投影/MTU 输入对，比较原/候选策略决定是否执行；接口记录不额外缓存期望或已应用 MTU，重试从唯一已决定树重建。
`transaction::staging` 持有整批一份 NET 能力与各受影响接口的暂存 DHCP；DhcpChange 区分保留原会话与替换为新/无会话，避免把无新句柄当成关闭原租约。
存储前像、设备 MTU 前像与原 FIB 根各自保持唯一所有权：

1. 先校验/编译整个候选和当前设备匹配，读取原文件并准备变化 Event/代际；
   再以一份 NET 批次预备/激活全部受影响接口，保留原配置和 DHCP。不会循环提交单接口来模拟整份导入。
   名称或解析设置变更不重建已确认网络；原来已禁用且没有待处理工作的接口也不重复激活。
   仅 MTU 变更重放确认过的地址/默认路由，保留原 DHCP、租约及连接时刻；不先清地址再重新申请。
   预备失败不保存候选；执行撤销未确认时对原已决定配置登记重试。
2. 写文件失败可能已 rename，因此按原始字节或原来的不存在状态撤销，不重新编码旧 schema。
   原字节仍可见时只同步目录确认，避免 ENOSPC 下重写未变化文件也被磁盘满阻止；否则完整替换/删除。
   同时撤销暂存执行并保留原配置。文件撤销未确认则保存唯一前像，暂停新的持久提交，不能称为完整回滚。
3. 文件持久化成功成为新配置决定，随后确认执行并发布；确认传输失败不能证明执行方未确认，不能假称恢复旧配置。
   owner 保留新决定、停止需要替换的过时 DHCP，并登记新配置重新应用；保留型会话不被关闭。安装/租约/重试共用原生执行路径，不另维护一套恢复实现。

设置快照、Update 与租约消息均以 u32 线版本 3 开始，只接受当前布局；DNS/搜索列表使用 u32 项数，解码先检查剩余字节边界。
磁盘 JSON 版本 1 与历史只读迁移的二进制 1–5 独立演进。
这一布局须成套更新原生服务与 Linux 网络客户端，不保留旧线布局降级分支。
快照在 generation 后提供 Ready/RollingBack/Applying/Rejected；状态由实际配置/文件撤销/接口重试工作投影，不维护需同步的健康副本。
只有文件确实不存在才使用默认配置；读取或解码失败时持有“无有效配置”状态，保留管理查询并禁用网卡，禁止局部 SET/RENAME 覆盖未知内容。
这条路径不触发关键服务崩溃循环；授权整份 IMPORT 可以替换未知/损坏内容并恢复设备配置，保存失败仍撤销为原文件字节及禁用状态。
单一 Port 根据最早待处理截止等待，首次工作经启动时已武装的 control Event 唤醒；整批失败统一延后 500 ms，静止时无限等待。
任一接口工作到期时合并全部待应用接口，重新用一份 NET 批次应用已决定配置；不把确认丢失后的整批决定拆成逐项提交。
通知/批容器空间不足也统一推迟待处理工作，不能用多个过期截止轮流忙转；重复失败不发布未改变状态。
新请求或其他到期工作可以合并尚未到期的接口；同一轮失败后重新统一截止。原文件前像在撤销确认后释放，不是额外配置或长期备份。
已持久设置相同且对应网络已确认时，重复提交直接返回，不再写文件或新建通知；待应用工作仍会被重新执行，不将期望值相同当成已应用。
当前覆盖接口/DNS、IPv4 静态来源、备份与已有执行服务；双栈/VRF/策略完整路由 schema、未来多执行服务协调及大配置/来宾存储故障验收仍在计划内。
运行中结果不确定的重试不等于跨 owner 崩溃恢复；后者依 R12 属二期。

## 路由准入策略

Configuration::route_policy 是唯一持久策略对象，包含必填 default（permit/deny）与有序 rules；配置树完全缺省时使用无规则的 permit。
每条规则可按 protocol 和 prefix 取 AND 匹配，缺省条件通配；第一个匹配动作立即终结，未匹配使用显式 default。
prefix 为规范 IPv4/IPv6 network/length，可选 minimum/maximum 限制被声明路由的前缀长度；不指定范围时精确长度。
只有 minimum 时上界为地址宽度，只有 maximum 时下界为 length；基准长度 ≤ minimum ≤ maximum ≤ 地址宽度，非规范网络拒绝。
action 为 deny，或 permit 并可选覆盖非零 preference/metric；不能改来源身份、比较范围、实例、地址族或终止/转发动作。
来源 protocol 取自配置 owner/会话授权元数据，不从路由正文自行声明；它只是匹配条件，不用它推导执行权限。
策略仅作用于受管来源，实际 LOCAL/connected/broadcast 事实在其后装配，不能借策略撤除或改写实际接口事实。
当前生产执行仍限默认 IPv4 main 表；IPv6 前缀规则对 IPv4 不匹配，不据此宣称 IPv6 执行完成。团体/AS 路径、邻居 import/export、命名链与协议专属动作仍待接入。

router-protocol::policy 同时拥有 JSON 类型/Schema、语义检查与唯一 native codec；没有独立策略文件、私有 syscall/ioctl 或另一条配置入口。
策略 wire 版本 1：12-byte 头（u32 版本、u32 规则数、u8 缺省动作〔permit=0/deny=1〕、三字节零保留），每规则固定 32 bytes。
行布局为 flags/protocol/family/length/minimum/maximum/action/reserved 各 u8，随后 u32 preference/metric 和 16-byte 地址；数值 little endian，地址为网络字节序。
flags 位 0–4 分别表示 protocol/minimum/maximum/preference/metric 存在；family 为 0/4/6，action 为 deny=0/permit=1。
无 prefix 时其长度/范围/地址必须全零，IPv4 地址后 12 bytes 为零；未置位可选字段、deny 的属性、保留位和包尾都完整检查。
编码一次预留最终缓冲，解码一次预留规则数组；OOM 返回 NoMemory，未交出部分策略或产生执行副作用，不增加 RIB JSON 分配/解析路径。

RIB 编译器只依赖纯模型、Source、prefix-index 和 fallible-tree；来源 owner 提供可信 protocol，不让编译机制反向依赖接口/会话 owner。
按通配 protocol/具体 protocol 分桶，再用同一 Poptrie 预筛选两族包含前缀，候选取最早规则序号，不能误用最长匹配代替 first-match。
长度边界在编译时固化，protocol 桶每来源解析一次；同桶/同前缀只有长度条件时，剔除被早期规则完全覆盖的行。
每条保留行至少覆盖一个新长度，因此同前缀最多保留 33/129 行；此剪枝以没有其他剩余条件为前提，新增条件必须重新证明覆盖关系。
编译后只保存动作和索引，不另持完整配置树。无规则 permit 为零程序对象；某来源无相关匹配桶时直接使用缺省决定，permit 复用原 Source。

Routes 持原始来源声明、已确认编译策略及同代解析快照；过滤/属性变换生成有效来源，再进入原 select_resolved 与唯一执行投影，不另建选路器。
被拒绝声明仍留在原来源，后续来源更新同样经过当前策略；清除策略可恢复最新原始声明，不要求生产者重放，不借旧 FIB 或旧策略结果证明递归。
属性字典按完整有效值共享；SourceDefinition 按来源不可变共享身份、比较范围、元数据与 Vec<H> 路径字典；投影只克隆该定义的 Arc，不克隆 M/H 或路径/成员。
原始与投影保持身份/比较范围/元数据不变；没有逐前缀 Arc、在线缓存或额外锁。字典只有只读引用且不反向持 Source，Arc 退休无环且不改变页/设备寿命。
完整下一跳字典可能包含策略暂退路由的对象，解析只从有效选择建立依赖；不把这些保留声明当成当前可达证明。
策略更新、来源替换、接口事件统一捕获同一图；纯策略变更也取原 NET 租约，激活可回滚，确认后才交换 Raw 来源/编译策略。
source_retry_at 现在表示完整路由意图的未确认工作；零接口时仍推进，DHCP 不携策略段时保留已确认策略。
无有效配置前像的完整导入一律重放执行意图，即使静态列表为空；不能因此跳过清除 RIB 仍保留的旧策略。

benchmark 决策：所有新增工作在控制面冷路径，来源定义控制块 O(来源数)，有效行/属性由同代解析快照保活，索引/动作为 O(规则数)。
不增加报文路径工作或第二套选择字段；百万更新的策略吞吐/峰值内存沿既有规模基准统一验收，不能以小用例宣称指标达标。
编译 first-match 与线性规则解释器对照覆盖两族/协议桶/顺序及重复规则查询上界；新 codec 用例覆盖范围、完整截断、隐藏字段和尾部，必要性来自新字节边界。
原生产 NET 事务用例扩展覆盖纯策略激活/撤销、允许属性覆盖、拒绝期间来源替换、清除后恢复最新声明，以及 deny-all 不删除实际直连事实；不新增 fixture/生产采样入口。
这些 host 检查不替代原生传输、存储故障、硬件/规模和端到端验收；完整路由策略与阶段 6 保持未完成。

## 接口默认路由策略

每个 interfaces 配置对象可提供 default_route 属性对象（preference/metric），null/缺省使用配置服务的默认偏好 1、代价 0。
preference 必须非零，metric 为 u32；该对象覆盖默认网关的选路属性，不另行保存网关或实际 ifindex。网关仍来自当前静态地址策略或成功 DHCP 租约。
JSON 导出/导入/差异、Schema 与备份共用同一类型；未知字段和零偏好在持久/执行前拒绝。Linux 兼容设置和名称变化保留原生属性，不冻结缺省策略。
配置服务从当前唯一配置投影 DefaultRoute；仅属性变化也预备接口/RIB 批次，即使地址/MTU 不变也不能短路。
同地址重放保留已有 DHCP 会话，续租换地址时读取当前持久属性，不沿用最初开会话时的属性；租约丢失撤回完整默认意图，不丢持久覆盖。
leases module 拥有 DHCP 会话/事件与地址确认，主文件只装配与处理实际接口寿命；没有多一份租约/策略状态或执行路径。
收到 DHCP peer-close 先退休死能力和该会话的租约，再经原 apply 重开；不能把 Some(dead channel) 当成 Keep，否则重启会永久保留失效会话。
开会话请求/回复先完整检查尾部/句柄数，返回容器在启动工作前预留；畸形请求不能产生新 DHCP 工作，畸形回复不能保留错误寿命能力。

Source 的不可变头部增加一个 owner 授予的非零比较范围，仅占每来源一个 u64，不增加前缀记录或目录引用大小。
范围 1 由 RIB 授予配置 owner 的接口/静态来源；普通协议会话用自身不复用身份作为独立范围，正文与工厂请求都不能自选范围。
身份分配从保留的观测/配置身份之后开始，协议会话不会碰撞范围 1；不从 protocol 观测标记推导权限或范围，也不把范围编码进来源 ID。
在全局偏好相等时，先按比较范围稳定裁决，再比较该范围内 metric；同 metric 继续按来源/行序稳定裁决，排序为严格全序，不用非传递的成对特判。
比较范围与实例/VRF 不同，不能据此扩大地址族或执行表权限。未来协议内 BGP/OSPF 选路仍归协议 owner，不由此顺序替代。
benchmark 决策：仅冷捕获/排序增加每来源字段与一次标量比较，接口 wire 每项增加 8 bytes；无新锁、逐前缀分配、逐包工作或常驻配置副本。
已有 RIB 线性对照继续覆盖独立范围不比较 metric；生产用例扩展覆盖属性 round-trip、偏好切主备、同范围 metric 切换、恢复及准确导出。
旧接口布局拒绝和无 route 不得夹带属性扩展原用例验证；JSON 回归扩展覆盖覆盖值/历史缺省和零偏好，原生 DHCP/RPC/VMO 行为留到统一验收。

## 静态路由配置

唯一 JSON 配置树新增默认空的 routes 数组，旧版本 1 文档缺省此字段仍表示无静态来源；导出/导入/差异/备份和 Draft 2020-12 Schema 都由同一类型生成。
当前范围为默认 IPv4 main 表；IPv6、VRF、规则及协议策略不接受成“已支持但不执行”的字段。
StaticRoute 包含规范 destination/prefix_length、非零 preference（缺省 1）、metric（缺省 0）和 action。
action.kind 为 forward/discard/unreachable/prohibit；forward 必须有非空 members，每成员含非零 weight（缺省 1）与 target。
target.kind 为 direct（interface 为配置对象名称，gateway 可缺省，on_link 缺省 false）或 recursive（address 为单播 IPv4）。
直接引用必须存在于 interfaces 配置对象中；零权重、重复目标、非规范前缀、未知对象和隐藏字段在持久/执行副作用前拒绝。
同前缀多个候选允许保留；静态来源不在配置服务做另一套优选，统一交原 RIB 管理距离/比较范围内 metric 裁决。

Configuration::route_source 唯一把持久意图投影为原 routing::Batch；配置服务只按 DeviceMatch 借当前接口解析 ifindex，不把它写进文件。
设备缺席时相应直接成员暂退，空转发组不声明；原持久意图保持，设备安装/重连沿原批次重新投影。递归与终止声明仍可独立存在。
设备匹配含糊拒绝，未注册设备不伪造零身份；接口禁用/载波变化由 RIB 冻结事实裁决，不另存在线缓存。
引用的配置对象换绑设备也会触发来源重编译；仅显示名/DNS 等变化不强迫替换静态来源。
本次投影有 O(静态路由/成员数) 临时字典/记录数组，接收端继续共享/去重属性与下一跳，不引入逐路由 Arc 或报文热路径工作。
benchmark 决策：它属于配置冷路径；大配置序列化/VMO/冷编译吞吐沿计划统一验收，不以小 host 正确性用例宣称百万静态更新达标。

接口变化和静态意图一起暂存，持久文件成功后才确认来源；文件失败回滚同一 NET 租约，确认不确定只重试已持久决定。
source_retry_at 只拥有“完整路由意图（静态来源/准入策略）尚未确认”的工作，不镜像 RIB 可达性；初始化/RIB 重连及未确认回滚/提交会排队，成功确认退休。
该工作加入原 Port 的最早截止，零接口时也推进；有有效配置的接口应用都携带完整静态来源与策略，因此可合并未到期来源工作。空闲无定时唤醒或新增线程。
重复相同持久决定但仍有执行工作时，直接重试执行，不重新序列化或读写设置；修改决定仍先读文件前像，再进行可逆激活/持久化。
现有模型 round-trip 回归扩展覆盖配置名/临时身份、设备缺席、历史缺省与引用拒绝；原 RIB→NET 用例扩展覆盖意图版本隔离及新地址/静态路由同时发布、整体撤销。
这是跨 codec、来源解析与执行准入的实际回归保护；持久存储故障、原生 RPC/VMO 与设备重连仍待计划末统一运行验收，不新增测试框架或配置副本。

## 原生配置审阅与整份替换

`liteos.network.Settings` 的 EXPORT(6)、SCHEMA(7)、VALIDATE(8)、IMPORT(9)、DIFF(10) 复用同一授权 channel。
Linux 侧只有 root:netdev 的设置端点可访问这些操作，普通只读状态端点仍只接受 GET；不新增配置文件、私有 syscall 或第二套执行路径。

- `router-protocol::administration` 是控制帧的唯一编解码 owner，root/适配层/客户端共用 Request/Reply。
  请求为一个 bytes 控制字段：u32 设置线版本 3、仅 IMPORT 携带的 u64 预期代际、仅备份导出/删除携带的 bytes 固定身份（16 字节）、u64 文档逻辑长度。
  VALIDATE/IMPORT/DIFF 各携带一个内容 VMO，其余请求长度零且无句柄；所有尾部与能力数在业务副作用之前检查。
- 回复控制字段固定 20 bytes（u32 线版本、u64 代际、u64 文档逻辑长度）。EXPORT/SCHEMA/VALIDATE/DIFF 一律返回一个只读 VMO，
  IMPORT 和备份删除仅返回代际、文档长度零且无句柄；其余操作成功时均携带一个内容能力，逻辑长度为零也不能省略能力。
  能力存在性按共享 Reply::has_document 判定，因此零字节损坏备份仍可导出；固定回复容量在持久副作用之前预留，提交后不再分配文档。
  EXPORT 是当前持久配置，SCHEMA 是字段元数据，VALIDATE 是规范化候选，DIFF 是变更列表。
  VALIDATE 检查配置和当前设备别名，不发送 DHCP、不保证后续资源/I/O 成功。
- IMPORT 在配置锁内检查预期代际，不符返回 SHOULD_WAIT，成功返回提交当时的代际。代际属于当前服务实例，包含运行时状态变化，
  因此可能保守拒绝；它不是跨重启的持久 revision。完整替换可恢复 Rejected，局部修改仍拒绝覆盖未知配置。
- DIFF 按 JSON Pointer 给出 path 和存在时的 before/after；省略一侧表示新增/删除，显式 null 不等于不存在。
  对象按字段递归，有序数组整体比较。它仅供审阅，不是可绕过语义校验的补丁入口。
- linuxd 只重放断线的只读查询；SET/RENAME/IMPORT 及 DHCP 不自动重放，传输失败可能已持久化，客户端必须重新读取事实。
  `network-config::configuration` 提供对应 Linux 客户端，沿用标准 socket 传输，不拥有配置状态。
- Linux 同一授权 datagram 只带操作码/控制帧，文档一律经 SCM_RIGHTS fd；不按大小保留内联旁路。
  输入检查可读 regular OFD、完整长度及数量，从偏移零以固定 32 KiB 缓冲捕获为独立只读 VMO，不依赖发送方文件/pager 后续寿命。
  只读查询重放使用相同捕获内容，不能重读一个已变化的文件。输出把原 VMO 包装成真实只读 regular OFD，无第二份正文拷贝。
  输入采用标准 sealed memfd；可变普通文件也可提交，但只保证捕获后固定，不声称与并发文件写原子。
- native 内容的边界/地址空间转换和分配均检查，读取错误不发布部分内容；fd/VMO/普通文件引用随失败、发送失败或客户端关闭正常退休。
  Linux 客户端同时拒绝正文/附带数据截断；IMPORT 的传输失败仍不得盲目重放。
  60 KiB datagram 上限只属于现有设置投影的控制消息，配置文档不再受它或 channel 的 64 KiB 容量限制；实际受文件系统/地址空间/可用内存约束。
  私有文件同样改用独立 VMO，已删除原 48 KiB 文件上限；大规模内存与真实传输仍待整机验收。


## 配置备份

配置树可选 backup 策略（interval_seconds 与 retain 均为非零 u32），null/缺省为禁用。禁用不删除已有文件。
首次启用或策略变更立即捕获一次，之后从成功完成时按单调时间计算间隔；普通配置/租约通知不重置周期，禁用时无周期唤醒。
router-config 同服务内一个后台线程拥有自动备份调度；配置以不可变 Arc 发布，后台只克隆快照句柄，不持配置锁执行序列化或文件 I/O。
调度锁只保护短状态转换，失败快照移出独占执行，被取消的大缓冲在锁外释放。上次接纳的周期策略属于调度执行状态，不是第二个配置 owner。

文件是原 Configuration JSON，无索引/计数器文件；backup-auto-<ULID>.json 与 backup-manual-<ULID>.json 分别表示自动/手动副本。
名字与命名持久化归[服务私有存储](service-storage.md)；备份身份/保留策略归 router-config::backup::archive。
ULID 复用固定库的编解码及 native CPRNG 随机位，排序时间高于当前存量，避免墙钟回退让新副本被当作最旧删除。
展示大小/UTC 时刻由文件系统元数据提供，不把逻辑 ID 时间当作真实时刻。只有规范命名的普通文件参与管理，临时文件、活动设置及未知名字不被轮转。

保存使用原子 CREATE_NOREPLACE；错误可能已创建，读回相同字节后同步目录确认，同一任务重试同一身份，不覆盖不同内容。
新副本确认持久后才清理旧自动副本；手动副本不受自动保留策略删除。清理失败只重试清理，不再创建额外副本；失败每 30 秒重试并公开原生状态。
状态直接来自调度阶段（Disabled/Waiting/Working/Retrying），不在配置提交健康状态里伪造 Ready。namespace 不确定或错误状态改变才唤醒观察者。
私有存储能力关闭由主 Port 观察并结束组件，由监督器重取能力；普通 I/O 失败保留任务，不重启系统。

BACKUPS(11) 查询目录/自动状态，BACKUP_CREATE(12) 建手动副本，BACKUP_EXPORT(13)/BACKUP_DELETE(14) 使用固定备份身份。
请求控制帧在需要目标的方法携带 bytes(16-byte ULID)，不接受路径；这四类请求均无正文。
删除和 IMPORT 成功只返回固定确认、无正文；创建返回 JSON 身份，列表/导出使用原 fd/VMO 通路。仅列表/导出可在断线后重放，创建/删除结果未知须刷新查询。
恢复由客户端先导出，再走带预期代际的唯一 IMPORT，因此仍经完整校验及 NET/DHCP/持久化整批提交，没有第二条恢复执行路径。
启用示例是在已导出的配置中设置 `"backup":{"interval_seconds":86400,"retain":10}`，校验后整份导入；不能用这个字段片段覆盖完整配置。
上述调度/能力/归档实现不等于真实定时 I/O、重启或断电验收；这些仍待统一阶段。
