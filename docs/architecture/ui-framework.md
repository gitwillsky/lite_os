# 用户态 UI 运行库与 Rust SDK

本文件拥有已落地的框架分层；实施范围与未完成项见[框架计划](../plans/classic-ui-framework.md)和[SDK 计划](../plans/classic-ui-sdk.md)。

## 共享边界

`classic-ui-abi` 定义版本化目标 C ABI 的布局、整数标签与函数表；`classic-ui-runtime` 生成
`libliteos_ui.so`，Linux SONAME 为 `libliteos_ui.so.1`。运行库静态纳入自己的 Rust 依赖和 std，
对外只导出 `liteos_ui_get_api`。`liteos-ui` 是应用侧安全源码 crate，不消费系统 Rust dylib metadata。
调用约定是 SDK 内部机制，开发者接口是 Rust；不交付 C/C++ SDK。

第一版接口仍处于实施阶段，尚未完成兼容性验收；系统应用的既有 Rust dylib 链接正逐步迁移。
不能据此声称现有全部应用已独立于系统工具链。

## 窗口与资源

`classic-ui::Display` 唯一拥有协议连接、configure、callback 和 SHM 缓冲。
每个窗口至多持有三个提交缓冲，release 前不重写；尺寸变更只淘汰已释放缓冲。
关闭窗口先回收空闲缓冲，在途缓冲仍由连接保活，release 后销毁；连接析构统一断开并关闭 fd。
`FrameReady` 是 wl_surface.frame 的重绘提示，`BufferAvailable` 是内存可复用通知，均不表示真实呈现完成。

`WindowHost` 唯一拥有装饰、可复用 CPU 绘图存储和未提交失效，查询 Display 的权威状态。
提交成功后才清除失效，WouldBlock 保留；关闭和 I/O 错误不伪造成功。
窗口层仅为配置、焦点与标题按钮视觉变化失效，客户区控件另按交互状态变化申请绘制；普通指针移动不会重新光栅整窗。
`Resources` 拥有主题、按需加载并共享的程序图标和最多四个 scale 的字体缓存；Rc 保活当前绘制引用，资源代际使主题重载后的窗口重绘。
通用文件对话框与其他共享控件使用同一 WindowHost 和 Tree 实现；旧的手绘文件对话框已移除。

运行库中的控件树保存交互草稿、焦点、选择与布局结果，应用保存业务数据。
同一逻辑矩形供绘制、裁剪和命中使用；布局在输入分发前更新，不依赖帧 callback 是否允许提交。
Tree 独占布局失效和最近的 bounds/scale；普通指针移动复用排版，内容、规则或 configure 改变后重新计算。
列表按稳定行标识选择，仅绘制可见行；表头调整列宽和双向滚动沿用共同几何。
树视图的父子结构、展开、可见索引与选择由运行库持有，文本不另建副本；列表和树共用双向滚动及双击激活。
标准编辑框拥有选择、剪切/复制和异步粘贴；密码控件禁止复制或剪切。
多行编辑控件从记事本收归运行库，统一 UTF-8 光标、跨行选区、Tab 和双向滚动。
行宽按修改范围更新，字体变化时重建；普通按键不扫描整份文档。
菜单、滑块和属性表行为位于共享运行库；属性表先请求全部页面验证，再以独立令牌请求应用，失败保留草稿并定位错误。
应用阶段收到的 X/Escape/Alt+F4 暂缓到结果返回：成功后关闭，失败保留窗口并显示错误；空闲与验证阶段直接关闭。
标签页由 TabStrip 给出表头、选中外扩、页面主体与内容区；comctl32 规则下选中页按下即切换，方向键不循环，
Ctrl+Tab/Ctrl+PgDn 循环切换，隐藏页无表头，禁用页可见但不可选。表头超宽时按比例压缩并截断文字，
尚无多行表头或滚动箭头。
树视图按 TVS_HASLINES/LINESATROOT/HASBUTTONS 绘制分支虚线和平面展开框，只高亮文字标签；
行几何同时用于绘制、选择命中、展开框命中、原地重命名和内容宽度，缩进与连线区不改变选择。
comctl32 系控件同样由运行库持有交互：平面位图工具栏（冷/热/禁用位图条、分体与整体下拉、复选、选择性文字、
悬停 500 ms 的工具提示）、ReBar 带区（把手、蚀刻边线、按首行高度选择的品牌 logo 与忙碌动画）、超链接文字
（主题 `[Internet Explorer]` 链接色）与 ComboBoxEx（图标、层次缩进下拉）。状态栏按 SB_SETPARTS 分格，
格图标复用行图标接口；位于客户区右下角时绘制尺寸手柄，命中由窗口装饰统一处理并发起标准 xdg_toplevel.resize。
Column/Row 可声明底色与左上角不平铺位图（Web 视图水印）。
菜单条目以父条目标识组成至多四层的级联子菜单，悬停 400 ms（SPI_GETMENUSHOWDELAY 默认值）或单击/方向键展开，
右侧越界时翻到父菜单左侧；默认项粗体。子菜单延时、工具提示延时与品牌动画共用一个截止时刻参与等待，不轮询。
对话框复用标准 xdg_toplevel.set_parent 和 xdg-dialog-v1；运行库按协议要求自行筛选父窗口交互。
父窗口首次提交前暂存 parent 请求，避免合成器按标准把未映射 parent 归一为 null。
Canvas 接收复制后的批量图元和文本，不接收应用分配的 Painter 或逐像素 IPC；居中文字由运行库按字体度量排版。
单行标签可声明右对齐，与左对齐共用截断规则；任务管理器性能页用分组框、LED 仪表和右对齐统计列还原 Windows 2000。
内核只发布 Slab 总量，内核内存分组暂不显示分页/未分页两行；“选项”菜单依赖的置顶与托盘行为尚无标准实现，暂未提供。
等宽文字使用资源上下文按需加载的系统终端 atlas，8×16 逻辑单元格，宽字符两格；缩放蒙版不分配临时像素。
七个普通应用（音量控制、任务管理器、媒体播放机、设备管理器、记事本、控制面板与资源管理器）已迁移到安全 SDK 与共享控件。
任务管理器在有界后台池采样 `/proc`，窗口控制继续使用标准 foreign-toplevel；协议句柄带代际，closed 后编号复用不会命中旧快照。
媒体播放机的载入、PCM 播放与停止收敛进入异步流程，UI 不 join 音频线程；定位请求在 drain 完成前合并到最新位置。
终端使用同一 SDK 的 Canvas，复用 terminal-model 和标准 PTY。
列表四种视图共用 ItemGrid 的几何、命中、键盘和可见范围；多选、原地编辑、列对齐与上下文菜单均由运行库拥有。
上下文菜单在父客户区绘制，不创建额外 surface；独立窗口的父子与模态仍使用标准 Wayland。
树数据父先子后输入后由 Outline 按层次遍历，支持同一真实路径的多个 UI 入口；展开通知允许后台补充子节点。
控制面板只声明页面控件与业务验证/应用闭包；日期选择、图标、分组、标签页表头与主题色由共享运行库提供。
显示/任务栏以标准 flock 保护各自字段的合并，临时文件 sync 后原子 rename，避免跨窗口更新丢失。
资源管理器保留历史、目录快照与路径身份，七个应用不再处理字体、标准控件绘制、frame 或像素提交。
控件的具体支持范围以实施计划为准，未完成的行为不能用空实现冒充支持。

## 异步模型

Application 在 UI 线程调度非 Send Future；Waker 只向有界任务集合的就绪队列登记并唤醒 socket，
不会从其他线程执行 UI 代码。每轮至多轮询 64 个就绪任务；Pending 等待通知，不周期扫描。
同一次 Display poll 等待协议、重复键、外部 FD、剪贴板发送与最近 deadline。
应用与合成器复用 poll 数组容量，每轮由 PollSet 重新借用 FD；不存在延长为 static 的描述符借用。
协议 socket 使用非阻塞收发。普通请求直接从 Writer 发送，背压和带 FD 请求才入队。
输出上限 1 MiB/64 个 FD，每次 flush 最多 64 KiB；可写通知继续发送，SCM_RIGHTS 只在首次成功写入时转交。
FD 注册一次唤醒后解除 interest，由下一次 Future 等待重新装载，避免常可写 fd 造成忙循环。

窗口作用域和 Task 的 RAII owner 负责取消；迟到通知不复用旧对象标识。
Clock 与 Background 是应用已有时钟和阻塞池的可复制入口，供异步任务在 await 后创建后续工作。
Dialogs 复用 Application 的唯一窗口路由与订阅，可在 async 流程中连续询问保存、选择路径与报告错误。
`Dialogs::window` 在异步流程中创建应用自己的（可模态）对话框窗口并返回其事件流，等价于 Win32 `DialogBox`；
资源管理器的“浏览文件夹”即以标准控件组成。
通用消息框布局位于共享运行库；文件对话框也使用 Tree，目录扫描与路径检查交给 context 的单个 worker。
文件请求与结果队列各限 32，筛选后的目录最多 4096 项；窗口编号和请求序号筛掉关闭/过期结果，UI 不等待线程退出。
媒体播放机与记事本使用同一扩展名筛选对话框，目录始终显示，用户可切换所有文件。
记事本按保存时的 revision 接受结果，写入期间继续编辑的修改仍保持未保存。
普通阻塞 I/O 和计算进入两个 worker、容量 64 的后台队列；队列满立即返回错误，UI 不等待入队。
取消不能撤回已经发生的外部副作用；后台线程也不回到已销毁的控件执行回调。

剪贴板沿用标准 wl_data_device。发送端最多八个非阻塞传输，每轮每源最多写 64 KiB。
SDK 读取等待 EOF，并限制为 1 MiB；超时、超限和无效 UTF-8 是错误，不将部分内容当成成功。

## SDK 文件与本机开发

系统文件清单安装 SDK 源码与 Cargo 示例；项目入口使用 cargo new，没有额外项目生成器。
`make prepare-rust-development` 将固定 Alpine AArch64 Rust/Cargo 1.87.0 与链接器闭包交给现有 APK 安装。
系统 musl 和 musl-dev 继续由 LiteOS 基础包提供，禁止用上游包覆盖。
该安装入口只安装包，不执行编译/运行 smoke；本机编译、旧 ELF 升级和 GUI 行为尚待验收。

## 合成后端

设备公开 VirGL2 时使用 GPU，只有明确不支持该能力的设备使用 CPU；能力查询或初始化错误向上传播。
两种后端接收同一标准 wl_shm 内容、窗口几何与叠加顺序。Content 的不可变提交拥有首次上传后的纹理，
窗口移动只更新四边形；Scanout 保活当前帧的纹理到 DRM page-flip 完成，不在 Session 维护内容镜像表。
Scanout 的 Backend 枚举独占一对 CPU 或 GPU 扫描目标；启动画面直接写入同一后端，不为 GPU 额外分配 CPU 全屏双缓冲。
目标析构先移除 KMS framebuffer 引用再释放 GEM，初始化中途失败使用同一回收路径。
系统菜单/切换面板先光栅到透明纹理再取样，轮廓反色使用固定 Gallium INVERT 逻辑操作。
方向约定按 virglrenderer-1.1.0：只有扫描目标带 Y_0_TOP（宿主以 GL 自下而上存储并正立扫描输出），
采样纹理不带该标记；viewport 使用非负 Y 比例，使屏幕 y=0 落在扫描目标第 0 行。
若纹理也带 Y_0_TOP 或使用负 Y 比例，内容仍正立但窗口位置整体上下镜像，而硬件光标与命中不随之镜像。
这完成了服务端合成路径的代码接入，尚未执行 GPU 画面或性能验收；不等同于已支持客户端 dma-buf/EGL。

## 时区与后台线程

calendar 使用固定 tz-rs 0.7.3 解析标准 TZif v1/v2/v3，已解析模型由一次初始化的读写锁拥有。
重载先在锁外读取/解析，再原子替换；损坏时保留原模型并报错，不修改进程 TZ 环境或借用 libc 全局字符串。
固定偏移仍发布标准 TZif 文件；未来安装完整时区数据库时可使用转换表和 POSIX 尾部规则。
TZif v4 尚未支持，不能以当前解析器宣称兼容全部格式。
