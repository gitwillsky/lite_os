# 路由配置与执行事务契约

原生配置树、提交协调、执行能力和备份的唯一详细契约；服务拓扑与依赖见[领域所有权](dependency-owners.md)。

## 复合网络执行批次

network-protocol::configuration::batch 版本 5 使用 36 字节头。u32 版本、接口及两族 FIB 各一个 u64 长度，随后为 u32 复探项数及 u32 选表规则长度。
接口及 FIB 后附 24 字节的复探项（u32 接口、u32 地址族、16 字节地址，IPv4 补零），最后放[选表规则](ip-forwarding.md#策略选路)。缺席保持，显式空集合清除；规则须随两族 FIB 提交。
接口和 FIB 各用原领域 codec。FIB 正文版本 7 将网关族和前缀族分开。IPv6 同前缀按首选到备用排列，保留来源代价；IPv4 下发已选集合。
Writer::from_bytes 只接管已初始化前缀，framing 由该领域保证；into_bytes 移交唯一存储。两者不添加 RPC 头、分配或校验，也不建立额外缓存。

Installer 的 PREPARE_CONFIGURATION(2) 接收该正文。RIB 与 NET 共用 network-protocol::configuration 的预备控制版本 6。
固定字段为 u32 版本、u32 转发开关（0 保持，4..=7 替换，bit0/1 开启 IPv4/IPv6）及四个 u64 长度，依次为网络配置正文、预路由链、[网桥](switching.md#配置事务)及[组播转发表](ip-forwarding.md#静态组播转发)。
各非空正文对应一个 VMO，顺序与长度槽一致。零长度表示保持，带版本的空集合表示清除。正文均缺席时须显式设置转发开关。
旧 PREPARE_ROUTES(3) 及其客户端入口已移除；无接口的 FIB 替换也只调用 prepare_configuration，没有独立内联/旧完整集合分派。
ConfigurationBatch::encode_forwarding 从冻结组/路由迭代器复用同一字段 codec，不收集整份逐前缀 DTO；encode 只承载接口变化，不另建 slice FIB 编码入口。
RIB 完成选路编码后把 Vec 移交 NetworkInstaller::prepare_configuration；共用 prepare_request 消费编码所有权，在 RPC 前释放副本，服务端仍完整验证正文。
具名单槽更新仍是不同语义的独立操作。
服务先捕获并验证正文，才进入 NET；回复能力容器在副作用前预留，失败不留下事务或部分发布。router-config/RIB/netstack 必须配套交付该布局。

预备只取得一份写租约：接口前像、新地址/MTU 事实和两族受管集合由同一个事务持有，各族只编译一次最终候选；任一失败不发布另一族。
IPv4 下一跳/显式源的准入共用 admit_with，读取候选设备事实，并合并未受影响的活动前缀和新邻接；将撤销的旧地址、旧受管路由不能证明新输入有效。
新邻接草稿只含自动接口路由，默认路由只来自 RIB；不追加受管全表，不为每个受管前缀线性扫增长候选表，也不构造第二个完整中间根。
活动和邻接候选共用 StoredRecord 的成员/设备选择，不维护另一套 eligibility 或结果缓存。
事务同时拥有受影响接口和受管下一跳依赖：激活前全部检查；同一临界区交换根并发布接口；撤销先恢复存活接口再恢复原根、过滤热拔出并报告 NoDevice。
接口不变、FIB 不变及两者同时变化均沿同一事务 owner 和发布/撤销机制；激活和撤销后按当前根提前重试待发 UDP，不保存旧网关裁决。
IPv6 主表的执行准入与路径共享见[链路网络契约](ipv6-link.md#受管-ipv6-路由)。双栈备选路由表和按规则选择出口见[策略选路](ip-forwarding.md#策略选路)。

## 双栈转发开关

配置树 ipv4_forwarding/ipv6_forwarding 独立控制两族单播和静态组播转发，缺省开启；Configuration 与 NET 初始值共用 forwarding_default，不复制默认策略。
导出、Schema、审阅、差异、导入、备份与恢复沿同一模型。[桌面路由接口与转发](../../user/programs/network-manager/README.md#路由接口与双栈转发)可与路由设置一起按预期代际提交。

1. router-config 的 routing::changed 包括开关；sources_changed 仅判断实际静态声明/策略/设备绑定，二者不另持运行副本。
   静态来源未变且无待重放工作时，单改转发开关或预路由链均由 RIB 移交 NET 的同一执行租约，无需重新选路。
   未知结果、重连及多项变更仍重放完整持久决定；DHCP 和动态来源的预备未携带开关时保持当前值，不能重置为缺省开启。
2. NET 的唯一运行值属于 NetworkStack；ConfigurationSession 在激活时与可选目标交换为前像，接口/FIB/开关在同一 NET guard 下发布。
   单独标量事务 routes=None，无全表前像；确认/回滚复用原写租约，不添加第二个事务 owner、锁或广播状态。
3. 激活关闭时只暂停所属族待发及其 deadline；收到的该族新转发包丢弃，本机 UDP/TCP/RAW、ARP/ND 与路由学习仍可用，NA Router 位跟随实际 IPv6 策略。
   未确认前保留有界原包，撤销关闭时恢复并重试；确认关闭或撤销启用时只释放所属族待办，不能在再次开启时复活旧转发包。已经交给 NIC 的 TX 不倒退。
   缺省策略仅在关闭 IPv6 转发时执行[主机路由发现](ipv6-link.md#主机路由发现与自动地址)。接口可显式禁止或允许转发时学习。
4. 接口 apply_state 比较协议引擎的实际地址集合，地址确实变化才调用会清除邻居的 update_ip_addrs；MTU、重复应用或无关策略不刷新有效 ARP。
   不增加“已应用地址”缓存；变更地址/UP 状态时仍走原地址发布和清理。

单独切换的工作与 FIB 规模无关；确认清理至多 64 包/256 KiB，冷配置不新增报文路径分配或锁。
既有双 NIC fixture 覆盖关闭/恢复、原写租约排斥、未知接口失败、原包回滚/确认释放及本机 UDP；控制帧与完整配置往返用例保护版本/能力和序列化。
这些宿主结果不能代替来宾、文件/通道故障及完整系统验收。转发数据面范围见[转发契约](ip-forwarding.md)。

## 原生 RIB 配置来源

`routing-rib` 已有原生 bin、bootfs 成员、启动角色及 component-manager 监督；配置 owner 只获 `liteos.routing.Configuration`，NET Installer 只授予 RIB。
`network-protocol::routing` 的配置来源能力复用设备安装、复合正文与事务 codec：操作 1 安装，2 接受接口与可选静态来源意图，6 创建可委托的独立来源能力，7 派生只读跟踪能力；接口重选不经配置来源转发。
直接 FIB 段、独立下一跳操作与正文指定来源身份均拒绝；没有给 Linux 域新增接口，也未把工厂能力授予普通应用或协议生产者。

sources::Routes 唯一拥有两族接口/静态/协议声明及身份水位；SourceUpdate 以（身份、族）替换，同一来源更新 IPv4 不能撤回 IPv6。身份不复用，不按类别编码。
Source 的泛型元数据 M 在捕获时冻结，由来源 owner 提供，不要求 Clone/Ord；前缀记录与八字节目录引用大小不变，不按前缀复制元数据。
每个接口保留一份完整默认声明；偏好/代价由配置 owner 提供，不由 RIB 固定数值或从 ifindex 推导。
候选先按偏好，再在 owner 授予的代价比较范围内按 metric 裁决，最后以稳定来源身份/声明顺序打破平局。
接口与静态配置属于同一配置 owner 比较范围；协议会话各用自身独立范围，不把不同协议的 metric 直接比较。
直接网关只用冻结候选接口的 LOCAL/connected 事实证明，不能借旧 FIB 或旧地址证明新输入。
协议生产者可以声明直接/递归下一跳、共享属性与终止动作；同一来源更新、撤回及接口变化都进入原 select_resolved，不另设选路器。
Facts 冻结 NET 接口和带 origin 的地址；RIB 锁串行化逻辑配置，物理变化由 NET 复核。覆盖只撤回配置地址，保留接口内建地址，不按值猜来源。
两族生成偏好 0 的 Observed；本机 /32、/128 为 Local（无转发成员），连接前缀才提供递归邻接；广播与未可用 IPv6 本机地址仍以 Prohibit 阻断绕行。
IPv6 on-link /128 不另生成同前缀转发候选；捕获按实际行数预留容量，只有存在非 /128 直连前缀的接口才创建转发邻接。
Observed 不保存在原始声明目录，但由同一次冻结解析图保活，供跟踪读取实际直连事实；不导出到受管 FIB，不发送无用观测组定义。
本机交付是 RIB 内部 Action，不加入来源声明 wire，协议生产者不能自称地址 owner；受管 FIB 投影拒绝 Local，实际安装只归 NET。
IPv6 定义与 AddressState 同次冻结；新物理地址保持 Tentative，相同地址承接真实 DAD，回环按候选 UP/MTU 直接取得资格。
旧配置资格不会随前像重放；DAD 完成/重复、关闭与地址移除沿原通知重算。冷捕获两遍地址行，不分配额外状态索引或更改报文路径。
每个 RIB 实例独立保留双栈冻结图。配置 owner 以随机实例身份调用 `OPEN_ROUTING_DOMAIN(14)` 取得同域配置和网络连接。删除后同名新域取得新实例，旧引用不能迁入新域。
域工厂请求为 u32 版本 1 和带长度的 UTF-8 名称，无句柄。重复打开复用存活域。域安装端从 `inet::routing_inputs` 取得本域通知，不向普通网络连接授予工厂能力。
接口、网关及 MTU 准入由 NET 执行。RIB 把不含路由意图的接口事实和已选路由交给 NET。本机、直连及广播等自动路由由 NET 派生。

配置预备(2) 的 VMO 使用 RIB 意图外层版本 5：44 字节头为 u32 版本及五段 u64 长度，随后依次放接口、IPv4 来源、IPv6 来源、准入策略及备选表和规则。
内层为 interface v8、routing::Batch v2、policy v1、policy_routing::Tables v2。缺席保持、显式空来源或备选表撤回、缺省准入策略清除限制；拒绝全空或错族正文。
策略段先以可失败分配完整捕获并验证，再预备任何执行效果；原生 RIB 不解析 JSON。旧外层拒绝，不保留降级或平行入口。
执行侧 ConfigurationBatch 见[复合网络执行批次](#复合网络执行批次)。失败复探项按接口和地址排序且不重复，畸形布局拒绝整批。
静态来源的身份由 RIB 启动时预留，观测 protocol 固定为 STATIC(4)、最低偏好 1；正文不能选择身份/表/授权。
来源不因配置 RPC 连接关闭而撤回，因为它承载已持久决定；RIB 重启后由配置 owner 重放，同普通协议会话寿命分开。
接口、两族静态来源与策略由同一协调器求解并编码一个 NET 事务；只替换同身份同族声明，另一族及缺席来源保持，不能借旧 FIB 证明新输入。

来源工厂请求为 u32 版本 4、u8 观测 protocol、u32 最低偏好（非零）、u8 IPv6 许可（0/1），无句柄；回复来源与同域网络 channel。
获授权的配置 owner 可把两项能力交给协议进程。范围为本域 IPv4 main 表及显式获准的 IPv6。未授权的族返回 AccessDenied，正文不能自选域或来源身份。
来源 channel 的 PREPARE(1) 为 u32 版本 4，依次为来源、查询与安装检查三个 u64 逻辑长度和三个只读 VMO。内层分别用 routing::Batch v2、tracking 查询 v4 与下述安装检查。
校验格式、来源授权及检查的目的族后，生成完整候选图及唯一 NET 批次。按族替换声明与复探义务，关闭来源撤回其两族。
回复 u64 来源身份、两个 u64 结果长度、u8 复探义务变化标志，依次移交事务 channel、查询和检查结果 VMO。身份由授权连接赋予。
结果由同一次候选图编码。客户端逐项核对查询顺序，校验检查结果的来源身份、代际与数量。
客户端 PreparedSource 持事务、来源身份及冻结结果，并静态借用 RoutingSource。来源能力关闭使其派生事务失效。
该值只移动现有能力/正文，不分配新的控制块或复制执行阶段；activate/confirm/abort 委托唯一 PreparedConfiguration，confirm/abort 消费整批观察。
候选正文、VMO 和回复容器在可见副作用前准备；事务复用接口配置的 ACTIVATE/CONFIRM/ABORT，不复制执行阶段、反向资源或当前 FIB。
空声明撤回路由。仍活跃的安装检查可保留失败网关复探义务，空检查清除本族义务。NET 确认后交换来源，撤销保留旧决定。
客户端 replace 沿无查询和无检查的 prepare → activate → confirm 路径。协议仅保留这一套预备及提交入口。
传输失败可能已完成提交，不能假定失败即未执行；重交完整来源是替换语义。此能力不是跨进程重启恢复或持久来源配置。
最后一个客户端关闭后，服务 worker 按 RAII 释放会话；Drop 只将预先分配的登记置为 Retiring 并 signal，不分配、不发 RPC。
登记只保存身份/待撤回阶段，不持 Session 强引用（避免 RIB→Session→RIB 环）；授权由 Session 与不可变来源头部携带。
主 Port 新增来源 Event，合并撤回后经原 NET 事务下发；在途接口租约期间保留工作，租约释放后重试，资源不足则有界延后，不丢弃撤回或空闲轮询。
新会话不得在预备租约期间创建，避免旧候选确认覆盖身份分配水位；创建/服务启动失败也走同一析构撤回，登记仅在执行确认后退休。
来源预备事务只记录派生它的来源身份，不保活来源 Session；激活/确认在原状态锁下复核该登记。
来源退出与确认由同一锁线性化；已退休来源的晚到确认撤销 NET 并释放租约，不能复活已关闭来源。接口配置事务不绑定普通协议来源寿命。
事务服务由 Transaction::serve 唯一装配；失败在状态锁外析构同一 guard，关闭执行能力并唤醒原 Port 的租约等待项，无 RPC 析构或新增恢复线程。
普通查询给出全来源候选图的当前结果。需要证明路径在安装后仍可达时，提交下述安装检查。

1. RIB 的状态锁串行捕获已确认来源与一次预备租约；候选只在独立事务能力中持有，不提前覆盖已确认目录。
2. 激活/撤销直接委托 NET 原事务；确认成功后无分配交换来源。RIB 不复制 NET 阶段和逆向资源，旧目录在状态锁外退休。
3. 关闭未确认能力只关闭 NET 对端并归还 RIB 租约，Drop 不发 RPC；NET 自动撤销期间的新预备仍由原 NET 写租约排斥。
4. 确认结果不确定时退出 RIB 实例，避免用旧来源冒充已与 FIB 同步。配置 owner 观察关闭后重放持久决定；本期不恢复协议进程或连接状态。

锁顺序为配置 owner → RIB 状态 → NET；NET 不反向同步调用前两者。RIB 单事务锁只接管自己的能力，不被 RIB 状态锁反向获取，分配失败的 guard 不在状态锁内析构。
NET 退出会结束对应 RIB 实例，配置 owner 丢弃旧 ifindex 并重装网卡；单独 RIB 退出只重连/重放配置，不重复打开存活设备。
NET 的 `INSTALL_DEVICE(1)` 使用 u32 版本 3、u64 目录 ID、长度前缀域名和设备描述，随一个目录能力传输；空域名指默认域。根 RIB 连接独占放置权限，目标具名域须已打开。
同域重试重交原接口。改绑前核对目录与设备描述，依据登记的弱域引用、ifindex 与实际 lifetime 撤回旧接口，再打开新会话；旧域事务在途返回 ShouldWait，目录独占保护队列寿命。NET/设备事件不反向获取登记锁。
`routing_domains` 与根配置同一次持久决定。网卡归属变化触发重扫，受影响的域独立确认接口、路由、选路规则和防火墙。重试期间报告 Applying。[配置方法](../../user/libraries/network-config/README.md#建立独立静态路由域)
NET 安装能力的 WATCH_ROUTING_INPUTS(5) 返回合并 Event。USER_0 报告接口拓扑变化，USER_1 报告双栈网关可达性变化。预备与纯 FIB 发布不通知。
该 Event 在 NIC 发布前装配，链路回调绑定到同一通知源。RIB 清除并重新武装两类信号，然后冻结接口、地址和双栈邻居事实，重新计算递归依赖及实际 FIB。
RIB 主线程以一个 Port 等待 NET 关闭、路由输入变化、来源撤回和租约释放。持久提交期间保留 WaitingForLease 工作，释放后重取快照并求解。
资源/执行暂态失败只为未完成工作设置重试截止，成功归空闲；纯 FIB 更新不回馈通知，避免重算自激。初始重算清理旧实例的无来源执行集合，配置 owner 重放持久意图。
配置来源的旧 REFRESH、配置服务中的路由重试字段及热拔出中转调用已删除；配置服务仍用 lifetime 清理界面记录和 DHCP，会话不再充当选路通知 owner。
设备发现的瞬态失败声明先入队再推进游标，不阻塞其他网卡；永久畸形/不支持/拒绝授权只报告，已消失声明退休。持久策略不能匹配设备属于待处理配置，不当作坏设备跳过。
接口容器、名字和委托能力在安装前预留；安装重试复用实际接口，配置应用失败只交原接口重试 owner，不重复建立设备或 DHCP。
目录等待持有独立登记句柄；重连先关闭旧句柄取消旧 observer，再 clear/arm/list。登记失败保留工作，重试时不重复武装仍存在的登记，不镜像 kernel 的 armed bool。
载波不可用只暂退本轮来源，不删除默认意图；载波恢复自动恢复优先候选，断线时仍可提交有效配置。
来源撤回由主 Port 推进。默认域和具名域分别接收本域的双栈静态路由、BGP 与 OSPF 候选。[OSPF 契约](ospf.md)

此链路为冷配置，不进报文热路径；沿既有 RIB/NET 冷编译诊断，不增每包门限。原生 RPC/VMO 时延、服务监督与真实设备切换留到计划统一验收。
链路通知每物理会话一个 Event/回调，没有逐包分配或新后台线程。观测快照临时保留 O(接口数) 设备 Arc，在 NET guard 外读硬件并立即释放；不新增常驻在线缓存。
现有 host 夹具直接运行生产来源/NET 事务，覆盖接口发布/回滚通知、断线切换/恢复、无自激与拔出；同一用例扩展验证授权偏好、递归直连出口、广播阻断、来源替换/备用/撤回和无观测组泄漏。
这些行为跨越选择、流式编码和真实 NET 准入，静态审查不足以证明组合结果；只扩展原用例，不另建 fixture 或生产诊断入口。原生 peer-close/Port/VMO 仍待统一运行验收。
性能决策：来源头部 O(来源数)、登记 O(存活/待撤回来源数)，观测来源 O(接口数)，编译时结果组有临时 used 标记；无每包新增工作或逐路由常驻字段。
来源预备额外有 O(Q) 查询、安装检查及结果，与事务寿命内的控制 worker。共用已编译图，无额外的检查往返。
按来源和前缀族持有去重的失败邻接，静态选择与协议检查共用 O(实际失败邻接数) 暂存。全表延迟与峰值内存沿既有规模评估。
来源意图保留原始 Source；观测与有效声明合并后只构建一次候选索引，NET 正文与跟踪读取共用此图；导出标记使用组，避免无用组成员分配。
解析图在确认后保留为权威 RIB，内存边界与跟踪成本见下节；百万冷编译沿既有基准统一评估，不把 host 正确性检查当成吞吐达标。

### 来源事务的安装后可达检查

来源预备同时检查候选目的前缀与下一跳，并生成复探依赖。接口与 NET 执行事务只接收各自的原有计划。
正文版本 4，版本与项数各 u32。IPv4/IPv4、IPv4/IPv6、IPv6/IPv6 项为 16/28/40 bytes，带接口的项增加四字节。
每项含 u8 目的族、前缀长度、带接口标志、零保留，接着是 Query（8/20 bytes）、目的网络（4/16 bytes）和可选非零 u32 接口。带接口仅允许 IPv6 link-local 地址且不允许默认路由。
结果正文版本 4，版本与项数各 u32、来源身份与候选代际各 u64，每项八字节为 reachable、cost-present、两字节零保留及 u32 成本。
整数为 little endian，双族地址为网络字节序；布尔只能为 0/1，未置位的可选成本必须为零。
不可达和未知成本均不填成本。普通跟踪能力保持独立。

1. 安装检查覆盖 RFC 4271 §9.1.2.1 的自递归条件：候选若会接管某次 LPM，则该分支回到候选自身而失败；已有更具体路由继续优先，不能退到祖先或旧出口绕过失败。
   按下一跳地址族搜索同一代际的冻结图，保留有效出口。IPv4 候选只改变 IPv4 覆盖，跨族依赖由同代 IPv6 图证明。搜索不修改活动表或重编译 FIB。
2. 搜索用一份批次内 visited 位图与复用工作向量；每个节点的递归成员最多展开一次，环路不进入 Rust 调用栈。
   每次入边仍先核对直接出口及实际立即网关；同一对象经不同地址进入时不能提前去重。每个检查仅清除实际触及的字，不保留跨前缀/代际准入缓存。
3. 解析图与检查共同拥有一份冻结接口投影，按 ifindex 排序查找，包含候选地址/MTU、管理和载波事实。
   检查每条有效直接分支及递归后的网关，不能从旧的解析组成员反推设备准入；配置意图仍可在无载波时保存，只有可转发选择受载波排斥。
   这些是与图同寿命的不可变输入，不是另一个在线接口状态 owner；新事实到来仍由原 RIB 编译/发表路径产生新图。
4. 带接口的下一跳直接验证该邻接。可用的直接邻接及实际直连观测提供零成本，普通来源 metric 不作 IGP 成本。结果仍须由整批选路和 NET 确认。
   检查遇到的失败网关随来源事务交给 NET 复探。失败状态解除、当前接口不可用或来源移除时，不再提交对应复探项。

成本决策：每批唯一 O(Q) 结果区，各族依次填写原输入位置，不复制检查或两份结果；另有 O(下一跳对象数/64) 位图和搜索峰值工作区；仅访问本检查可达的依赖，不为每条检查复制全表或分配一套状态数组。
邻接恢复由 NET 的原 ARP/ND 定时器与事件驱动。来源更新移除未引用的失败依赖，撤销回滚原复探集合。没有新增按前缀探测或后台任务。
宿主夹具覆盖自递归、备用出口、接口范围，以及来源撤空后仍能探测、恢复转发和撤销时保留原义务。原生 RPC 与并发竞态待系统验收。

## 双栈下一跳跟踪

router-protocol::tracking 拥有查询、状态、路由证明与立即出口和权重。resolution 复用其 Adjacency/Member。
原生工厂 TRACK(7) 或已授权来源 TRACK(2) 派生同一默认实例两族的只读能力；不授予写入或其他实例，普通应用无入口。
授权来源另提供 WATCH_ROUTES(3)：请求仅 u32 来源版本 3、无句柄，返回普通跟踪 channel 与 Event，初始查询为空。
该登记不可变的 whole_graph 范围使每次已确认图发表均通知，不因立即出口相同而遗漏递归依赖变化；预备、激活和撤销不通知。
SNAPSHOT/UPDATE 使用下述快照与查询正文，空查询返回只有头部的快照。更新查询不缩小完整图观察范围。
Query 的 prefix_length=None 为同族单播地址 LPM，默认路由必须经 resolve_via_default 显式允许；拒绝 unspecified/multicast/limited-broadcast、mapped 和无 zone 的链路地址。
Some(length) 为精确规范网段（包括 0/0），禁止 resolve_via_default；不受更具体子网遮挡，也不能以父网段或多个子网覆盖代替精确存在。允许空集合及重复项。
结果区分 NoRoute/DefaultExcluded/Unresolved/Forward/Discard/Unreachable/Prohibit/Local（0–7），携选中前缀、来源、偏好/代价及共享组的立即出口/相对权重。
Local 仅用于本机 /32、/128 的发布依据，无成员且不能作为下一跳证明；直接成员 gateway=None 表示查询目的邻居，策略终止也无成员，Forward 必须非空。不可解析/终止选择不绕向父前缀。

1. TRACK 请求/UPDATE(2) 是 u32 版本 1、u64 正文长度及恰好一个只读 VMO；查询正文为 u32 版本/项数和按族编码的查询项。
   外壳版本仍为 1，查询正文版本为 4；每行 u8 family（4/6）、u8 flags（默认许可/精确模式）、u8 精确长度、零保留及本族地址，共 8/20 bytes。
   非精确模式长度必须为零；完整 framing/字段先验证，再登记/原子替换定义。TRACK 返回 channel 和 Event，空回复正文。
2. SNAPSHOT(1) 无参数/句柄，回复 u64 长度及一个只读 VMO；初始化没有确认图时返回 ShouldWait，不把它冒充空表。
   正文头为 u32 版本 5、u32 项数与非零 u64 代际，数值 little endian。结果头为 36/60 bytes，成员 16/28 bytes，地址按网络字节序。
   结果头为 family/flags/精确长度/状态/路由长度/成员宽标志各 u8、两字节零保留、u32 偏好/代价/成员数、u64 来源，再放本族查询地址及路由网络。
   精确回复必须与请求网络/长度相同；不执行 DefaultExcluded，缺失时没有来源/路由；捕获校验与冻结读取共用字段投影，不丢查询模式。
   成员为 u32 ifindex/weight、u8 flags〔网关存在/on-link/IPv4 成员使用 IPv6 网关〕、三字节零保留及网关。IPv4 结果只要含 IPv6 网关就置宽标志，全部成员的网关槽为 16 字节，短地址补零。
   流式编码只创建最终缓冲；客户端捕获后完整验证一次，OwnedSnapshot 保活不可变正文，借用 view/成员迭代不重复扫描或建立解析数组。
3. 同一 State 锁下捕获查询定义 Arc 与解析快照 Arc，锁外编码/传输；只读者可保活旧代际，不阻止新配置确认。
   NET 确认后的唯一 publish 入口交换完整 Routes；普通 TRACK 比较可见证明，无关代际不通知；WATCH_ROUTES 则通知每次确认发表。
   两者均不在预备、激活或撤销时通知。
   首次登记已有电平；首次确认从未就绪转为就绪通知。更新为不同集合也通知，相同集合不通知；Event 合并变化，调用者 clear → arm → snapshot。
   还须观察 channel PEER_CLOSED；代际仅属于该 RIB 实例，不能跨重启比较。独立只读能力不随父来源能力关闭撤销，后者的路由仍按原寿命撤回。

登记保存 id、查询定义、Event 与不可变观察/来源范围；路由分发启用后另持下述确认游标，不复制路由答案或持 Session，Session 单向持 RIB，无引用环。
创建先准备正文/能力/返回容器，登记后启动失败由 Session 析构移除；关闭只在短状态锁内移除，查询/句柄在锁外释放，无分配或 RPC。
发表时只做无分配比较及合法自有 Event 的 USER_0 signal；kernel observer 在武装时预留 port 槽，通知走 deliver，不在确认后触发可失败的队列分配。
State 锁不反向调用 Session 或 NET；查询、更新、关闭与发表均沿原锁串行，不新增锁、全局状态或后台轮询。

benchmark 决策：每批观察有一个 worker/Event 与 O(Q) 查询数组；提交比较至多遍历全部注册查询及其组，代价为 O(Q × 前缀查找 + 比较成员数)，不进入报文路径。
确认图保留原 Catalogue/Poptrie、选择行、来源字典结果和唯一解析组；O(候选/前缀/字典/组成员) 常驻空间是权威控制面状态，不能再称仅临时分配。
无策略时复用原 Source，有策略时保留有效行/属性且共享不可变来源定义；不重复编译索引或保存第二份 FIB，旧图在锁外退休，慢读者只延长其冻结代际寿命。
沿既有冷编译/规模验收测量更新延迟和峰值内存；本轮未执行运行时 benchmark。现有生产事务用例验证主备变化、默认排除、广播阻断、准备隔离及无关代际不触发变化；codec 用例检查完整截断/隐藏字段。
原生 Event/peer-close/VMO、观察规模与端到端仍待统一验收；IPv6/VRF 跟踪、其他动态协议与高级策略未完成，不据此声明完整动态选路可用。

## 原生接口执行事务

`router-protocol::interface` 拥有复合批次内层版本 8 的接口意图/执行描述。u32 版本、u32 项数，每项 44-byte 固定头，随后依次放手动 IPv6 地址、委派前缀和通告 DNS。
固定头为 u32 index、u8 flags〔up/address/route/MTU/IPv6/下游通告/委派 presence〕、u8 IPv4 prefix、u8 route protocol、u8 通告接收策略、IPv4 地址和网关各四字节、u32 MTU/preference/metric/IPv6 项数。
末尾为 u16 最大通告间隔、u16 默认网关寿命（均为秒）及两个 u32 计数，分别为委派前缀数和 RDNSS 地址数。通告缺席保持，显式间隔 0 停用，非零间隔启用。停用或缺席时通告字段均为零。
委派项为 16-byte /64 网络和两个 i64 单调纳秒截止时间（首选、有效）。缺席保持、空集合清除；前缀有序且不重复。租约通过同一事务交换和撤销。
IPv6 每项 20 bytes：16-byte 地址、u8 prefix、u8 on_link 与两字节零保留；必须按地址排序且无重复。缺席保持，显式空集合清除手动地址，不能在未置 presence 时隐藏正文。
通告 DNS 项为 16-byte IPv6 单播地址，按配置顺序保存，无重复，最多八个。通告启用时空集合清除 DNS，地址数量计入最小 MTU 校验。
DefaultRoute 将 gateway/protocol/选路属性作为同一个可选值；没有 route 时相关 wire 字段全为零，拒绝隐藏元数据；有 route 时偏好非零且需要已启用的 IPv4 地址。
MTU 的 presence 位独立于值：None 保持实际设备配置，Some(0) 仍可表达回环禁用；未置位值必须为零。只接受当前版本，不保留旧布局。
整数为 little endian，地址按网络字节序；空批次、未知版本、非法保留位、字段矛盾及多余字节拒绝。
解析视图只借用输入；完整 route 是 RIB 输入，纯执行投影为 None；字段检查不混入接口存在性或 Linux ioctl 的 classful 地址推导。
当前表达一个 IPv4 地址及多个静态 IPv6 地址。DAD、源选择与直连范围见[IPv6 地址契约](ipv6-link.md#静态地址与直连路由)，经网关路由使用同一静态 routes。
`interfaces.<名称>.ipv6.accept_ra` 支持 `host_only`（缺省）、`disabled` 和 `always`，后者允许转发中的上联学习。旧配置缺省 `host_only`。执行字段 0 保留、1 缺省、2 禁止、3 始终允许，回环拒绝该字段。
策略随接口事务激活、确认及回滚。DHCPv4 租约更新保持原值。重设接收策略重启请求状态，现有学习结果按各自寿命保留。配置与通知走原有冷路径，数据包发送无额外查找。
`interfaces.<名称>.ipv6.advertise` 缺省停用。设为 `{"mode":"enabled","max_interval_seconds":30,"router_lifetime_seconds":90}` 可发布静态直连 /64 及默认网关。网关寿命 0 时不公布默认网关。可选 `dns` 地址列表提供解析器，按自身寿命发布和撤回。
启用时最大间隔为 4 到 1800 秒，非零网关寿命至少等于最大间隔且不超过 9000 秒。策略与静态地址共同校验和提交，详见[下游路由通告](ipv6-link.md#下游路由通告)。

1. RIB 配置来源的 PREPARE 向 router-config 派生事务能力；RIB 再从 NET 安装授权派生唯一执行能力，Linux 域 channel 不提供该操作。
   外层消息与 FIB 组合方式由上节唯一复合批次定义；接口变化不单独申请另一个写租约。
   netstack 在唯一 NET owner 内校验完整批次、重复身份、实际设备 MTU 范围与候选网关，准备完整候选 FIB、设备身份与可复用等待者。
   候选路由准入与源地址校验使用新 MTU，不读取旧值；低于 IPv4 下限的候选退出全部相关成员。
   准备失败保持原接口/FIB；空闲域只保存一个空 Option，不常驻配置数组或 FIB 副本。
2. ACTIVATE 在一次 NET 临界区替换整批 MTU、地址、管理状态、自动路由及受管默认路由，交换整个 FIB 根并由事务保留原根。
   设备 MTU 与协议分段能力只由 NetworkInterface::configure_mtu 同步发布；写租约和不复用的 ifindex 保证预备后范围不变，发布无分配。
   正常发布不逐路由处理；未受影响的标量记录只在 PREPARE 复制，不能把冷准备成本算作已消除。
   未确认期间排斥接口/路由配置写入（EAGAIN），读取、socket 与协议推进继续使用当前已发布状态。
   新 DOWN 接口仍可安装；IPv6 的活动/未发布根都先纳入新接口的自动前缀，任一准备失败不发布接口；实际设备移除不能被配置租约阻止。
3. CONFIRM 释放原根与租约；ABORT 或能力关闭恢复原根、别名顺序、原 MTU/协议能力与接口状态，不重建索引。
   热拔出后的 ABORT 先恢复其余接口、释放租约并报告 NoDevice，不复活离线设备或其路由。
   已发布后的 CONFIRM 只确认配置决定并退休原资源，设备随后离线不撤销其余接口的新配置。
   事务能力的 waiter Mutex → NET 为单向锁序；NET 不反向取得能力锁。预备 waiter 防止竞争 + OOM 阻止最后关闭时的回滚。
   事务前像与候选数组只在冷配置寿命中存在，退休根在 NET guard 外释放，不在每包路径增加锁、分配或状态副本。

IPv6 字段属于 interfaces 对象的 ipv6.addresses；完整配置替换缺省/空集合会清除手动地址，IPv4 租约的原生计划缺席此字段时保留。
仅修改 IPv6 也触发同一接口提交；相同地址不重置当前 DAD。准备阶段预留地址、组和直连根，发布/撤销无分配，监听协议义务不由事务前像复制。
安装、配置切换、租约绑定/失效已使用这条唯一执行路径；DHCP 准备失败时撤销 tentative 网络变更，旧会话在确认前仍保留。
当前 SET/RENAME/IMPORT 的提交 owner 是 `router-config::transaction`；所有入口先产生同一候选树，再调用唯一 commit_configuration。
原生接口对象的 mtu 是独立于 IPv4/启停的持久策略，缺省/删除覆盖都使用以太网默认 1500；schema 与完整校验共享 68..65535 的通用范围，实际 adapter 可更窄。
旧 JSON 缺失字段按同一默认语义读取，当前编码生成明确值，没有第二份 MTU 配置文件；设置/租约投影不新增 MTU 字段或应用私有 ABI。
policy::resolve 产生短寿命的 IPv4 投影/MTU 输入对，比较原/候选策略决定是否执行；接口记录不额外缓存期望或已应用 MTU，重试从唯一已决定树重建。
`transaction::staging` 持有整批一份 NET 能力与各受影响接口的暂存 DHCP；DhcpChange 区分保留原会话与替换为新/无会话，避免把无新句柄当成关闭原租约。
存储前像、设备 MTU 前像与原 FIB 根各自保持唯一所有权：

1. 先校验/编译整个候选和当前设备匹配，读取原文件并准备变化 Event/代际；
   再以一份 NET 批次预备/激活全部受影响接口，保留原配置和 DHCP。不会循环提交单接口来模拟整份导入。
   名称或解析设置变更不重建已确认网络；原来已禁用且没有待处理工作的接口也不重复激活。
   仅 MTU 变更重放确认过的地址/默认路由，保留原 DHCP、租约及连接时刻；不先清地址再重新申请。
   预备失败不保存候选；执行撤销未确认时对原已决定配置登记重试。
2. 写文件失败可能已 rename，因此按原始字节或原来的不存在状态撤销，不重新编码旧 schema。
   原字节仍可见时只同步目录确认，避免 ENOSPC 下重写未变化文件也被磁盘满阻止；否则完整替换/删除。
   同时撤销暂存执行并保留原配置。文件撤销未确认则保存唯一前像，暂停新的持久提交，不能称为完整回滚。
3. 文件持久化成功成为新配置决定，随后确认执行并发布；确认传输失败不能证明执行方未确认，不能假称恢复旧配置。
   owner 保留新决定、停止需要替换的过时 DHCP，并登记新配置重新应用；保留型会话不被关闭。安装/租约/重试共用原生执行路径，不另维护一套恢复实现。

设置快照、Update 与租约消息均以 u32 线版本 4 开始，只接受当前布局。设置快照附带[运行时通告 DNS](ipc-network.md#interface)，不写入持久配置。
DNS 和搜索列表使用 u32 项数，解码先检查剩余字节边界。
磁盘 JSON 版本 1 与历史只读迁移的二进制 1–5 独立演进。
这一布局须成套更新原生服务与 Linux 网络客户端，不保留旧线布局降级分支。
快照在 generation 后提供 Ready/RollingBack/Applying/Rejected；状态由实际配置/文件撤销/接口与 BGP 重试工作投影，不维护需同步的健康副本。
只有文件确实不存在才使用默认配置；读取或解码失败时持有“无有效配置”状态，保留管理查询并禁用网卡，禁止局部 SET/RENAME 覆盖未知内容。
这条路径不触发关键服务崩溃循环；授权整份 IMPORT 可以替换未知/损坏内容并恢复设备配置，保存失败仍撤销为原文件字节及禁用状态。
单一 Port 根据最早待处理截止等待，首次工作经启动时已武装的 control Event 唤醒；整批失败统一延后 500 ms，静止时无限等待。
任一接口工作到期时合并全部待应用接口，重新用一份 NET 批次应用已决定配置；不把确认丢失后的整批决定拆成逐项提交。
通知/批容器空间不足也统一推迟待处理工作，不能用多个过期截止轮流忙转；重复失败不发布未改变状态。
新请求或其他到期工作可以合并尚未到期的接口；同一轮失败后重新统一截止。原文件前像在撤销确认后释放，不是额外配置或长期备份。
已持久设置相同且对应网络已确认时，重复提交直接返回，不再写文件或新建通知；待应用工作仍会被重新执行，不将期望值相同当成已应用。
当前覆盖接口/DNS、双栈静态来源、备份与已有执行服务；双栈/VRF/策略完整路由 schema、未来多执行服务协调及大配置/来宾存储故障验收仍在计划内。
运行中结果不确定的重试不等于跨 owner 崩溃恢复；后者依 R12 属二期。

## 已确认路由分发观察

同一 Tracking channel 的 ROUTES(3) 仅允许 WATCH_ROUTES 派生能力；普通 NHT 返回 NotSupported。
工厂/来源 TRACK 的既有调用者传固定来源范围，WATCH_ROUTES 必须绑定授权 Source 自身身份；该身份不能由消费者在请求中指定。
来源工厂的 Rib::track(queries, excluded_source) 与 Rib::watch_routes(source) 仅供本服务装配，范围不扩大至其他 RIB 实例。

1. 请求为 u32 外壳版本 1、u64 已应用代际及 u32 长度的 Selector JSON，无句柄；connected 选择实际连接网段，protocols 为提供者协议标记的有序集合。
   首次代际零表示完整读取；选择非空，解码排序去重，首次绑定后不可更改。未知字段、尾部和非法代际在执行前拒绝。
   回复为 u64 长度和一个只读 VMO，正文由 router-protocol::tracking::routes 唯一拥有，与 NHT 查询和快照各自版本化。
2. 正文版本 2：32-byte 头为 u32 版本/reset/count/零保留，u64 base/generation；reset 当且仅当 base=0，generation 正且不早于 base，相等时必须无变化。
   每行 28/40 bytes：u8 family/三字节零保留、u8 长度/操作/协议/丢弃、u64 来源、u32 度量/零保留，再放本族网络地址；数值 little endian，地址为网络字节序。
   操作 0 撤回且后续元数据全零，1 连接网段且协议字段零，2 提供者协议；宣告来源非零。前缀规范、严格递增且唯一，reset 不含撤回。
   全文验证后才返回不可变 Changes；迭代不重复校验或分配 DTO，客户端还须核对 base 等于请求代际。
3. 只投影已确认图中的选定 Forward/Discard；不可解析、拒绝及禁止路由不发布。连接网段须与冻结接口的实际配置网络/长度吻合，排除普通主机地址和广播记录。
   协议来自 Origin 的提供者元数据，不从 Linux 显示值推断；能力绑定的自身来源无条件排除。变化保留来源、协议、度量和丢弃语义，不复制下一跳组。
4. 每个串行 handler 的可选 Cursor 只持不可变筛选、已确认根和最近提供根；收到成功应用的 offered 代际才推进 acknowledged。
   仍请求已确认代际则从旧根重新求差；未提供代际拒绝。编码、回复/VMO 创建失败不能提前确认，消费者以旧代际重取可合并中间变化。
   所有根在同一 State 锁内捕获，锁外归并/编码及退休；服务每 channel 单 worker，避免交错请求覆盖游标，不增加锁或跨实例历史。

成本为冻结有序路由流的线性归并，只分配最终增量正文；每个消费者至多保留已确认和最近提供的两代根，不常驻另一份 DTO 全表。
慢读者会保活旧图，增量编码仍扫描两代已选表；全表变化成本与控制面截止延迟沿统一规模基准评估，不新增微阈值或宣称规模达标。
现有来源/真实 BGP 对端夹具覆盖来源筛选、连接网段识别、属性替换、撤回与错误批次不前进；原生 RPC 丢回复/退出竞态仍待系统验收。

## BGP 会话配置

唯一配置树的可选 bgp 包含本地 AS、可选 AS 联盟、Identifier 与具名邻居；邻居保存地址、AS、管理距离、hold/retry、被动连接、反射客户端角色、入口/出口策略、宣告间隔和默认路由解析选项。
邻居可用 IPv4 或 IPv6 地址。链路本地邻居在具名域引用该域的接口配置名，在默认域引用运行时接口名。域内地址与接口组合唯一，Identifier、AS、距离和 retry 非零，hold 为零或至少三秒。
缺省/空值表示关闭整个域。邻居的 `shutdown` 缺省为 false，设为 true 时保留配置并停止会话。Schema、差异、备份及导入/导出共享同一配置模型。
import 缺省拒绝，显式策略包含 default、degree 和有序规则；前缀/AS/团体条件、下一跳改写及 degree 的边界见[BGP 契约](bgp.md#入口政策反馈选路与发表)。
export 独立缺省拒绝，按各邻居的有序规则决定实际发布。可使用同一匹配和属性编辑模型，协议限制见[BGP 出口策略](bgp.md#出口策略与实际发送)。
规则可按 ORIGIN、MED、本地优先值及 AS 跳数筛选；范围语义见[BGP 标量政策](bgp.md#标量属性政策)。允许动作还可设置 ORIGIN、Set/Remove MED；同一模型/Schema 服务导入、差异与持久化。
三类团体可按集合替换/删除/添加，解码时排序去重；差异比较使用规范值，规则顺序仍保留。作用范围与成本见[BGP 团体编辑](bgp.md#团体集合编辑)。
改写参与实际协议选路和出口编码，原始接收不变；共享、失败清理与作用范围见[BGP 标量政策](bgp.md#标量属性政策)。
resolve_via_default 缺省为 false；非法前缀范围或下一跳在完整配置校验阶段拒绝，错误路径定位到邻居及规则字段。
cluster_id 为可选反射簇；客户端角色隐含启用反射，缺省簇等于 Identifier。非法外部客户端及反射模式下的内部属性覆盖在副作用前拒绝，错误路径定位到具体邻居/规则。
confederation 的公开身份、成员集合与会话角色由同一模型校验；配置、准入及发布边界见[联盟契约](bgp-confederation.md)，不建立独立配置文件。
配置 owner 从选定域开独立来源，移交同域网络连接。具名域链路本地邻居使用实际接口索引，接口缺席的邻居停用至接口出现。接口归属或寿命变化只重建相关域的 BGP 会话。

1. 校验完整候选后仍先走原持久决定和 NET 确认；BGP 在持久决定后应用。BGP 初始化失败不宣称已经回滚整个配置，返回未确认错误、保持新决定及 Applying，并按原 Port/500 ms 截止重试。
   单邻居启停和已启用 TCP-AO 的换钥经 `UPDATE_NEIGHBORS(4)` 发送实例协议版本、长度与已持久配置 VMO。启停只影响目标邻居，换钥保留活动会话。部分端点尚未应用时保留 Applying，由原 Port 重试最新决定。其他 BGP 配置变化仍重建域。
2. 工厂创建后取得一次实际 SNAPSHOT，才持有实例能力；观察 channel 关闭后重放已保存配置，不恢复先前 TCP 或动态路由状态。
   旧实例的 Port 通知按当前能力是否实际关闭复核，不能关闭新实例。通知分配失败仍保留真实待处理工作，不把失效能力当健康状态。
   没有 pending 工作时不轮询；失败重试不重复增加观察代际。能力 Drop 只关闭句柄，协议行政关闭由 BGP actor 完成。
3. 原生配置管理 BGP_STATUS(15) 复用管理控制帧，无输入正文/句柄；回复原配置代际与一个状态正文能力。
   同一配置锁下取得实例状态和代际；无有效持久配置返回 BadState，等待应用返回 ShouldWait，不伪装成空邻居或 Ready。
   linuxd 经授权 `/dev/network-settings` 提供可重试查询；持久修改走带预期代际的 IMPORT。BGP_REFRESH(18) 复用同一入口，断线时不重放。
   BGP 状态按邻居报告入口/出口策略、客户端角色、配置接口、认证模式及密钥 ID、已协商 IPv4/IPv6 能力、原始接收量及实际 TCP 宣告量，按域报告有效簇、待应用工作与已确认协议选择量。最终 FIB 安装量由路由查询提供。

邻居状态的 retry_blocked 来自协商 owner 的实际停用决定；ipconfig /bgp 显示对端错误和暂停原因。修正双方能力后，须实际修改/关闭再启用本机 BGP 配置以重建域；重复导入完全相同配置不会重建。
正常能力拒绝和不相容只处理该邻居，不终止其他健康邻居；资源/服务失败仍走原域清理。原生主动/被动连接、并发碰撞与断线竞态待系统验收。

BGP_ROUTES(16) 也使用管理控制帧，但必须有一个非空查询文档能力；正文按 tracking::IpPrefix 解码，不误作持久 Configuration。
成功回复同一代际和单前缀结果正文；未配置/待应用/失败边界沿会话查询。原始接收与确认选择的区别见[BGP 路由观察](bgp.md#逐前缀路由观察)。

BGP_REFRESH 输入是 `RefreshRequest` 文档，包含配置邻居名和 ipv4/ipv6。BGP 实例 REFRESH(3) 使用实例协议版本、长度和同一文档 VMO。成功确认已排队，返回当前配置代际。
会话和能力归当前 BGP 实例判定。配置替换、会话退出和资源失败的收发边界见[BGP 契约](bgp.md)。来宾运行和 FRR/BIRD 互通尚未验收。
`transaction::{retry_at,RouterConfig::wake_configuration}` 向同级 BGP 执行器共享原有重试节奏与唤醒，不建立第二套定时器或公开到 crate 外。

## BGP AS 路径筛选

RouteRule 的可选 as_path_regex 是经过编译验证的 AsPathExpression；缺省/null 不增加条件，与前缀、AS 包含及团体条件取 AND，规则仍按首个匹配终结。
入口匹配已完成 AS4 重建的原始路径；出口匹配已经入口政策修改且确认的有效路径，不含本次出口动作或线上追加的本地 AS。拒绝仍进入现有 ImportPolicy 判定/出口撤回流程。

1. 表达式按 ASCII 正则搜索子串；`^`/`$` 限制完整路径首尾，`^$` 匹配空路径，`_` 按固定 FRR 10.0 展开为 `(^|[,{}() ]|$)`，防止数字子串冒充完整 AS。
   支持分组、分支、字符类和重复，不支持反向引用、环视或 Unicode 类；语法由固定 regex-automata 0.4.18 的解析器拥有，不声明完整 POSIX/FRR CLI 兼容。
   AS 以十进制 AS-plain 表达；段间空格，普通序列空格分隔、集合 `{a,b}`、联盟序列 `(a b)`、联盟集合 `[a,b]`，保留类型和顺序语义。
2. AsPathExpression 私有值同时拥有源文本和不可变单方向 DFA；JSON/Schema 只表示字符串，Eq 比较源值，克隆用 Arc 保活同一程序，不重新编译/复制自动机。
   Arc 无弱索引、可变缓存或会话状态，引用全部释放即回收；共享数据可跨配置审阅线程，实际匹配仅用栈上 state。未配置表达式不分配程序或预留匹配工作区。
   完整解码阶段编译并拒绝非法输入，之后才可提交配置；不另设策略文件、编译服务或配置副本。上游编译器内部仍用其 alloc 分配，不宣称完整 OOM 故障注入已验收。
3. 为限制确定化膨胀，展开文本上限 1 MiB，NFA/DFA 的库计量预算各 1 MiB，确定化工作区预算 4 MiB；它们不是整个进程的 RSS 上限。超预算返回配置错误，不切换到回溯/懒编译路径。
   StoredPath 的 Display 由路径 owner 流式提供规范文本，Search 以 fmt::Write 逐段推进 DFA。命中/死状态提前停止；仅完整输入执行 EOI 转移，不能把格式化分块误当作路径结束。

成本为每规则一次冷编译和随程序大小常驻的空间；匹配 O(路径文本长度)、O(1) 临时空间，没有逐路由字符串、匹配缓存或分配。
本次以现有路径/政策夹具保护边界、原始值与实际对端报文，以配置用例保护往返；不新增微基准，完整全表及规则规模的 CPU/内存/传播成本沿统一控制面基准评估，尚无规模性能结论。

## BGP 本机网段意图

BGP 配置树的 networks 为 tracking::IpPrefix 集合（network/length）；缺省空，解码排序去重，手工模型也须规范有序。
同一 IpPrefix 值类型用于精确观察、BGP 查询、网段配置与 schema，几何校验由 tracking 模型统一拥有。
导入/导出、差异、备份与启动重放沿原唯一配置树；网段变更按当前 BGP 配置寿命重建域，不新增配置文件或写入口。
原生 BGP actor 通过已有 WATCH_ROUTES 跟踪能力登记精确查询；每次确认图变化重取冻结结果，不扫描/复制完整 FIB。
来源确认的学习变化先登记出口，再更新本机资格；查询暂未就绪不能吞掉已经确认的学习变化。首图未就绪等待原 Event，不新增周期轮询。
资格与原生出口、属性所有权及成本见 [BGP 本机宣告](bgp.md#本机网段宣告)；原生 RPC、来宾持久化/断线竞态与互通仍待系统验收。

## BGP 其他来源路由发布

同一 bgp 配置对象的可选 redistribute 使用上述唯一 Selector；缺省/null 关闭。空选择拒绝，protocols 集合规范化，BGP 标记 186 拒绝，避免剥去协议路径后重复导入。
connected 选择实际直连网段；protocols 按实际提供者元数据筛选当前已选路由。配置、Schema、差异、持久化及重放仍走唯一配置树，变化沿现有域重建寿命。

1. actor 复用 WATCH_ROUTES 的确认图通知及 ROUTES 增量；先登记来源确认后的学习变化，再更新本机网段资格和重分发候选。首次未就绪等原 Event，不设新轮询器。
   只请求 RoutingDomain 已完整应用的代际。应用先验证范围与撤回身份，再准备共享属性、全部新节点和返回空间；最后无失败替换/删除及推进代际，错误保留旧候选和确认位置。
2. 重分发使用 INCOMPLETE、空 AS_PATH 和来源实际度量对应的本地 MED；与显式网络共享本地出口模型，不反向创建另一份 BGP 转发来源，也不伪造 UPDATE/邻居身份。
   同前缀出口优先有效显式网络，其次重分发，最后有效学习路径；变化进入唯一 AdjRibOut，仍受显式邻居政策、实际 next-hop-self、发送间隔、刷新及完整 TCP 发送记账约束。
   本地 MED 可向外部邻居发布，学习的上游 MED 仍不默认跨 AS 转发；显式出口动作继续有效。
3. 状态的 redistributed_routes 是其他来源候选数；逐网段 redistributed 保留实际来源、协议、度量和丢弃语义。它们都不等于任何邻居已收到，实际发送仍读 exported。
   初始同步以有界游标合并学习、本机和重分发目标。候选索引随重分发数量常驻，临时原子预备随实际变化数增长。

规范依据见[网络基线](../standards-baseline/network.md#bgp)；宿主生产路径检查不代替服务授权/故障竞态、FRR/BIRD 互通或目标规模验收。

## 路由准入策略

Configuration::route_policy 是唯一持久策略对象，包含必填 default（permit/deny）与有序 rules；配置树完全缺省时使用无规则的 permit。
每条规则可按 protocol 和 prefix 取 AND 匹配，缺省条件通配；第一个匹配动作立即终结，未匹配使用显式 default。
prefix 为规范 IPv4/IPv6 network/length，可选 minimum/maximum 限制被声明路由的前缀长度；不指定范围时精确长度。
只有 minimum 时上界为地址宽度，只有 maximum 时下界为 length；基准长度 ≤ minimum ≤ maximum ≤ 地址宽度，非规范网络拒绝。
action 为 deny，或 permit 并可选覆盖非零 preference/metric；不能改来源身份、比较范围、实例、地址族或终止/转发动作。
来源 protocol 取自配置 owner/会话授权元数据，不从路由正文自行声明；它只是匹配条件，不用它推导执行权限。
策略仅作用于受管来源，实际 LOCAL/connected/broadcast 事实在其后装配，不能借策略撤除或改写实际接口事实。
准入策略用于主表和备选表的受管来源；两族共用首条匹配和属性修改，异族前缀不匹配。独立 IPv6 协议来源须显式授权；邻居 import/export 见[BGP 契约](bgp.md)。

router-protocol::policy 同时拥有 JSON 类型/Schema、语义检查与唯一 native codec；没有独立策略文件、私有 syscall/ioctl 或另一条配置入口。
策略 wire 版本 1：12-byte 头（u32 版本、u32 规则数、u8 缺省动作〔permit=0/deny=1〕、三字节零保留），每规则固定 32 bytes。
行布局为 flags/protocol/family/length/minimum/maximum/action/reserved 各 u8，随后 u32 preference/metric 和 16-byte 地址；数值 little endian，地址为网络字节序。
flags 位 0–4 分别表示 protocol/minimum/maximum/preference/metric 存在；family 为 0/4/6，action 为 deny=0/permit=1。
无 prefix 时其长度/范围/地址必须全零，IPv4 地址后 12 bytes 为零；未置位可选字段、deny 的属性、保留位和包尾都完整检查。
编码一次预留最终缓冲，解码一次预留规则数组；OOM 返回 NoMemory，未交出部分策略或产生执行副作用，不增加 RIB JSON 分配/解析路径。

RIB 编译器只依赖纯模型、Source、prefix-index 和 fallible-tree；来源 owner 提供可信 protocol，不让编译机制反向依赖接口/会话 owner。
按通配 protocol/具体 protocol 分桶，再用同一 Poptrie 预筛选两族包含前缀，候选取最早规则序号，不能误用最长匹配代替 first-match。
长度边界在编译时固化，protocol 桶每来源解析一次；同桶/同前缀只有长度条件时，剔除被早期规则完全覆盖的行。
每条保留行至少覆盖一个新长度，因此同前缀最多保留 33/129 行；此剪枝以没有其他剩余条件为前提，新增条件必须重新证明覆盖关系。
编译后只保存动作和索引，不另持完整配置树。无规则 permit 为零程序对象；某来源无相关匹配桶时直接使用缺省决定，permit 复用原 Source。

Routes 持原始来源声明、已确认编译策略及同代解析快照；过滤/属性变换生成有效来源，再进入原 select_resolved 与唯一执行投影，不另建选路器。
被拒绝声明仍留在原来源，后续来源更新同样经过当前策略；清除策略可恢复最新原始声明，不要求生产者重放，不借旧 FIB 或旧策略结果证明递归。
属性字典按完整有效值共享；SourceDefinition 按来源不可变共享身份、比较范围、元数据与 Vec<H> 路径字典；投影只克隆该定义的 Arc，不克隆 M/H 或路径/成员。
原始与投影保持身份/比较范围/元数据不变；没有逐前缀 Arc、在线缓存或额外锁。字典只有只读引用且不反向持 Source，Arc 退休无环且不改变页/设备寿命。
完整下一跳字典可能包含策略暂退路由的对象，解析只从有效选择建立依赖；不把这些保留声明当成当前可达证明。
策略更新、来源替换、接口事件统一捕获同一图；纯策略变更也取原 NET 租约，激活可回滚，确认后才交换 Raw 来源/编译策略。
source_retry_at 现在表示完整路由意图的未确认工作；零接口时仍推进，DHCP 不携策略段时保留已确认策略。
无有效配置前像的完整导入一律重放执行意图，即使静态列表为空；不能因此跳过清除 RIB 仍保留的旧策略。

benchmark 决策：所有新增工作在控制面冷路径，来源定义控制块 O(来源数)，有效行/属性由同代解析快照保活，索引/动作为 O(规则数)。
不增加报文路径工作或第二套选择字段；百万更新的策略吞吐/峰值内存沿既有规模基准统一验收，不能以小用例宣称指标达标。
编译 first-match 与线性规则解释器对照覆盖两族/协议桶/顺序及重复规则查询上界；新 codec 用例覆盖范围、完整截断、隐藏字段和尾部，必要性来自新字节边界。
原生产 NET 事务用例扩展覆盖纯策略激活/撤销、允许属性覆盖、拒绝期间来源替换、清除后恢复最新声明，以及 deny-all 不删除实际直连事实；不新增 fixture/生产采样入口。
这些 host 检查不替代原生传输、存储故障、硬件/规模和端到端验收；完整路由策略与阶段 6 保持未完成。

## 接口默认路由策略

每个 interfaces 配置对象可提供 default_route 属性对象（preference/metric），null/缺省使用配置服务的默认偏好 1、代价 0。
preference 必须非零，metric 为 u32；该对象覆盖默认网关的选路属性，不另行保存网关或实际 ifindex。网关仍来自当前静态地址策略或成功 DHCP 租约。
JSON 导出/导入/差异、Schema 与备份共用同一类型；未知字段和零偏好在持久/执行前拒绝。Linux 兼容设置和名称变化保留原生属性，不冻结缺省策略。
配置服务从当前唯一配置投影 DefaultRoute；仅属性变化也预备接口/RIB 批次，即使地址/MTU 不变也不能短路。
同地址重放保留已有 DHCP 会话，续租换地址时读取当前持久属性，不沿用最初开会话时的属性；租约丢失撤回完整默认意图，不丢持久覆盖。
leases module 拥有 DHCP 会话/事件与地址确认，主文件只装配与处理实际接口寿命；没有多一份租约/策略状态或执行路径。
收到 DHCP peer-close 先退休死能力和该会话的租约，再经原 apply 重开；不能把 Some(dead channel) 当成 Keep，否则重启会永久保留失效会话。
开会话请求/回复先完整检查尾部/句柄数，返回容器在启动工作前预留；畸形请求不能产生新 DHCP 工作，畸形回复不能保留错误寿命能力。

Source 的不可变头部增加一个 owner 授予的非零比较范围，仅占每来源一个 u64，不增加前缀记录或目录引用大小。
范围 1 由 RIB 授予配置 owner 的接口/静态来源；普通协议会话用自身不复用身份作为独立范围，正文与工厂请求都不能自选范围。
身份分配从保留的观测/配置身份之后开始，协议会话不会碰撞范围 1；不从 protocol 观测标记推导权限或范围，也不把范围编码进来源 ID。
在全局偏好相等时，先按比较范围稳定裁决，再比较该范围内 metric；同 metric 继续按来源/行序稳定裁决，排序为严格全序，不用非传递的成对特判。
比较范围与实例/VRF 不同，不能据此扩大地址族或执行表权限。BGP 和 OSPF 的协议内选路归各协议服务。
benchmark 决策：仅冷捕获/排序增加每来源字段与一次标量比较，接口 wire 每项增加 8 bytes；无新锁、逐前缀分配、逐包工作或常驻配置副本。
已有 RIB 线性对照继续覆盖独立范围不比较 metric；生产用例扩展覆盖属性 round-trip、偏好切主备、同范围 metric 切换、恢复及准确导出。
旧接口布局拒绝和无 route 不得夹带属性扩展原用例验证；JSON 回归扩展覆盖覆盖值/历史缺省和零偏好，原生 DHCP/RPC/VMO 行为留到统一验收。

## 静态路由配置

唯一 JSON 配置树新增默认空的 routes 数组，旧版本 1 文档缺省此字段仍表示无静态来源；导出/导入/差异/备份和 Draft 2020-12 Schema 都由同一类型生成。
根级 routes 配置默认双栈 main 表；静态备选表与选表条件见[策略选路](ip-forwarding.md#策略选路)。桌面静态路由表单编辑同一模型并使用打开时的配置代际审阅、提交。
StaticRoute 包含规范 destination/prefix_length、非零 preference（缺省 1）、metric（缺省 0）和 action。
action.kind 为 forward/discard/unreachable/prohibit；forward 必须有非空 members，每成员含非零 weight（缺省 1）与 target。
target.kind 为 direct（interface 为配置对象名称，gateway 可缺省，on_link 缺省 false）或 recursive（address 为不需接口范围的单播下一跳）。
直接引用须为具名物理接口配置或 VLAN 网关。IPv4 路由的直连网关和递归下一跳均可用 IPv6，IPv6 路由只接收 IPv6 下一跳。链路本地只允许直接指定接口。非法前缀、零权重、重复目标及未知字段拒绝。
同前缀多个候选允许保留；静态来源不在配置服务做另一套优选，统一交原 RIB 管理距离/比较范围内 metric 裁决。

Configuration::route_source 按族把同一持久 routes 数组投影为原 routing::Batch；配置服务只按 DeviceMatch 借当前接口解析 ifindex，不把它写进文件。
设备缺席时相应直接成员暂退，空转发组不声明；原持久意图保持，设备安装/重连沿原批次重新投影。递归与终止声明仍可独立存在。
设备匹配含糊拒绝，未注册设备不伪造零身份；接口禁用/载波变化由 RIB 冻结事实裁决，不另存在线缓存。
引用的配置对象换绑设备也会触发来源重编译；仅显示名/DNS 等变化不强迫替换静态来源。
本次投影有 O(静态路由/成员数) 临时字典/记录数组，接收端继续共享/去重属性与下一跳，不引入逐路由 Arc 或报文热路径工作。
投影按本族声明数预留，空族不按另一族规模分配；RibAddress 统一两族解析/策略/执行映射。Facts 新增地址查询仅在冷提交/重算，无新增报文分配、锁或全局。
benchmark 决策：它属于配置冷路径；大配置序列化/VMO/冷编译吞吐沿计划统一验收，不以小 host 正确性用例宣称百万静态更新达标。

接口变化和静态意图一起暂存，持久文件成功后才确认来源；文件失败回滚同一 NET 租约，确认不确定只重试已持久决定。
source_retry_at 只拥有“完整路由意图（静态来源/准入策略）尚未确认”的工作，不镜像 RIB 可达性；初始化/RIB 重连及未确认回滚/提交会排队，成功确认退休。
该工作加入原 Port 的最早截止，零接口时也推进；有有效配置的接口应用都携带完整静态来源与策略，因此可合并未到期来源工作。空闲无定时唤醒或新增线程。
相同的局部设置只重试未完成的执行，不读写文件。完整导入即使配置相同也持久化提交编号。写入前保留原文件前像。
现有模型 round-trip 回归扩展覆盖配置名/临时身份、设备缺席、历史缺省与引用拒绝；原 RIB→NET 用例扩展覆盖意图版本隔离及新地址/静态路由同时发布、整体撤销。
这是跨 codec、来源解析与执行准入的实际回归保护；持久存储故障、原生 RPC/VMO 与设备重连仍待计划末统一运行验收，不新增测试框架或配置副本。

## 原生配置审阅与整份替换

`liteos.network.Settings` 的 EXPORT(6)、SCHEMA(7)、VALIDATE(8)、IMPORT(9)、DIFF(10)、COMMIT_RESULT(24) 复用同一授权 channel。
Linux 客户端经 [router-api](userspace-abi.md#网络管理入口) 调用；网关按账户授权后，通过 root 私有设置端点转发给原生服务。

- `router-protocol::administration` 是控制帧的唯一编解码 owner，root/适配层/客户端共用 Request/Reply。
  请求以 u32 管理控制版本 11 开头，随后是操作专有字段和 u64 正文长度。按域的操作追加长度前缀域名，零长度指默认域。`OPEN_NETWORK_NAMESPACE(28)` 回复固定控制字段、16 字节实例身份和一个原生网络 channel。
  IMPORT 带 24 字节预期代际，IMPORT/COMMIT_RESULT 带 16 字节提交编号，备份导出/删除带 bytes 身份。非空正文携带一个 VMO。具名请求只解析到已配置的作用域。
- 回复控制字段固定 36 字节（u32 线版本、24 字节代际、u64 文档逻辑长度）。EXPORT/SCHEMA/VALIDATE/DIFF 一律返回一个只读 VMO，
  IMPORT 和备份删除仅返回代际、文档长度零且无句柄；其余操作成功时均携带一个内容能力，逻辑长度为零也不能省略能力。
  能力存在性按共享 Reply::has_document 判定，因此零字节损坏备份仍可导出；固定回复容量在持久副作用之前预留，提交后不再分配文档。
  COMMIT_RESULT 返回一字节正文，0 为现有记录无法确认，1 为该次配置已保存。应用进度仍由 GET 查询。
  VALIDATE 检查配置和当前设备别名并返回当前 JSON 格式的正文，不发送 DHCP、不保证后续资源/I/O 成功。
- 代际为启动时生成的非零 u128 随机身份和非零 u64 序号（均小端）。IMPORT 在配置锁内匹配整个代际，拒绝旧实例及并发变化，完整替换可恢复 Rejected。
  GET、WAIT 与审阅共享同一代际。WAIT 在相等时借用原 Event，15 秒到期返回当前代际并释放名额。客户端遇相同值继续等，不重读正文。无逐包成本，订阅规模随管理验收测量。
- DIFF 校验候选配置和当前设备匹配，冻结已保存配置及代际，并在锁外生成差异。已保存配置不可用时列出恢复会写入的内容。
  结果按 JSON Pointer 给出 path 和存在时的 before/after。省略一侧表示新增或删除，显式 null 表示该字段存在。对象按字段递归，有序数组跳过相同首尾元素，再按索引比较。
  BGP 团体编辑列表先规范化为集合值。BGP 和 OSPF 的密钥变更仍会列出，正文仅在审阅中遮蔽。linuxd 只重放断线的只读查询，提交结果不明确时查询原编号。
- 提交编号由客户端按 [RFC 9562 UUIDv4](https://www.rfc-editor.org/rfc/rfc9562.html#section-5.4) 生成。保留的编号不能再次提交。查询与提交在同一配置锁下排序，存储回滚未确认时不返回推断结果。
  `interfaces` 将最近 128 次保存的编号与配置原子替换，布局为配置 JSON、按提交顺序拼接的 UUID、u8 项数、固定版本尾标。撤销恢复整个前像，重启读取后同步目录再确认已保存。
- Linux 同一授权 datagram 只带操作码/控制帧，文档一律经 SCM_RIGHTS fd；不按大小保留内联旁路。
  输入检查可读 regular OFD、完整长度及数量，从偏移零以固定 32 KiB 缓冲捕获为独立只读 VMO，不依赖发送方文件/pager 后续寿命。
  只读查询重放使用相同捕获内容，不能重读一个已变化的文件。输出把原 VMO 包装成真实只读 regular OFD，无第二份正文拷贝。
  输入采用标准 sealed memfd；可变普通文件也可提交，但只保证捕获后固定，不声称与并发文件写原子。
- native 内容的边界/地址空间转换和分配均检查，读取错误不发布部分内容；fd/VMO/普通文件引用随失败、发送失败或客户端关闭正常退休。
  Linux 客户端同时拒绝正文/附带数据截断；IMPORT 的传输失败仍不得盲目重放。
  60 KiB datagram 上限只属于现有设置投影的控制消息，配置文档不再受它或 channel 的 64 KiB 容量限制；实际受文件系统/地址空间/可用内存约束。
  启动和管理入口共用历史 1–5 版网络设置解码器，转为当前配置树后执行同一语义校验。审阅和恢复也接受字段较少的版本 1 JSON 备份。
  启动读取保留原文件，确认提交后写入当前格式。私有提交记录仅由启动读取器处理，导入文档不能携带记录。每次持久化最多追加约 2 KiB，无逐包成本。

## 配置备份

配置树可选 backup 策略（interval_seconds 与 retain 均为非零 u32），null/缺省为禁用。禁用不删除已有文件。
首次启用或策略变更立即捕获一次，之后从成功完成时按单调时间计算间隔；普通配置/租约通知不重置周期，禁用时无周期唤醒。
router-config 同服务内一个后台线程拥有自动备份调度；配置以不可变 Arc 发布，后台只克隆快照句柄，不持配置锁执行序列化或文件 I/O。
调度锁只保护短状态转换，失败快照移出独占执行，被取消的大缓冲在锁外释放。上次接纳的周期策略属于调度执行状态，不是第二个配置 owner。

文件是原 Configuration JSON，无索引/计数器文件；backup-auto-<ULID>.json 与 backup-manual-<ULID>.json 分别表示自动/手动副本。
名字与命名持久化归[服务私有存储](service-storage.md)；备份身份/保留策略归 router-config::backup::archive。
ULID 复用固定库的编解码及 native CPRNG 随机位，排序时间高于当前存量，避免墙钟回退让新副本被当作最旧删除。
展示大小/UTC 时刻由文件系统元数据提供，不把逻辑 ID 时间当作真实时刻。只有规范命名的普通文件参与管理，临时文件、活动设置及未知名字不被轮转。

保存使用原子 CREATE_NOREPLACE；错误可能已创建，读回相同字节后同步目录确认，同一任务重试同一身份，不覆盖不同内容。
新副本确认持久后才清理旧自动副本；手动副本不受自动保留策略删除。清理失败只重试清理，不再创建额外副本；失败每 30 秒重试并公开原生状态。
状态直接来自调度阶段（Disabled/Waiting/Working/Retrying），不在配置提交健康状态里伪造 Ready。namespace 不确定或错误状态改变才唤醒观察者。
私有存储能力关闭由主 Port 观察并结束组件，由监督器重取能力；普通 I/O 失败保留任务，不重启系统。

BACKUPS(11) 查询目录/自动状态，BACKUP_CREATE(12) 建手动副本，BACKUP_EXPORT(13)/BACKUP_DELETE(14) 使用固定备份身份。
请求控制帧在需要目标的方法携带 bytes(16-byte ULID)，不接受路径；这四类请求均无正文。
删除和 IMPORT 成功只返回固定确认、无正文；创建返回 JSON 身份，列表/导出使用原 fd/VMO 通路。仅列表/导出可在断线后重放，创建/删除结果未知须刷新查询。
恢复由客户端先导出，再走带预期代际的唯一 IMPORT，因此仍经完整校验及 NET/DHCP/持久化整批提交，没有第二条恢复执行路径。
启用示例是在已导出的配置中设置 `"backup":{"interval_seconds":86400,"retain":10}`，校验后整份导入；不能用这个字段片段覆盖完整配置。
桌面定时备份表单只修改同一配置模型的备份字段，复用审阅与整份导入。表单使用打开时的配置代际作为基准。
上述调度/能力/归档实现不等于真实定时 I/O、重启或断电验收；这些仍待统一阶段。
