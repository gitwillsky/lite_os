# 原生 IPv6 地址与链路网络契约

从[IPC 与网络契约](ipc-network.md)进入；本文件拥有自动/静态 IPv6 地址、DAD、邻居发现、显式直连 ICMPv6、直连/受管路由 UDP、路径 MTU 及地址共用的组播监听契约。
完整 IPv6 主机收发和路由仍属[路由计划](../plans/router.md)，不能以地址出现代替双栈可用。

## Owner 与入口

- `netstack::inet::ipv6::InterfaceAddresses` 拥有接口的邻居与组播，`ipv6::address::Address` 唯一拥有各地址的 DAD、nonce 及使用资格；随 `NetworkInterface` 生灭，在同一 NET guard 下串行推进。
  不增加锁、Atomic、全局状态、独立线程或另一份设备在线缓存。loopback 不生成以太网地址。
- 管理启用、有效单播 MAC、载波与 MTU 至少 1280 同时满足后，生成 modified EUI-64 的 `fe80::/64` 地址并开始检测。
  关闭接口、载波失效或低于最小 MTU 撤销资格并释放查询、邻居及待解析载荷；恢复后重新检测。冲突状态不会自动转为可用，重新启用才重试。
- `inet::poll` 在回收 TX completion 后推进地址；IPv6 RX 在同一实际 NIC 批次中消费，原 token 归还、AF_PACKET 镜像与计数继续使用设备路径。
  新地址阶段变化通知既有接口观察者；设备链路回调同时唤醒 NET 与控制面，不持有 NET guard 或执行反向查询。
- `ipv6::packet` 只装配/验证借用报文，全部头、选项和 checksum 经 `packet-wire`；`ipv6::membership::Listener` 拥有所属组的监听状态。
  `ipv6::neighbor::Neighbors` 唯一拥有当前接口的邻居/时钟索引与待解析载荷；未引入应用私有接口。
  双栈主机共用设备的原生收发和报文归还机制。[IPv4 主机网络](ipv4-transports.md)

## 地址与邻居发现

1. 初次入组和 DAD 同时随机延迟至多一秒，先完成 MLD 报告义务（提交成功或旧代允许的同组报告抑制），再发一个 DAD NS；源地址 `::`，目的 solicited-node，Hop Limit 255，无 SLLA。
   发送成功后等待一个接口邻居重传间隔（缺省一秒），并先排空接口 RX 再确认 Preferred；预算耗尽推迟确认，避免漏掉已入队的冲突。
   背压不消耗次数，也不能因为回调已执行而宣称 NIC 已接受报文。
2. 每次 DAD 探测取新的六字节 CPRNG nonce；接收当前探测的同 nonce NS 视为回送，记录后补三个探测间隔。
   nonce 只在当前探测观察窗口有效，不靠 MAC 相同忽略冲突；其他有效 DAD NS 或 NA 使该地址变为 Duplicate；仅当所属组没有其他有效地址时退组。
   Tentative 收到普通非 `::` 源的地址解析 NS 静默忽略，既不回复也不误判冲突。
3. Preferred 回应指向本地址的有效 NS：普通解析回送单播 NA，设置 Solicited/Override，携带本机 TLLA；DAD 回应 all-nodes NA，只设置 Override。
   地址可用后使用正式 link-local 源补发 MLD 当前状态。关闭、Duplicate 与尚在探测的地址不能发普通 NA。
4. 接收核对以太网目的/合法单播源、IPv6 来源/目标、长度/MTU、ICMPv6 checksum/Code、Hop Limit、选项边界和 DAD 源规则。
   ND 拒绝所有 Fragment header，包括 atomic fragment；未知扩展选项按 discard 动作丢弃，不绕过端点语义。
   此入口只处理 Hop-by-Hop/Destination 扩展，不执行 Routing/AH，不在此生成 ICMP 错误。

## 静态地址与直连路由

- 持久意图来自唯一配置树 interfaces 对象的 ipv6.addresses：address、prefix_length（0..128）及 on_link（缺省 true）。
  只接受非映射单播，拒绝 ::、::1、多播和重复地址；JSON 读取后按地址排序。完整模型的校验、导出/导入、差异、备份及重放共用此字段。
  当前 router-config 管理的网卡可配置多个地址；原生接口事务也支持 loopback 的额外 /128 单播，::1 仍独立由设备生成。
- 完整配置提交替换该接口的全部手动地址；缺省/空集合清除手动地址，不移除自动地址。DHCPv4 租约使用缺席的 IPv6 意图，保持当前 IPv6。
  同址改前缀/直连策略保留最新 DAD；新分配的地址经过同一检测，不能以事务已确认代替 Preferred。关闭或低 MTU 时撤销实际使用资格。
- 每接口只保留一份 solicited-node 监听状态；多个地址映射到同组时共享，单个冲突或删除不能让其余地址退组。
  准备仅捕获地址意图、组身份并预留实际组向量容量，不改变监听或地址资格；激活/撤销不分配，实际监听及退组时钟始终留在接口。
  共同地址的状态随交换移交；已移除地址失去资格，回滚重新分配时重新 DAD。已完成退组的组可使用预留容量重建，不重放旧查询或旧协议时钟。
- 每 NET 的 inet::route::Ipv6Routes 使用既有 Poptrie 编译本机 /128 与显式直连前缀，地址不隐含 on-link。
  与 IPv4 共用配置写租约；候选根在准备阶段构造，地址/根一起发布或撤销。接口 UP/MTU 和源/目标资格仍读取实际 owner，不复制 DAD。
  热插入同时准备活动与未发布侧的根，任一失败均不发布新接口；热移除不受事务阻止，撤销过滤已移除设备，不复活旧出口。
- benchmark 决策：地址意图/索引仅在冷配置分配；收发为 Poptrie 查询、实时地址匹配和源选择，无额外锁、RPC 或逐包分配。
  源选择 O(A)，全局接收资格检查最坏 O(I×A)，控制监听引用同步 O(A×G)，I/A/G 分别是接口/地址/组数；配置规模、控制公平性与转发成本沿统一验收测量，不宣称常数成本或已通过性能验收。
  双栈静态路由已由统一配置接入。执行范围见下节，动态地址寿命与转发分别见[主机路由发现](#主机路由发现与自动地址)及[跨网卡转发](ip-forwarding.md)。

## 受管 IPv6 路由

- NET 的同一 ConfigurationSession 接受 IPv6 MAIN 表（254）的规范前缀、直达/网关路径、共享带权组及 blackhole/unreachable/prohibit；
  与接口及 IPv4 根在同一 NET guard 发布或撤销。空组、未知接口及非法首选源在预备阶段拒绝，不部分生效。
  同前缀候选按 RIB 下发顺序执行。查询保留候选和原代价，邻居查询报告出口可达性。
- 网关须为非本机单播地址且实际出口具备 UP/最小 MTU；链路地址、显式 on-link 或候选地址的显式直连前缀才证明网关直达。
  不能用将撤销的地址/受管 FIB 证明新网关可达；首选链路源必须属于每个选定出口，回环源不能从物理口发出。
- Ipv6Routes 拥有一个 Poptrie/属性数组，自动本机与显式直连路由优先；受管路径复用 route::nexthop 的类型化字典与带权选择。
  地址变化保留同一不可变路径字典，活动/候选根通过 Arc 冷共享；不复制邻居、DAD 或设备在线状态，热路径不增引用、不分配。
- UDP 的最终 IP 目的保持远端，ND 只解析选中下一跳；提交和失败清理重新查询当前根，不另存每流网关副本。
  失效设备不再可选；热插入同时保留活动与逆向根的受管描述，撤销不会复活已拔出出口。显式首选源被移除后，相应受管路由退休，即使另有存活路径。
- 受管网关以出口接口和网关地址识别。不可变路径字典包含网关到路径组的索引，FIB 根记录当前引用的组。邻居探测耗尽后由同一邻居 owner 保留失败状态，静态配置不改写邻居的 Router 标记。
- NET 轮询合并网关已知失败集合的变化。失败确认、恢复和压力回收通过网关信号报告，接口移除或关闭通过拓扑信号报告。邻居查询继续读取同一 owner。
  发送探测和仍处于 Failed 的重复尝试不发变化通知。合并标记只在处理状态变化时更新，无逐包查询、独立时钟或新的可达性缓存。
- 带权首选成员失联后尝试同组可用成员。原本选择健康成员的流继续沿原路径。全组失联时，先检查同前缀的备用静态路由，再与可用的通告及较短的受管路径比较。
  到达终止路由即按其策略处理。备用路径实际发包后可触发首选网关复探，收到有效邻居确认后恢复其选路资格。
  RIB 收到网关通知后排除同作用域的已知失败邻接，重新展开递归依赖并替换当前 FIB。即使主网关随路由一起撤下，仍可在原邻居 owner 复探。
- 复探只登记本次求解遇到的失败依赖，与 FIB 同事务激活或撤销。邻居必须已存在且处于 Failed，登记复用原时钟和发送预算，成功发出后至少间隔一分钟。
  退出失败状态即停止定期探测并通知 RIB。配置撤销取消对应登记，接口消失随邻居 owner 退休。连续失败或背压保持原状态，无重复重算。
- RIB 的同一递归解析与 Forwarding 投影支持 u32/u128，两族共享组一次转换、逐前缀借用原选择，合成唯一执行正文。
  持久静态 routes 经同一 RIB/配置事务接入两族，IPv4 来源更新保持 IPv6。IPv6 BGP 来源、下一跳跟踪和单播转发已接通。ICMP 回程仍见下节。
- benchmark 决策：新增成本为冷阶段组元数据及候选数组；单成员不计算 hash，多成员使用完整 IPv6 源/目的 jhash2 和原带权算法。
  每条 IPv6 FIB 记录保留一个 u32 下发顺序，备用组沿现有字典去重。单一路由无需遍历备用，失联时只在索引返回的前缀区间内扫描下一候选。
  递归重算沿原冷编译和确认路径，合并网关事件后仍重算两族选路。复探仅额外保存已知失败依赖，每包查找不遍历递归图。大表重算和恢复时延待规模验收。
  准入/撤销、网关切换、失败队列及真实出包复用 NET/NIC 夹具；双栈规模与整机表现待统一验收，不引用旧 IPv4 测量声称已达标。

## IPv6 BGP 路由

IPv4/IPv6 TCP 邻居可按配置协商 MP IPv6 单播，学习路由经同一 RIB 来源、安装后递归检查及 NET 事务接入实际 UDP 回程。
可用本机 /128 为 Local，支持精确网段发布且不能用于递归转发；DAD 未完成或重复地址仍为 Prohibit，回环即时取得资格。
相同地址更改 prefix/on_link 不丢失 DAD；地址失效或移除撤回原宣告，冻结旧图不改变，NET 不重复安装受管 Local。
两族查询/检查与增量读取共用同代冻结图；来源按族替换，撤回及 peer-close 不清除另一存活来源。
发布 IPv6 网段走 MP_REACH/MP_UNREACH，IPv4 TCP 的外部/本机 IPv6 出口需显式配置非链路下一跳，不从 IPv4 地址或 BGP Identifier 猜测。
第一个接收下一跳须非链路；附带 link-local 仅在实际同链路范围已证明时使用，否则保留全局下一跳；不得凭传输对端猜 zone。
单 NIC 夹具串接真实 OPEN/UPDATE、入口政策、RIB、NET、ND/UDP 与撤回，并检查对端接收及 EoR；原生服务与 FRR/BIRD 验收仍待执行。
IPv6 本机 /128 已按真实使用资格参与发布；双栈 TCP 邻居已接通；其余政策/来源契约见[BGP](bgp.md)及[配置契约](router-configuration.md)。

## 路由查询

- 同一域 ROUTE_SNAPSHOT 按族捕获本机、显式直连、受管前缀与全部有效成员；族 0 在同一 NET guard 捕获两族，避免跨发布代际。不从地址另造用户可见路由，也不触发邻居或时钟推进。
  槽号只在捕获时映射为快照内顺序身份，按当前存活接口过滤组成员，无引用组不进入正文；不能把热拔出后的描述写成不存在的出口。
- 本机/直连前缀共用按接口去重的单路径组，受管前缀引用共享字典组；组成员只捕获一次，不按前缀复制。
  旧快照独占正文，后续路由更新、地址迁移或热拔出不改变已返回的行与成员。
- 编码仍在 NET guard 内，完整正文验证和偏移分配在 guard 外。IPv6 冷捕获需 O(接口+槽) 映射及 O(组+成员) 临时存储；
  这是过滤不可变字典中已退出成员所需的短寿命投影，不是第二份活动路由或设备在线缓存。报文路径不增加分配/锁/原子操作。
- linuxd 的 RTM_GETROUTE dump 支持 AF_INET6 与 AF_UNSPEC，投影完整 16-byte 目的/网关/首选源及全部带权路径；
  仍不提供单条 route get、变化订阅或 Linux 写入。字段宽度、消息长度和输出预留沿同一类型化 codec，超出 UAPI 表示范围明确报错。
- 验证扩展既有 NET/NIC 与 route_netlink 用例，覆盖实际递归路由、拒绝动作、双路径热拔出、旧快照不变及 16-byte 网关长度/上限。
  冷捕获不新增墙钟阈值；双栈规模与实际来宾 `ip -6 route` 仍待统一系统验收。

## ICMPv6 回程与邻居可达性

- Preferred 才回应 Type 128/Code 0；单播回复源保持被请求的本机地址，组播回复选接收口可用单播地址，目的复制请求源。
  当前接通本机可用单播、all-nodes 与自身 solicited-node 组的请求；本机回复查询同一 IPv6 FIB，支持本机、直连及受管网关回程。
  全局回复可从另一网卡发出，保留被请求的本机单播源；多播请求的回复源仍属于接收接口，按 RFC 4443 §4.2 选择。
  源或目的为链路地址时固定原逻辑接口 zone；ND 解析选中下一跳，不凭收到帧的 MAC 推断远端直达。
  ND/DAD/MLD 仍由接收链路处理，不沿默认路由转送；回环经同一 IP 编码入口投递，保留逻辑接收接口。
  Identifier、Sequence 与全部数据原样返回，IPv6 TC 随请求，普通回复使用出口单播跳数，缺省 64。ND 仍用 255。链路 padding 不参与回包。
- 已完整接收的 atomic fragment 按 RFC 6946 处理 Echo；真正分片由[本机重组 owner](ip-reassembly.md)统一处理，ND 继续拒绝 atomic 和真实分片。
  非零 Code、坏 checksum、非法源/目标、discard 扩展选项、未可用地址与 Echo Reply/错误消息不会被错误反射。
- 只从有效 NS 的 SLLA 学习 MAC；NA 只更新已有目标，INCOMPLETE 在以太网上必须有 TLLA，Override 清除且 MAC 改变时保留旧 MAC。
  Solicited 确认可达，其他有效改变进入 STALE；收到数据帧或缺少选项时不凭以太网源猜测邻居。
  普通单播 NA 回复也走同一个解析入口，允许在缺少 SLLA 时先做额外的地址解析。
- 未知邻居进入 INCOMPLETE，以当前可用地址为源、携带 SLLA 向目标 solicited-node 发 NS。成功提交才计数，三次探测后仍无响应则判失败。
  REACHABLE 的随机有效期为接口基准值的 0.5 到 1.5 倍，缺省基准 30 秒。过期转 STALE，首次发送进入五秒 DELAY，随后以旧 MAC 发至多三次单播 PROBE。
  到期与首次使用同轮到达也安排 DELAY。普通邻居失败后退休，已学网关按[主机路由发现](#主机路由发现与自动地址)切换路径。上层可达性确认尚待接入。
- 待解析的本机回复最多 64 包/256 KiB，按 Vec capacity 加 AVL 节点计费；最长五秒，并在解析失败或关闭时清除。
  准入时固定本报文的实际出口与邻居键（可为网关），载荷的远端 IP 不变；排队期间不重新选路，不建立每流路由缓存。
  与 UDP 待发队列在重试时重查 FIB 的语义不同，已准入控制报文只等待原下一跳或到期丢弃。
  载荷、等待节点、邻居节点与时钟 storage 全部准备成功才发布；任何 OOM 不遗留半个索引、丢失旧邻居或虚报发送。
  每轮最多处理八个邻居时钟及八个等待报文；发送容量不足只等实际活动，部分排队回复不会无界忙重试。

### 邻居索引与内存证明

每接口懒分配最多 1024 个邻居，数值参考固定 Linux v6.12 的 gc_thresh3；不是复制其全局/按 NET 回收策略。
达到压力上限时按使用时间回收无排队引用的 STALE 或 Failed。容量或内存不足时丢弃本次本机回复并计 TX drop。

- 地址 AVL 只存一份协议状态；另一 AVL 是 `(绝对时间或 Writable, IPv6 地址)` 的派生索引，时钟检查不遍历全部邻居。
  每邻居创建时预留一个时钟节点，重排采用 take/fill/commit；Idle 的 storage 属邻居，排队时只由时钟树持有，同一时刻恰有一份。
  clock 的临时 None 只在不可重入、无分配的独占交换中存在，不能对观察者可见；计时与真实 NIC 发送都不持有第二份状态。
- 已解析路径借用 RX，直接将回复编码到独立 TX reservation，不分配载荷或节点；借用在 consume 内结束，不能把 RX 引用交给等待队列。
  仅待解析时复制到独立拥有的帧；解析后只按权威邻居信息改 L2 目的，再提交 NIC。实际 capacity 与节点费用精确退款，不保留旧 RX loan。
- Writable 身份每轮最多捕获八项，新发送失败不能在同轮反复重试；有实际推进但预算不足时回投，纯容量等待不制造 timer 忙循环。
  所有 error、关闭与退休路径仍归 NET guard；设备记录硬件错误，协议只在实际拒绝/退休时回报 drop，保留重试不算丢包，不复制累计统计。

## UDP 收发

- 原生域服务接受 IPv6 UDP；Linux `socket(AF_INET6, SOCK_DGRAM, 0|IPPROTO_UDP)` 使用同一入口，不存在另一套 UDP 引擎。
  tuple、端口租约、两方向载荷、PEEK/截断、shutdown 与 readiness 属 `inet::udp`；族/zone 及选项契约见 [Socket 传输](socket-transport.md)。
- IPv6 单播目的支持本 NET 可用地址、显式 on-link 前缀及受管直达/网关路由，包括静态全局/ULA 地址；loopback 资格取实际 UP 与最小 MTU，以太网地址必须 Preferred。
  link-local 的出接口由有效 zone 或既有设备绑定确定，其源须属同接口；全局显式源须是本 NET 的可用地址，PKTINFO 指定源还须满足指定出口。
  未指定源按 RFC 6724 的同址、适当 scope、默认 label 和最长共同前缀选择当前出口的永久 Preferred 地址；不缓存选择结果。
  全局单播目的的本机资格在 NET 内检查，允许从另一接口收到该地址的数据/错误；ND 与 DAD 仍只处理接收接口自己的地址，不隐式代理邻居发现。
  本机目的走原 IP-medium 回环队列，并保留原 logical iif；对端直连目的复用唯一 ND/NUD 表。
- 接收验证本地目的、扩展头、完整 UDP 长度及强制非零 IPv6 checksum；atomic fragment 独立交付，真正分片沿[本机重组](ip-reassembly.md)完成后使用同一接收路径。
  Ethernet 不接受 ::1 来源或目的；与 loopback 的扩展选项 discard 规则相同；源 sockaddr、目的与 iif 冻结真实接口，后续设备配置不重建旧记录。
  IPV6_RECVPKTINFO 按实际接收时选项返回目的和接口；PEEK 可切换选项且不消费报文。发送 IPV6_PKTINFO 按顺序逐条验证本次源/出口，
  不修改 socket 绑定；mapped IPv4 与 native IPv6 的不同折叠规则、错误及编码由 [Socket 传输契约](socket-transport.md#linux-边界与当前限制)拥有。
- TX 将源、目的、logical 出口与跳数冻结在原八槽队列；在最终 DMA 写 IPv6/UDP header 和 checksum，不创建整帧暂存。
  `IPV6_UNICAST_HOPS` 与 IPv4 TTL 独立，0 有效，-1 恢复默认 64；设备背压保留队首，实际提交成功才出队。
- 未解析 UDP 仍由 socket 队列持有载荷，邻居表只持解析义务，不复制 payload。ND 每轮返回至多八个实际解析失败的邻居，先结束邻居借用，再由 NET 通知 UDP owner。
  按当前根退休仍经失败接口/下一跳的所有远端 datagram；换路后的等待者保留并立即重试，实际丢弃条数记 TX drop。已关联 peer 受影响时设置原 pending error 槽 HostUnreachable，只消费一次。
  其他路径、metadata 与 FIFO 保持不变，新发送仍可重新解析；完成事实仅活一轮，没有常驻失败数组、每流网关缓存或额外分配。
  无失败缓存或延迟重试特例；关闭、端口释放、接口资格失效和准入后路径消失沿原清理路径。
- 故障退休在已有 backing 原位压紧，只在部分删除且 ring 起点非零时旋转存储；正常收发不运行压紧、不额外分配。
  benchmark 决策：失败路径最多八槽/128 KiB 存储；正常双栈分支、checksum 和实际 NIC 成本沿统一验收测量，不放宽已有门槛。

## UDP 空端口与错误交付

- 合法 IPv6 单播 UDP 找不到监听者时，在原 ingress guard 生成 Type 1/Code 4 端口不可达；checksum 错误、队列已满和非本机目标不能触发此反馈。
  多播目标/非法源静默丢弃；与 Echo 共用 IPv6 FIB 回程，支持回环、直连、网关及不同出接口，不借 IPv4 默认路由或原帧 MAC 推导回程。
  只在实际回程存在后消耗 ingress 限速额度；输出按实际出口 MTU 检查，超限丢弃，不截断 Echo 载荷或伪造硬件错误。
- `NetworkInterface::ipv6_errors` 独占该接口的 token bucket，包含回环；默认 burst 10、每秒补 10，保留不足一次补充的时间余量。
  只在实际无监听者时消费，不创建每流状态或额外 timer。可配置限速尚待路由配置 schema，不宣称已提供管理入口。
- 回复最多 1280 个 IP 字节，引用最多 1232 字节原 IPv6 包，不引用链路 padding。Traffic Class 和 Flow Label 为零，Hop Limit 取出口单播默认值。
  packet-wire 的同一正文/校验和 emitter 直接写最终 IP 或 Ethernet 窗口。Ethernet 先归还配对 TX reservation 再走原控制发送入口，避免占住唯一槽；
  回环沿原 token 携带 logical iif。网卡背压不保留 RX；仅未解析邻居沿既有有界队列拥有独立回复，失败/关闭按原路径回收。
- 接收完整 ICMPv6 checksum、Type/Code 和引用边界后，按引用的原源/目的/端口及 ingress 接口反查同一 UDP owner；引用源必须等于外层本机目的。
  `packet-wire::Ipv6Quote` 允许合法正文截断，但扩展链与所需 UDP 头必须可见；不暴露可当作完整接收包的类型，不对不可见正文伪造 checksum 验证。
- 无 RECVERR 时，端口不可达只交付已关联 UDP；未关联 socket 忽略，不影响其他独立目的。UDP endpoint 唯一持有 pending error，
  POLL 报可读/错误；send、receive（包括 PEEK）或 SO_ERROR 任一消费后清除，返回 ConnectionRefused，由 linuxd 映射 ECONNREFUSED。
  不取消关联、清空数据或释放端口。启用扩展错误的交付见[数据报错误队列](socket-transport.md#数据报错误队列)。
- 验证沿现有生产 NET/NIC/回环夹具，覆盖准确引用/截断、错误 tuple、无监听与队列满的分界、限速余量及错误一次消费；格式夹具覆盖可见扩展链和 Jumbo 引用。
  benchmark 决策：普通 send/receive 多一次常数错误槽检查，只有合法无人监听报文更新 bucket；已解析回复无分配，未解析沿原 ND 上限。
  不增锁、worker、VMO 或服务往返；整机错误流量/CPU/内存沿统一双栈验收测量，不新增独立墙钟阈值。

## TCP 收发

原生 TCP 已接入 IPv6 回环、本机/链路及网关路由；双栈监听、接口范围、共享 ND/PMTU 与 PTB 重分段的唯一契约见 [TCP 装配](ipv4-transports.md#双栈-tcp-装配)。
完整系统/ABI/互通验收待统一执行；BGP 已接入双栈邻居配置与会话；同一链路地址的接口范围和下一跳边界见 [BGP 契约](bgp.md)。

## 路径 MTU

- NET 的 path_mtu::PathMtu 统一拥有双栈学习值。IPv6 按 logical 出接口、源与目的区分路径，不同端口共享估计，NET 之间隔离。
  普通 UDP 不保存学习副本，不以 socket 关闭清除仍可服务其他端口的估计。当前适用本机 TCP/UDP 的实际所选路径，不代表完整双栈转发已提供。
- 仅 Type 2/Code 0、完整外层 checksum、合法可见原 IPv6/传输头及匹配 tuple 可更新；引用源必须等于外层本机目的。
  报告值小于 1280、未小于原头声明的完整 IP 长度、错误端口/接口或不可辨认的引用均拒绝，不能拿截断引用的可见长度当作原报文大小。
  Ipv6Quote::original_length 来自同一次完整头/Jumbo 校验，不把引用交给普通接收 parser 或复制引用载荷。
- 学习只收紧实际出口上限；更大的 PTB 不抬高有效估计。相同或更小值续期十分钟，过期后下一次普通发送可使用实际出口 MTU 探测增长，不额外发包或增加 timer/worker。
  报文准入、查询与实际提交都使用该 owner；poll 传同一轮冻结时刻，不在提交中重读时钟。实际接口 MTU 始终是上限，接口退休或源地址失去使用资格时清理相关路径。
- 有效 PTB 即使对应未关联 UDP 也更新路径；未启用 RECVERR 时，仅已关联 endpoint 通过原 pending-error 槽交付 MessageTooLarge，由 Linux 映射 EMSGSIZE。
  receive/PEEK、send 或 SO_ERROR 消费一次，不改变 peer、端口或独立目的的队列。已准入的数据报按新路径上限分片。禁止分片且超限时退休并记 drop，已关联 endpoint 同样报错。
- 标准 IPV6_MTU 查询已关联 IPv6 UDP 的当前路径值，未关联返回 NotConnected；mapped peer 查询实际 IPv4 路由 MTU，不学习 IPv6 PTB。
  设置 0 清除手工发送上限，至少 1280 的非负整数只约束新发送；路径 MTU 与实际设备 MTU 仍优先。查询不把手工上限伪装为网络估计，也不消费 pending error。
  设置不改写已排队载荷；显式上限属于原 InetSocketOptions，IP 层不复制。原选项查询追加 Ipv6Mtu，设置编码 kind 11 携带 i32；不增加 syscall、ioctl 或数据环布局。
- 表只在匹配的有效 PTB 时可失败分配，两族合计最多 1024 项；达到压力上限先清除过期项，不驱逐活跃估计来恢复过大的发送。
  容量或分配失败不改变旧估计、不发布半个节点；原异步 EMSGSIZE 仍交付，查询保留实际已知值，不虚报学习成功。配置化寿命和容量尚未开放。
  过期项查询时不再生效，存储在压力或接口失效时回收；NET 销毁释放全部节点，无全局缓存或锁。
- benchmark 决策：空表不分配，每次 IPv6 UDP 准入/提交新增一次 O(log P) 查找；PTB 按有界表插入，压力回收为 O(P)，接口资格清理为冷路径 O(P × I × A) 扫描，I/A 分别为接口/每接口地址数；全局源核对整个 NET，链路源仍限原 zone。
  整机双栈验收沿现有实际 NIC、CPU、吞吐与内存测量，不增加脱离 IPC/数据面的微阈值。生产 NET/NIC 回归覆盖坏反馈、路径共享/隔离、手工上限、排队重检、过期和退出清理；来宾 ABI 与互通仍待验收。

## 主机分片发送

- UDP 与普通 RAW 取当前路径和入队时冻结的 IPV6_MTU 上限中的较小值。默认允许本机分片，IPV6_DONTFRAG(62) 可设/查，禁止时超限返回 EMSGSIZE。
  原生选项设置 kind 24 携带布尔值，查询追加编号 30。TCP 保持按 MSS 分段。
- UDP 在最终设备窗口写分片并复用完整数据报的校验和，分片关闭传输校验卸载。普通 RAW 先完成应用指定的校验和，再按 RFC 8200 放置分片头。
  逐片携带 Hop-by-Hop 或截至 Routing header 的扩展头。首片必须容纳剩余扩展头和完整的已知上层头。HDRINCL 由应用提供各片，按设备 MTU 准入。
  ND 消息的自动分片受 RFC 6980 限制。Jumbo 发送、IPV6_MTU_DISCOVER 模式和逐报文 DONTFRAG 控制仍未开放。
- 同一 NET 的 IPv4/IPv6 标识共用 `inet::identification` 的 4 MiB 节点上限和回收预算。IPv6 以线上源、目的为键，按 RFC 7739 的随机初值分配 32 位编号。
  保留到最后一片提交或报文退休，之后等候 60 秒才允许复用。入队失败、ND 失败与关闭均释放保留。准入时超出编号或节点预算返回 ENOBUFS。
- 设备背压保留队首偏移。路由 MTU 变化时仅重新划分尚未提交的区间。组播本机回送仍只提交一次完整报文，路由器保持 IPv6 PTB 语义。
- benchmark 决策：普通报文不查标识表。分片不额外分配载荷，每片将所需头和载荷直接写设备窗口。
  宿主夹具覆盖背压、冻结策略、校验和、实际重组和 RAW 自带片。真实网卡、来宾 ABI 与吞吐并入统一验收。

## 组播监听

- 地址监听 `ff02::1` 与自己的 solicited-node 组；all-nodes 按标准免报告，solicited-node 以 ASM EXCLUDE 空集合报告，兼容 MLD snooping。
- UDP/RAW 通过标准 `IPV6_JOIN_GROUP`/`IPV6_LEAVE_GROUP` 修改 ASM 成员，使用 20-byte `ipv6_mreq`；长输入只读取标准结构，短输入拒绝。
  重复成员返回 EADDRINUSE，退出不存在成员返回 EADDRNOTAVAIL，非法组返回 EINVAL，加入未知接口返回 ENODEV；TCP 不支持成员操作。
  非零接口采用实际 NET ifindex；0 在加入时选择已启动、满足 IPv6 MTU 的首个非回环接口（没有时用回环），退出时匹配任一同组成员。
  加入不改变本地绑定、端口或发送接口。可以绑定组播接收地址，链路作用域必须有 zone/设备绑定；绑定具体地址的 socket 不再因目标是组播而接收其他目标。
  组播绑定只过滤接收，不作为发送源；关联默认目标保留组地址过滤，IP owner 仍选实际单播源。
- Socket 唯一成员表按 `(组, ifindex)` 排序，未加入时不分配，最后退出时释放容量；接口按引用聚合应用与地址的监听义务。
  加入先准备 socket 容量，再准备/提交接口引用，最后发布成员；任何 OOM 不留下半个成员。退出/关闭无分配，设备已退休时只释放成员。
  接口重启保留 socket 引用并重新报告；地址撤销不能删除应用所需组，应用退出不能删除地址所需组。不复用的 ifindex 防止旧成员迁移至新设备。
- `IPV6_MULTICAST_ALL` 可设/查，默认 1；默认接收已由 IP 层准入的接口组播，设为 0 后 UDP/RAW 只接收自身在实际入接口加入的组。
  仍需满足协议号、端口、绑定地址/设备、关联来源与校验和。最后一个引用退出即撤销接收资格，退组报告重传不延长资格；已入队报文保留。
  内建 ICMP/ND/MLD 不受应用成员或 RAW 类型过滤器阻止。
- 复用 INET `SET_OPTION`：kind 13 为 MulticastAll 标量；kind 14 的通用值是加入布尔（0/1）、选项字节为 0，随后是 u32 版本 1、带长度前缀的 16-byte 组地址及 u32 接口。
  kind 15/16/17 分别为默认组播接口、跳数及回送，沿通用标量格式；查询项在既有选项表末尾追加，不改变旧编号。
  所有 SET_OPTION 都在副作用前验证完整请求、拒绝额外 handles 并预留结果；服务能力限定可操作的 NET，Linux 内存布局仅在 linuxd 解析。
- UDP/RAW 的 `IPV6_MULTICAST_IF`、`IPV6_MULTICAST_HOPS` 与 `IPV6_MULTICAST_LOOP` 均可设/查，默认分别为 0、1、1。
  接口 0 恢复自动选择；未知接口和设备绑定冲突不改变旧值。跳数 -1 恢复 1，0..255 有效；回送只接受 0/1。
  设备绑定、链路/接口作用域的 zone 与单次 PKTINFO 按既有冲突规则约束实际接口；它们未选择接口时才使用默认组播接口，因此单次控制可覆盖默认值。
  组播与成员共用实际链路默认选择，映射到 `33:33` MAC，不经单播网关或 ND；源选择按组播 scope 比较候选单播地址。
  当前不提供可配置的组播路由表或组播跨接口转发，单播 FIB 与转发行为不变。scope 0/15 发送明确拒绝；Ethernet 入站拒绝 scope 0/1/15。
- 跳数与回送意图随数据报发布冻结；单播选项和后续修改不能重写旧数据报。RAW HDRINCL 保留报文本身的跳数，校验和规则见 [RAW 契约](raw-ip.md)。
  Hop Limit 0 和接口内组播只投递本机成员，不占 NIC reservation；实际 lo 设备仍沿自身队列单次发送，不再额外复制。
  正常链路发送在首次 IP 输出时消费回送义务，使用已有 lo 固定队列并保留实际逻辑接口；NIC 背压不阻塞或重复本机投递。
  回送前与接收时均检查实际接口成员和地址/协议资格；本机队列满只丢该副本并计 drop，不无限重试或撤销已安排的链路发送。
- MLDv2 报告使用 Hop Limit 1、HBH Router Alert 值 0、完整 ICMPv6 checksum；无可用链路地址时按 RFC 3590 使用 `::`。
  组状态由双族共用的 `multicast::listener::Listener<A>` 持有，MLD 只适配消息及接口参数；来源仍用紧凑 IPv6 地址，不扩大为带族标签的列表。
  当前代首次入组和退组按 Robustness Variable 重传，随机间隔不超过一秒；旧代非 Done 重复报告间隔按 RFC 2710 为 10 秒。
  成功提交才消耗次数；旧代同组报告可结束待发送报告并进入已监听状态，抑制后不错误宣称自己是最后报告者。
- 普通、组和来源查询按 RFC 9777 合并；更早的完整回复覆盖后续查询。来源查询去重后以 INCLUDE 记录回答，不把全组监听误变为永久来源过滤。
  一组来源过大时按 MTU 分为多个记录，已发前缀不因背压重发，未发尾部保留；新查询只与未发尾部合并，旧代一份等价报告可同时覆盖查询与状态变化。
- 来源查询最多持有 128 个 IPv6 来源（2 KiB 逻辑内容），仅实际查询时 fallible 分配；超额/分配失败保持已有义务。
  限额依据 RFC 9777 §10.1，避免同链路输入无限占内存；不改变本机真实监听集合。
- 收到有效 v1 Query 进入 older-querier 窗口，按 v1 报告与抑制规则执行；只有最后报告者发送 Done，窗口结束恢复 v2 当前状态报告。
  兼容时钟、Robustness Variable 和 Query Interval 只归接口；新加入组立即使用当前参数，组专属查询也更新接口参数，不逐组复制查询器状态。
  Query 必须来自 link-local 并带 Router Alert/Hop Limit 1；其目的可以是接口拥有的单播或多播地址。
- SendTime 区分绝对计时与等待发送容量。等待容量不生成立即重投 timer，依靠设备活动重试；依赖尚未成功入组的 DAD deadline 不单独驱动忙循环。
  每接口每轮的组播与 DAD 两类分别至多四次实际控制提交；成功后轮转，预算耗尽续调度，设备背压等待活动。
  所有 IPv6 RX 与 IPv4 共用既有收包预算，不能因族分支漏记预算；同轮沿已有八接口批次。
- 回环和 scope 0/1 不产生 MLD 报告，也不留下等待发送的到期工作；应用来源过滤配置、IPv4 IGMP 与完整双栈组播仍待补齐。
- benchmark 决策：成员修改属于冷路径，连续有序表查询为 O(log G)，单播只做地址族/组播判断，不增加分配、锁或 RPC。
  实际组播收包仍沿既有有界 demux 与队列，不新增逐报文副本；MLD 查询来源只校验一次，运行时吞吐与 snooping 互通留待统一验收。
  发送借用既有 IP 输出与接口事实，无新增锁、路由副本或报文分配；RAW 从已有编码队列复制，UDP 在最终 NIC/lo 窗口共用同一 codec。
  本机副本需要一次额外写入和软件校验和，不能直接复用尚未完成硬件校验和的 DMA 数据；不分配中间帧。组播开/关回送及 checksum offload 的成本纳入统一 pps/IMIX 验收。

## 主机路由发现与自动地址

- 每个以太网接口独立决定是否发送 RS 和接收 RA。缺省仅在 IPv6 转发关闭时允许，可显式禁止或允许转发时学习。RS 在随机初始延迟后最多实际发送三次，间隔四秒。收到有效 RA 后停止。
  没有可用链路地址时用未指定源，省略源 MAC 选项。策略定义及事务见[路由配置契约](router-configuration.md#原生接口执行事务)。
- RA 必须来自非本接口地址的链路本地地址，目标为本接口地址或全节点组。ICMPv6 checksum、Code、hop limit 255、选项 framing 均须有效，且不得含分片头。仅合法的源 MAC 选项可供邻居学习。
- 主机采用合法通告的 IPv6 MTU，范围为 1280 至设备当前 MTU。无 MTU 选项或值越界时沿用上次接受的值。IPv6 路径 MTU 和发送检查以此为链路上限，IPv4 和网卡 MTU 保持各自的配置。
- 非零 Cur Hop Limit 更新接口的本机单播默认跳数，零保留现值。普通 UDP、原始 IP、TCP 和本机 ICMPv6 使用选定出口的值。显式 socket 跳数、自带 IP 头和协议固定跳数各自优先。
  数据报在准入时冻结跳数。TCP 和路由回复的默认值在实际出接口确定后应用，转发数据沿原报文跳数递减。
- 邻居 owner 采用通告中非零的可达基准时间和重传间隔，下限分别为 100 ms 与 10 ms。既有计时截止保持有效，新探测及 DAD 使用当前间隔。可达时间在首次确认、基准变化及每三小时后的首次确认时重新取样。
- RDNSS 和 DNSSL 的寿命独立于默认路由。同接口重复条目只续期，零寿命撤回，到期或链路关闭后移除。RDNSS 拒绝含非单播服务器的选项，链路本地服务器在投影中携带 ifindex。
  每接口分别保留八条服务器与搜索域，满时优先回收最早过期条目。同一通告内按出现顺序保留新条目。DNSSL 沿现有 DNS 文本规则接受 ASCII 主机域名，去重忽略大小写。
  新增、撤回及过期经网络域通知设置服务，DNS 的无变化续期不要求刷新解析配置。读取与投影均在控制路径，普通收发不查询 DNS 列表。
- RA 路由、PIO 的直连前缀及 SLAAC 地址各自独立计时。PIO 的 L 位更新直连前缀，A 位在有效的 /64 前缀上复用接口 IID 和 DAD。优选期结束后仍可收发，自动选源优先使用优选地址。有效期结束后撤回地址。
  已有地址受 RFC 4862 两小时规则保护。手工配置同一地址时移交唯一的 DAD 状态，保留通告寿命，撤销手工配置后仍有效的自动地址接回该状态。
- RIO 按规范化前缀、前缀长度和网关更新路径，寿命为零只撤回该路径。`::/0` 选项覆盖本通告头部的默认路由寿命和优先级。接收有效 NA 且 Router 位清除时撤回该网关发布的全部路径。
- 本机地址和通告直连前缀先于通告网关路径。链外目的按最长前缀和通告优先级选路，平级时优先已解析网关。选出的路径与配置或协议路由按前缀长度比较，同前缀优先采用配置路由，SLAAC 本机 /128 仍走本机。
  普通 ND 耗尽探测预算后保留已学习网关的 Failed 状态，选路优先使用仍可达路径，即使备用路径前缀更短。未知网关仍可启动首次解析。收到有效邻居确认后首选路径可再次使用。
  UDP、TCP、原始 IP 或本机回复经备用路径实际提交后，安排一条可探测的较优通告网关。候选与实际路径按相同优先规则比较，网关以接口和地址共同识别。平级路径依解析状态及稳定身份择优。
  首选通告路径失效时，可由其他接口或较短的静态路由承载流量。相继提交的数据可触发多条较优路径复探。全部通告网关失败时，在有发送请求时优先尝试当前可复探的网关。
  每个网关两次实际复探至少相隔一分钟，背压期间沿现有可写队列等待。无效或过期通告不参与选路。静态网关与通告网关共用邻居确认与复探节奏，见[受管 IPv6 路由](#受管-ipv6-路由)。
  已排队的全局 IPv6 UDP 与原始 IP 单播重查出口，保留已选源地址及分片身份。显式接口绑定、组播出口和链路本地作用域仍限制出口。
- 每接口最多记录 8 条默认路由、24 条指定网段路由、16 个直连前缀和 16 个自动地址。无学习状态时无需分配。接口失去载波、关闭或低于最小 MTU 时清空。停止接收通告后已学事实仍按原寿命失效。
- benchmark 决策见双栈转发的 pps/IMIX 验收。选路从接口 owner 读取有界候选，在同一次遍历获得当前路径和可复探候选。实际提交后复用 ND 时钟节点登记，无新增锁、分配或路由索引。
  IPv6 MTU 采用已有链路值与通告值的较小者。邻居确认复用每链路的随机可达时间，通告处理和定时均不增加逐包分配或 RPC。
  单播跳数复用已经选出的出口，发包时读取一个标量。查询关联 socket 的默认跳数走现有只读路径查询，不建立新的路由缓存。

## 下游路由通告

- 配置启用通告且 IPv6 转发开启时，接口复用现有 MLD 监听器加入 `ff02::2`。以已通过 DAD 的链路本地地址为源向 `ff02::1` 发送 RA，Hop Limit 255，并发布源 MAC 和有效链路 MTU。
- 前缀来自已可用的手动直连 /64 或仍有有效期的下游委派。两者都携带 L/A 标记，同网段只发布一次，显式手动意图优先。配置预备联合校验活动前缀和 DNS 选项，确保可放入一个最小 MTU 通告。
  手动前缀优选期为 45 分钟、有效期为 90 分钟。委派前缀的 PIO 寿命分别限制在上联租约剩余优选期和有效期内，向下取整到秒。
  委派与通告共用绝对截止时间。转发和路由查询在同一接口读取未过期的直连前缀，路径查询显示 DHCP 来源。到期退休路由并通过现有通告历史撤回旧前缀。
  运行期只记录实际发出的前缀。已发布前缀变为不可用时，通告以相同 L/A 标记和零优选期、零有效期撤回，继续发布 90 分钟。客户端的地址有效期仍受 RFC 4862 两小时保护约束。
  新旧前缀放不进一帧时分批发送，每帧保留当前默认网关寿命。启用接口的前缀历史最多容纳三个最小 MTU 通告。预备时为当前、候选和仍有效历史的并集保留空间，超限保留原配置。
  历史跨同接口运行期链路重启保留，设备移除或系统重启后由客户端已发布寿命退出。上联会话和下游分配见[委派会话契约](ipc-network.md#dhcpv6-前缀委派会话)，独立通告前缀仍待接通。
- 通告可按接口发布有序的 IPv6 DNS 服务器。RDNSS 寿命为最大通告间隔的三倍，独立于默认网关寿命。替换、清空或停用时，对上次已发出且仍有效的旧地址发送零寿命 RDNSS。
  新旧 DNS 和活动前缀无法同帧容纳时，先发包含当前 DNS 和撤回 DNS 的通告，再按最小组播间距刷新活动前缀。设备背压期间保留待撤回地址，历史只在提交成功后更新。
- 定时组播按配置区间随机选择，前三次之间最多十六秒。有效 RS 合并到下一次组播，随机延迟至多 500 ms，并遵守三秒组播最小间隔。背压只等设备可写，实际提交后推进时钟。
- 停用策略或关闭转发时，链路仍可用则分批发出零默认网关寿命及零寿命前缀和 DNS，最多三次。设备已关闭或失去载波时依客户端寿命退出。事务回滚恢复原策略并重新调度，已提交的报文仍由协议寿命约束。
- benchmark 决策：只在通告时钟到期时遍历地址和已发布历史，使用有界栈数组直接编码 DMA。前缀和 DNS 历史按预备容量分配，无逐包堆分配、新锁或周期 RPC。
  选路复用本轮时钟和已有动态候选遍历。真实设备组播、负载与互通沿统一系统验收测量。

## 地址查询与版本

- `InterfaceSnapshot` 是固定大小、可复制的轻量接口事实。接口 codec 版本 5 包含 VLAN 网关类型，完整地址统一从 NamespaceService::address_snapshot 查询。
  收发/AF_PACKET/路由事实不因多地址枚举增加分配或列表复制，没有新旧地址查询双轨。自动链路地址的阶段只由 Address 提供，不由投影层计时。
- 原生查询 ordinal 15 携带 u32 接口（0 表示全部），严格拒绝尾部和输入句柄；未知非零接口返回 NoDevice。
  成功返回领域结果、u64 正文长度及唯一只读 VMO；当前 namespace 能力决定可见 NET，不增加应用私有入口。
- `network-protocol::namespace::addresses` 拥有 AddressSnapshot 版本 6。8-byte 头为 u32 版本/行数，每行 56 字节。
  行为 u32 原生接口、u8 地址族（4/6）、u8 前缀长度、u8 状态（0 tentative、1 preferred、2 duplicate、3 deprecated），
  u8 flags（bit0 广播存在、bit1 显式 on-link、bit2 接口内建来源、bit3 当前可用、bit4 SLAAC 来源），
  16-byte 地址（IPv4 后十二字节为零）、4-byte IPv4 广播（缺席时为零）、16-byte 接口名、四字节零保留及两个 u32 剩余寿命（优选、有效，单位秒）。
  AddressOrigin 由 owner 提供，Interface 为内建地址，Configured 为配置安装（含租约），Slaac 为通告自动配置。配置集合替换只撤回 Configured 意图。
  usable 由同一 NET guard 根据 Preferred 或 Deprecated、接口启用、载波及所属族最小 MTU 冻结。Tentative 与 Duplicate 均不可用。
  单次读取单调时钟，根据 owner 的实际截止计算剩余寿命。余数向上取整，u32::MAX 表示无限，优选期结束后有效地址以 Deprecated 查询，已过有效期的地址省略。
  已配置但尚待 DAD 启动/重启的地址以 Tentative 查询，不能从配置事实消失或提前成为可用源。
  拒绝非法族/前缀/状态、隐藏字段及尾部；IPv4 只有 Preferred，IPv6 不带广播，不接受 mapped 地址。
- 同一 NET guard 下稳定遍历计数并编码，仅分配最终正文；旧 snapshot 随接口关闭或 DAD 改变仍保持冻结事实。
  OOM 不改变地址、探测或接口状态；客户端验证完整正文后才提供逐行读取，不再复制第二份地址数组。
- Linux `RTM_GETADDR` 按 AF_UNSPEC/AF_INET/AF_INET6 从同一快照惰性投影实际行，IPv4/IPv6 共用地址消息生成器。
  当前以太网自动链路地址为 /64、link scope，回环 ::1 为 /128、host scope，按实际 UP/最小 MTU 资格出现；IPv4 DOWN 时保留的配置地址仍可查询。
  手动地址投影实际前缀/状态，未建立直连前缀时带 IFA_F_NOPREFIXROUTE；Tentative/Duplicate 分别带 IFA_F_TENTATIVE/IFA_F_DADFAILED。
  SLAAC 地址使用动态来源标志，Deprecated 带 IFA_F_DEPRECATED。IFA_CACHEINFO 提供捕获时的剩余优选期和有效期，创建与更新戳沿用零值。通告学习的单播路径标记为 RTPROT_RA。
- Linux 位宽只在投影边界校验，原生接口保留非零 u32；不能表示时整批 EOVERFLOW，不发送部分结果或截断身份。
  尚未开放 IPv6 地址修改、地址变化多播或 `/proc/net/if_inet6`，完整范围见 [Socket ABI](../syscall-support/socket.md#netlink_route)。
- benchmark 决策：地址枚举是冷路径 O(A) 捕获/验证和单份正文，逐接口读取当前链路资格；DAD 拆分仅改变所属对象，没有新增锁、分配、计时器或探测。
  普通收发不捕获地址快照，查询成本与多地址规模沿统一系统验收评估，不新增微基准或放宽门槛。
  现有 NIC/NET 回归保护 DAD/MLD/NUD、回环及冻结/关闭；codec 与实际 Linux 投影用例不代替来宾 `ip addr` 或服务 RPC 竞态验收。

## 邻居查询

- 两族邻居表分别独占实际地址/MAC/NUD/时钟与待解析义务。IPv6 有效 NA 的 Router 位保存在同一记录，Override 拒绝的地址变化不能借此修改 Router 身份。
  `NamespaceService::neighbor_snapshot(index)` 在一个 NET guard 冻结指定接口或全部接口，不触发解析、刷新可达性或延长寿命。
  原生接口身份是非零 u32；Linux 位宽属于投影层。普通探测失败项退休；承担复探义务的失败网关保留邻居记录和时钟，撤销义务后可按容量规则回收。
- 域请求 ordinal 14 携带 u32 接口（0 表示全部），拒绝尾随数据与输入句柄；未知非零接口为 NoDevice。
  成功回复为领域结果、u64 正文长度及唯一 VMO；句柄/长度与完整正文验证成功后才生成快照，既有域能力决定可见 NET，不开放应用私有入口。
- `network-protocol::namespace::neighbors` 拥有版本 3 的快照封装，8 字节头含 u32 小端版本和行数。`router-protocol::neighbors` 拥有共用的 32 字节记录。
  行依次为 u32 接口、u8 状态（0 incomplete、1 reachable、2 stale、3 delay、4 probe、5 failed）、u8 Router、u8 当前阶段次数、u8 MAC 是否存在、
  16-byte 地址（IPv4 后补零）、6-byte MAC、u8 地址族 4/6、u8 零保留字段。Router 位仅限 IPv6。Incomplete 和 Failed 的 MAC 字节全零。非法长度、字段或状态组合均拒绝。
- capture 在同一 guard 两次遍历（计数/编码），只准备一份正文存储；服务经 VMO 交接，linuxd 持不可变正文，dump 按游标逐条投影，不再复制行 Vec。
  OOM 不发布部分集合、不改变邻居或时钟；关闭/设备删除清理 owner，已冻结 dump 保持捕获时的事实。现有 NET/接口生命周期与权限不变。
- Linux 入口支持双栈 `RTM_GETNEIGH` dump 和按接口/地址单条查询；状态、MAC、IPv6 Router 位与实际探测次数按标准 ndmsg/NDA 属性输出。
  没有权威的年龄或历史探测次数不伪造 NDA_CACHEINFO 或非活动阶段 NDA_PROBES；Linux 接口号不能表示时在发布整批之前返回 EOVERFLOW。
  具体请求规则、写入限制和未开放投影由 [Socket ABI](../syscall-support/socket.md#netlink_route)拥有，不在原生服务编码 Linux 常量。
- benchmark 决策：查询按实际邻居数量线性捕获与验证，属于冷路径；普通收发不增加快照、扫描、锁或消息。
  NA 接收只更新所属记录的一个 Router 位；新增成本沿统一系统验收检查查询延迟/临时内存及并行流量，不设置脱离 IPC 的 host 墙钟阈值。
  现有 ND fixture 验证冻结、过滤、NET 隔离、Router 规则、OOM 与关闭；同一生产 netlink codec 验证双栈 UAPI，来宾 `ip neigh` 仍待验收。

### 桌面邻居观察

- 域操作码 20 和授权设置操作码 25 复用同一邻居记录。续页键由逻辑接口号和双栈地址组成。查询在同一 NET guard 按接口、IPv4、IPv6 顺序取最多 64 条及一条前瞻记录。
  先在有序接口表定位，再从原邻居树按地址续读，编码在锁外完成。回复头包含版本 1、行数、后续页标志，每行先是 32 字节邻居记录，再是 16 字节接口名。查询不触发解析或续期。
- 网关操作码 `0x80000002` 接受[按域内联请求](userspace-abi.md#网络管理入口)和同一个游标。正文首字节 0 为保活，1 为完整页，2 为行数、后续页标志、u64 变化位置及对应记录。接收方验证新页排序和游标后才替换旧页。
- 可见页每秒采样，沿用[有界会话与保活](ip-forwarding.md#桌面计数订阅)，离页停止。界面按接口和地址保留选择。Linux 的邻居 dump 沿原入口读取全量，管理分页不引入 Linux 多播订阅。
- benchmark 决策。窗口和网关只持有一页，报文处理没有新增工作。并行观察的锁持有时间、快照和消息开销纳入整机验收。[桌面入口](../../user/programs/network-manager/README.md#邻居)

## 验证、成本与边界

固定来源见[网络基线](../standards-baseline/network.md#ipv6-自动链路地址)。宿主复用既有 NIC loan、NET poll 与 codec 夹具，
覆盖真实出帧、DAD/ND/MLD 与地址投影；同链路 Echo 全载荷/奇数长度/MTU/padding、借用退休与收包预算，
以及邻居学习/Override/主动解析/NUD、逐项分配失败与等待队列上限/分批清理。
网关与双 NIC 用例覆盖单播源保留、多播接收口选源、异路回程、下一跳解析及端口不可达引用；固定 TX 存储的 allocation fault 保护已解析路径不分配。
这些检查不证明真实网卡的组播接收过滤、交换机 snooping、成熟协议互通或完整 IPv6 合规；统一系统验收仍待执行。

benchmark 决策：Echo 与邻居查找新增主机热路径，沿最终双栈数据面的实际 NIC、pps/IMIX、空闲 CPU 和内存统一测量，不新建脱离完整数据面的墙钟门限。
当前结构成本是一次 IPv6 FIB 选路、O(log N) 邻居查找、预留时钟的无分配重排及一次载荷 RX→TX 拷贝；仅查询存储/未解析帧分配，按上限清理。
选路借用同一 NET guard 的接口字段，RX 设备 loan 不扩大为整个接口的独占借用；不增锁、配置副本、服务往返或常驻路由缓存。
每次 NET poll 每接口读取一次设备共享链路事实，不做 LINK RPC；宿主资源回归不作为整机无性能回退的结论。

尚未实现：OSPFv3、DHCPv6-PD、邻居配置/变化订阅、
上层可达性确认、错误队列其他附带信息、组播路由、可配置 DAD/容量与接口 ID 策略。主机分片和错误队列见前文及[传输契约](socket-transport.md)。
原始 socket 与双栈单播转发已接通，范围分别见 [RAW 契约](raw-ip.md)及[转发契约](ip-forwarding.md)，仍待系统验收。
已有地址查询、静态路由 UDP、ping 回复及邻居解析/探测不代表完整双栈主机网络已交付；跨服务、来宾 ABI 与互通仍待统一验收。
