# 双栈转发契约

本文件拥有原生 NET 的 IPv4/IPv6 单播和静态组播跨接口执行、等待和错误返回。路由来源及选路见[RIB 与执行 FIB](ipc-network.md#rib-候选目录)。
当前已接通生产 NIC 接收、同域 FIB 选择、出口邻居解析及实际 TX；尚未完成来宾多网卡和成熟路由器互通验收，不声明完整双栈路由系统已交付。

## 入口与职责

- `inet::ingress` 消费一个接收批次，对发往本接口单播 MAC 的已分类 IPv4 做唯一 FIB 目的分类。本机、广播、多播仍交本机入口，其他目的交 `inet::forward`。
  ARP 地址不能伪装成待转发 IPv4；VLAN 与回环不进入物理转发入口。RX 仍由原 token 消费和归还，AF_PACKET 在同一次消费中观察原始帧。
- 目的分类只属于同一帧、同一 NET guard，直接交给本机 ingress 使用，避免为新增入口重复查询本机收包的目的；不是另一份长期路由缓存。
- IPv6 批解析仅确认固定头和数据报长度；发往本接口单播 MAC 的非本机单播进入转发，普通本机/ND/组播仍走原入口。低于 IPv6 最小 MTU 的接口不接收 IPv6。
- RoutingTable/FIB 仍是唯一出口选择；按当前源/目的选择加权成员，不缓存跨事务路由、邻接或设备身份。下一跳/接口变化后的重试重新查询当前 FIB。
- 双栈选路和转发按 ifindex 二分定位实际出口，借用域内按编号递增的设备表。有 RX 借用时直接使用入接口字段，按编号定位其余接口。
  带权组每次累计权重时按出口读取一次设备资格，链路状态和地址仍来自同一域。此路径无新分配或锁。整机对照少量物理接口及大量 VLAN 网关的选路 CPU 时间和吞吐。
- 双栈 FIB 在候选前缀键不变时共享 Poptrie 布局。记录区间与候选独立，撤销或退休不改变另一根的结果。有序输入在构建时合并相邻同前缀记录。
  根持有一次引用，查找只借用。整机分别测量前缀不变和前缀变化时的配置时间、内存峰值及转发吞吐。[Poptrie 论文](https://conferences.sigcomm.org/sigcomm/2015/pdf/papers/p57.pdf)
- IPv4 单播复用本次准入的本地表及主表结果，策略表仍按优先级查询。DNAT 改写目的后、重组及续发重新选路。无逐包分配。整机对比选路耗时。[Linux IPv4 接收选路](https://github.com/torvalds/linux/blob/v6.12/net/ipv4/route.c)
- 物理网卡双栈单播从原 RX 借用取得队列号。等宽或更窄的出口保留原映射。出口较宽时，原队列号限定 TX 子集，使用同一地址散列及可直接定位的 TCP/UDP 端口选择队列。
  已分片或带不透明扩展头的包仅以地址散列。同一原包在分片、邻居等待或背压重试时保持选择。设备队列数由原发送预留读取，无新锁、分配或查询 RPC。
  整机验收分别测量等宽和不同队列数的接口间吞吐、队列分布及重排。[Linux XPS](https://www.kernel.org/doc/html/v6.12/networking/scaling.html#xps-transmit-packet-steering)
- 转发帧无需预留并取消入接口的槽。本机回复在原队列按需预留，未取得槽时只计发送失败，不镜像为发出报文。二层交换提交标签帧前核对实际槽容量。
  现有多队列 UDP/ARP 用例覆盖无回复和实际回复，整机验收测量省去的发送队列锁与票据操作对 CPU 和吞吐的影响。
- 每个网卡队列在域锁外领取一批 RX，验证共享环记录并检查直接承载的 IPv4/IPv6 头。IPv4 转发和 IPv6 物理入口复用原帧的 IP 边界，仍按原入口检查链路准入、IPv4 头校验和及 IPv6 选项。
  接收借用的会话拥有映射与归还队列，发送映射和发送 FIFO 由外层队列独占。会话在装配时分配一次，整机对照队列内存、跨核访存与吞吐。
  独立队列预查 IPv4 首部校验和、IPv6 逐跳选项和需要的分片头，结论随原帧保留。域在原准入点采用结果，按实际策略限速回复。每帧增加八字节，整机测量固定头、扩展头及畸形报文。
  RX 与 TX 使用各自的客户端锁。域从上批之后开始按字查找 RX 就绪位，只领取选中的一批。位随同队列暂存批次的空与非空转换而更新，票据和失败清理不变。
  整机验收对照位图查找、跨核发表、RX 锁和域锁的开销，测量稀疏与饱和转发及纯二层交换的吞吐与延迟。[Linux 位图查找](https://github.com/torvalds/linux/blob/v6.12/lib/find_bit.c#L40-L65)
- 网卡队列线程可为双栈原始目的查找最窄结构前缀。一个接收批次最多尝试一次借用当前域的布局，临界区只增加布局引用，遍历在域锁和布局发布锁外执行。
  队列与域在不同线程时，IPv4 也预查原始源前缀，供源地址准入及本机反向选路使用。域线程按原始地址和布局身份核对提示，从当前 FIB 读取活动前缀与记录区间。
  撤回、重建和回滚遵守当前 FIB，重组、地址改写及待发重试按实际地址查找。源前缀增加每帧八字节暂存量，单独对照队列查找和域内复用成本。
  整机分别测量队列线程与域线程的 CPU 时间、竞争、内存和单域吞吐，覆盖本机接收、无状态规则及命中记录超出随帧容量的链。[VPP 按收包队列分派](https://docs.fd.io/vpp/25.10/developer/corearchitecture/multi_thread.html)
- 独立 RX 线程预判双栈无状态地址及 TCP/UDP 端口规则，最多记录三次命中。域线程核对版本和入接口，端口裁决还须通过传输层校验，再结算计数。其余报文仍执行同一规则。整机对比有无端口规则时的吞吐和域锁占用。
- 当前防火墙或已有 NAT 连接需要传输层事实时，队列线程对硬件未验证的直接 TCP、UDP 和 ICMP 报文执行软件校验，计算在 RX 锁与域锁之外。分片和 IPv6 扩展链仍在协议入口按完整语义处理。
  转发只在需要传输层事实时消费结果，校验失败和原先同步检查得到同一分类。配置切换期间未预查的帧按当前策略检查，本机接收保留原硬件校验标志。整机对照开关硬件卸载及有无传输层规则时的 RX、域锁时长、吞吐和 CPU 用量。
- 两族单播转发默认启用，面向路由器用途；仅同一域的实际合格接口可用。默认参考固定 RouterOS 的 IPv4/IPv6 Settings，不据此声明兼容其全部运行参数。
  独立开关沿同一[原子配置事务](router-configuration.md#双栈转发开关)生效；IPv6 NA 的 Router 位来自当前执行策略，不复制到地址 owner。

## 转发专用 CPU

- `forwarding_cpus` 属于根配置，适用于全部路由域。值为升序的逻辑 CPU 编号，空列表启用共享调度。专用 CPU 各有一个受隔离的协议线程，固定分区按线程数量取余分配，路由域的状态保持原处。
- 根服务只给 netstack 交付 `system::SCHEDULE` 资源。服务请求和网卡中断仍沿各自的调度与路由机制。切换时等待当前批次结束，再把线程的新增、替换和释放一并交给内核。确认后发布新派发范围并重发唤醒。失败时取消并回收本次准备的线程。
- 根 RIB 配置及根 NET 安装能力的操作 15 使用 u32 版本 1、u64 逻辑 CPU 掩码。只接受无句柄请求，成功回复无正文和句柄。具名域和普通网络能力不能调整全局放置。
- router-config 在持久提交前应用调度，内核只在允许普通任务保留共享 CPU 并完成旧上下文迁移后确认。保存失败时恢复上一份持久配置对应的调度，结果不明时用原配置事件循环重试。
- 执行服务重连后从持久配置重放，等待期间配置状态显示 Applying。协议线程退出时由内核归还 CPU。
  参考 [Linux CPU 分区](https://docs.kernel.org/6.12/admin-guide/cgroup-v2.html#cpuset)与 [VPP 工作线程放置](https://docs.fd.io/vpp/25.10/developer/corearchitecture/multi_thread.html)。
- 专核配置只增加冷路径 RPC 和调度准入，无逐包工作。整机测量迁移耗时、持续转发吞吐、共享任务延迟及空闲 CPU。[桌面入口](../../user/programs/network-manager/README.md#转发专用-cpu)

## 转发唤醒与共享 CPU 调度

- 共享调度按逻辑 CPU 数划分执行分区。路由域选择固定分区，分区首次承载域或网卡队列时启动线程。不同分区可并行推进，域内 FIB、连接和邻居仍由原域持有。
  网卡用户态 IRQ、收发服务、NET 设备通知和转发线程在启动前使用同一公平权重。共享 CPU 上按 nice +5 等效权重运行，空闲时继续等待事件。
  权重设置只在线程创建时执行。整机分别测量共享与专用 CPU 配置下的输入延迟、首包时延和吞吐。[Linux nice 权重](https://docs.kernel.org/6.12/scheduler/sched-nice-design.html)
- 安装时先分散同一网卡的队列，再按线程及分区的登记量分配。单队列网卡也参与。批次调度与并行判断共用同一登记。[VPP 队列放置](https://docs.fd.io/vpp/25.10/developer/corearchitecture/multi_thread.html#interface-placement-in-multi-thread-setup)
  支持队列亲和的设备在安装时按分区设置中断目标。对照同域多块单队列网卡、RSS 网卡及 CPU 布局切换，测量中断分布、吞吐和桌面延迟。[Linux VirtIO-net 亲和分配](https://github.com/torvalds/linux/blob/v6.12/drivers/net/virtio_net.c#L3427-L3480)
- 队列数受设备、可用逻辑 CPU 和 RSS 表上限约束。VirtIO 自动分流可直接使用设备公布的多个队列。未建立反向流时，自动分流的行为由设备决定。
  [VirtIO 1.4 §5.1.9.5.6](https://docs.oasis-open.org/virtio/virtio/v1.4/cs01/virtio-v1.4-cs01.html)
  多队列吞吐验收使用实际提供多个队列的隔离后端。常规 QEMU 用户态网络只提供一对队列，打开 `mq` 或 `rss` 不会改变该数量。
  [QEMU 队列数量](https://github.com/qemu/qemu/blob/e545d8bb9d63e9dd61542b88463183314cff9482/hw/net/virtio-net.c#L3661-L3674)
- 队列线程在域锁外领取和归还 RX、发布 TX 并回收完成，每轮最多领取及归还各四批 RX、发布四批 TX 并回收 64 项 TX。容量跃迁与收发故障按网卡合并再通知域，空闲读取不扫描队列。
  单纯发布 TX 或归还 RX 槽只推进队列。若域在同一线程，直接登记协议工作。布局变更重新登记两类工作，应用与链路变化仍直接通知域。
  归还 FIFO 按设备槽数预留，每槽只登记一次。空 FIFO 首次登记时唤醒，VirtIO 按已协商的事件索引或标准抑制位合并通知。整机测量通知次数、RX 周转和吞吐。[VirtIO 1.4 §2.7](https://docs.oasis-open.org/virtio/virtio/v1.4/cs01/virtio-v1.4-cs01.html)
  发送描述符与可选的只读载荷持有按提交顺序进入预留 FIFO。待发和已发布槽均占用发送容量，只有匹配的完成可回收。
  双栈物理单播可由独立出口线程复制不变的载荷后缀。NAT 用同一字段遍历确定改写前缀。抓包、重组及重新分片的 IPv4 在协议线程完成编码。最后一个读者释放后归还 RX 槽。
  跨线程载荷增加一次 RX 票据持有和 FIFO 元数据。整机对比普通转发与双栈 NAT 的吞吐、域线程占用和 RX 槽周转，覆盖最小帧、常见 MTU 和出口背压。
  每队列暂存一批，域领取最后一条后重查共享环以续填。域内协议仍归原所有者。整机测量增加队列前后的域轮询耗时、吞吐与发送背压。
  接口提交时由租约一次发布入接口序号，队列每批读取一次。租约退休时撤销登记，已领取的工作只访问旧会话。接口发表后补发唤醒以消费安装期间已准备的批次。
  待办 FIFO 每队列至多一项，安装时预留容量，事件合并不分配。布局切换在批次边界生效，已有队列任务留在原 FIFO，由新线程承接。
- 活动时同时使用包数预算和 2 ms 软时间预算。在队列任务、路由域事务及域内接收批次的边界检查时间。一个域事务至少可处理一批有数据的接口，随后停止领取新批次并完成本轮控制、发送和通知。
  时间预算耗尽后从下一接口继续，包数预算耗尽时沿接口窗口轮转。在遍历尾部保留前面未排空接口的续调度。转发线程释放锁后让出 CPU，并使用低于普通任务的公平权重。
  已收到的通知和已到期的计时器沿用当前预算，即使前一批恰好清空也要在截止时让出 CPU。让出后或进入空闲等待时重置预算。
  本机 TCP、UDP 与 RAW 各保证一次发送尝试，再按同一截止轮转，每八次采样时钟。TCP 输出按身份移除已结束的连接。整机测量转发与本机发送混流的吞吐、持锁时间和桌面延迟。
- 协议积压清空时在分区协调锁外读取实际协议的最早截止。单纯队列活动沿用已登记的截止，计时器到期时即使队列积压也继续推进协议。
  跨域扫描分批让出 CPU，遇到新协议活动或已到期的计时器立即回到工作循环。整机分别测量纯队列事件和需要域推进的事件数量与 CPU 时间。
  有设备背压且只能由可写事件继续的工作不登记时钟。TCP 的退出和纯时间状态独立于路径和发送背压。
- 双栈转发待发报文按地址族存入两棵 AVL，共用原容量限制。各族按唤醒代、重试截止和入队顺序排列，取队首确定下一项，重排复用原节点。
  邻居进展、设备可写或路由变化只推进一次唤醒代，早于该次通知的报文立即可重试。尝试后仍阻塞的报文进入当前代，等待下次通知或自己的截止。
  收包前的三层重试预留一批新包的发送额度，收包后可使用剩余额度。每八个重试数据报检查同一软截止，已有重试进展的轮次到期后续调度。
  发送时仍查询当前出口、核对连接身份并延续原分片游标。测试分别比较满队列尚未到期和批量唤醒的开销，整机关注背压时域锁占用和桌面响应。[Linux 按截止排序](https://docs.kernel.org/timers/hrtimers.html#hrtimer-subsystem-implementation-details)
- 目录或协议 guard 竞争导致跳过的工作在 1 ms 后补做。无活跃截止且没有争用时等待设备或应用通知。截止只在静止前捕获，域和协议 owner 不保存计时副本。
- 队列、协议待办和等待位共用一个原子字。活动时直接消费，空闲才等待 futex，首个请求唤醒。迟到唤醒复查待办和原截止。[Rust parker](https://raw.githubusercontent.com/rust-lang/rust/1.90.0/library/std/src/sys/sync/thread_parking/futex.rs)
  按持续小包、突发及空闲对照待办交接的 syscall、NET CPU 和输入延迟。吞吐分别测量多域与单域多连接。批次预算参考 [Linux NAPI](https://docs.kernel.org/6.12/networking/napi.html)。

## 隔离的多队列吞吐验收

使用独立的 LiteOS 开发工作区和镜像。在支持多队列 TAP 的 Linux 测试机上，为两个端点各建独立网络命名空间和专用二层网段。网桥不接入现有业务接口。

```sh
for side in a b; do
    sudo ip netns add "liteos-peer-$side"
    sudo ip tuntap add dev "liteos-tap-$side" mode tap multi_queue user "$(id -u)"
    sudo ip link add "liteos-br-$side" type bridge
    sudo ip link add "liteos-veth-$side" type veth peer name eth0 netns "liteos-peer-$side"
    sudo ip link set "liteos-tap-$side" master "liteos-br-$side" up
    sudo ip link set "liteos-veth-$side" master "liteos-br-$side" up
    sudo ip link set "liteos-br-$side" up
    sudo ip -n "liteos-peer-$side" link set lo up
    sudo ip -n "liteos-peer-$side" link set eth0 up
done
```

把以下 QEMU 配置保存为 `.local/router-test.conf`。[QEMU `-readconfig` 与 TAP](https://www.qemu.org/docs/master/system/invocation.html)

```ini
[netdev "side-a"]
  type = "tap"
  ifname = "liteos-tap-a"
  script = "no"
  downscript = "no"
  queues = "4"
[device "side-a-nic"]
  driver = "virtio-net-pci"
  netdev = "side-a"
  mac = "52:54:00:01:00:01"
  mq = "on"
  rss = "on"
[netdev "side-b"]
  type = "tap"
  ifname = "liteos-tap-b"
  script = "no"
  downscript = "no"
  queues = "4"
[device "side-b-nic"]
  driver = "virtio-net-pci"
  netdev = "side-b"
  mac = "52:54:00:01:00:02"
  mq = "on"
  rss = "on"
```

以 `make run ACCEL=tcg QEMU_SMP=4 QEMU_DEVICE_CONFIG="$PWD/.local/router-test.conf"` 启动。按 MAC 将两块网卡绑定到同一路由域，分别配置 `192.0.2.1/24`、`198.51.100.1/24` 和 `2001:db8:1::1/64`、`2001:db8:2::1/64`。
在两侧配置地址和到对端的路由，再分别验证双栈可达性。

```sh
sudo ip -n liteos-peer-a address add 192.0.2.2/24 dev eth0
sudo ip -n liteos-peer-a -6 address add 2001:db8:1::2/64 dev eth0
sudo ip -n liteos-peer-a route add 198.51.100.0/24 via 192.0.2.1
sudo ip -n liteos-peer-a -6 route add 2001:db8:2::/64 via 2001:db8:1::1
sudo ip -n liteos-peer-b address add 198.51.100.2/24 dev eth0
sudo ip -n liteos-peer-b -6 address add 2001:db8:2::2/64 dev eth0
sudo ip -n liteos-peer-b route add 192.0.2.0/24 via 198.51.100.1
sudo ip -n liteos-peer-b -6 route add 2001:db8:1::/64 via 2001:db8:2::1
```

在 `liteos-peer-b` 运行 `iperf3 -s`，在 `liteos-peer-a` 用 `iperf3 -P 8 -c` 分别连接 IPv4 和 IPv6 对端。
固定来宾 CPU 数、网卡配置和负载，依次改变 LiteOS 分配给转发的 CPU。记录实际队列配置、各次吞吐、丢包率与 NET CPU 时间。共享 CPU 的桌面响应另按系统验收场景采样。
结束后停止测速与来宾，删除这两套命名空间、TAP 和网桥。

## IPv4 执行与报文语义

1. 接收先验证完整 IPv4 头与 checksum，排除非法源、回环/多播/保留源及 FIB 已知本机/广播源；不以 transport checksum 作为路由器的转发前提。
   按路由选择实际出口并解析邻居，同一发送尝试的分片共用出口。丢弃不回错误，禁止与不可达分别报告。TTL 到期返回 Time Exceeded，DF 超出 MTU 返回 Fragmentation Needed 及 MTU。
2. 正常转发不分配：原包借用 RX，头最多 60 字节的栈窗口；TTL 减一，保留 DSCP/ECN、Identification、上层 payload、选项与分片语义。
   无选项、地址保持原样且符合出口 MTU 时，已校验的固定头按 RFC 1624 增量更新 TTL 校验和。由同一个出口提交入口发送，背压重试仍以原包计算。
   固定头生成单独对比完整重算，整机以小包混流测量域内 CPU 时间和吞吐。[RFC 1624](https://www.rfc-editor.org/rfc/rfc1624.html#section-3)
   超 MTU 且允许分片时按八字节边界切分，保留原分片偏移与 MF；非首片将非 copied 选项改为 NOP，保持头长和 copied 选项，与 Linux v6.12 ip_options_fragment 的处理一致。
3. Record Route 写实际出口地址；Timestamp 支持时间、地址加时间及指定地址，非 UTC 计时显式置高位，满选项递增 overflow，溢出/非法指针返回 Parameter Problem。
   源路由默认拒绝并返回 Source Route Failed；未知已通过 framing 的选项按原值保留，不擅自执行其策略。
4. IPv4 发送按网关族借出口的 ARP 或 ND，IPv6 网关只决定 Ethernet 目的 MAC，EtherType 与报文仍为 IPv4。出帧共用实际 reservation/commit。
   主机与转发共用 packet-wire 的分片窗口，完整 options/载荷仍借用原包，不经丢失 options 的 Repr 重编码；真实提交失败不能提前推进游标。
   IPv6-only 出口的本机 IPv4 流量可使用同域其他启用接口的合格 IPv4 地址，仍优先采用绑定源或首选源；没有源时报地址不可用。

## IPv6 执行与报文语义

1. Ipv6Datagram 只提供完整固定头/长度；本机 Ipv6Packet 另校验完整扩展链，ICMP 引用不冒充完整包。转发只处理首个逐跳头，Destination/Routing/AH/Fragment 及不认识的上层保持不透明。
   Hop-by-Hop 的未知选项按高两位决定跳过、丢弃或返回 Parameter Problem；错误指针来自唯一格式库。无连接状态规则时逐片执行无状态转发。
   启用连接状态规则时，分片按[分片流量过滤](#分片流量过滤)进行检查。
2. 全局目的按原始源/目的选择当前 IPv6 FIB 和加权成员；链路目的限定接收 zone，带链路源/目的的报文不得跨接口，超范围返回 Destination Unreachable code 2。
   源为未指定、组播、回环、mapped 或当前本机地址时拒绝；禁止路由返回管理员拒绝，丢弃路由不反射错误，无可用路由返回不可达。
3. Hop Limit 仅在转发时减一；到期返回 Time Exceeded。出口超实际 MTU 返回 Packet Too Big 与 MTU；路由器不分片，原始片头、标识、流标签、Traffic Class 与 payload 保持。
4. ND/NUD 只归实际出口的地址 owner。正常解析命中直接写最终 DMA：Ethernet 写完整二层帧，IP-medium 只写 IP；转发明确关闭 TX checksum 重算。
   解析创建了立即工作时让出并回投，不能等待下一次外部 timer；真正 ND 等待及 TX 背压沿原有界队列，恢复后重新选路且不再次递减 Hop Limit。
   备用路径实际提交后，可按现有节奏在原首选网关所属接口登记复探。TX 拒绝或背压时不登记。
5. 错误最多为 IPv6 最小 MTU 1280 字节，引用修改前原包，源取反向当前出口的合格地址。错误与 Redirect、无法确定上层、非唯一源不反射新错误；资源不足丢弃，不伪报远端不可达。

## 静态组播转发

- 配置根对象中的 `multicast_routes` 按组和可选源设置一个入接口和最多 32 个出口，共最多 4096 项。接口使用物理配置名或 VLAN 网关名，网桥成员使用其所属 VLAN 的网关身份。
- 精确源规则优先，选中后检查实际入接口。入接口失联或不匹配时该规则不转发。链路范围组和链路本地源禁止跨接口，SSM 地址必须配置具体源。
  [RFC 5771](https://www.rfc-editor.org/rfc/rfc5771.html#section-4)、[RFC 4291](https://www.rfc-editor.org/rfc/rfc4291.html#section-2.7)、[RFC 7346](https://www.rfc-editor.org/rfc/rfc7346.html#section-2)、[RFC 4607](https://www.rfc-editor.org/rfc/rfc4607.html)
- 静态复制前检查当前预路由规则。组播使用实际源、组、入接口及可判定的端口，无连接跟踪或地址转换。启用端口规则时，不能安全分类的组播分片停止转发。本机订阅独立接收原包。
- 复制每份报文时跳数减一。IPv4 沿共享分片逻辑处理小 MTU，IPv6 超出出口 MTU 时跳过该出口，按最小失败 MTU 报告 Packet Too Big。局部背压不阻塞其他出口。[RFC 4443 §3.2](https://www.rfc-editor.org/rfc/rfc4443.html#section-3.2)
- 正文版本 1 以 u32 版本及项数开头，按组和可选源排序。每项为长度前缀地址、u8 源存在位及可选地址、u32 入接口、u32 出口数及升序 u32 出口。地址长度为 4 或 16 字节，长度为 u32。
  缺席的入口为零，缺席的出口不编码。NET 校验候选接口，随后与网桥、接口和防火墙同批交换。撤销直接恢复前像。
- 报文处理复用原 RX 和出口预约，无逐包表分配或额外锁。表为空时跳过组播分类。每帧最多两次二分选规则，每个出口只复制一次载荷。多个出口共用转发预算，耗尽后丢弃剩余副本。
  组播基准测量单出口及多出口吞吐、与单播共享预算时的延迟。静态组播不协商 PIM 或代理成员关系，上联须把流量送达配置的入接口。

## 策略选路

桌面通过[路由设置](../../user/programs/network-manager/README.md#备选表与选路规则)在同一次审阅中提交备选表、静态路由和选路规则。表仍有规则引用时，桌面要求先处理相关规则再删除表。
使用现有 `ipconfig /export` 导出完整配置，在根级添加 `policy_routing`，然后通过同一 `ipconfig /import` 提交。
`tables` 每项包含表号 `id` 及采用[静态路由格式](router-configuration.md#静态路由配置)的 `routes`；表号非零且不得占用 253–255。
`rules` 每项包含 `priority`、`source`、`prefix_length` 和目标 `table`。缺省 `origin` 为 `forwarded`，可用 `ingress` 引用 `interfaces` 中的配置名。
`origin: "local"` 匹配本机单播，不填 `ingress`。任意源用 `0.0.0.0` 或 `::` 加 `prefix_length: 0`。本机规则在 Linux 规则列表显示为 `iif lo`。
规则优先级在 1–32765 内全局唯一，数字越小越先尝试。源网段、入接口及标记条件都须匹配。表无可用路由时继续，显式丢弃或拒绝时结束。
系统先处理本机地址，规则均未命中时使用主表。可用可选 u32 字段 mark 和 mark_mask 匹配报文标记。指定标记并省略掩码时匹配全部位，
包括显式指定的零。掩码必须非零，标记在掩码以外的位必须为零。两个字段均省略时匹配任意标记。掩码比较对照 [Linux v6.12](https://github.com/torvalds/linux/blob/v6.12/net/core/fib_rules.c#L244)。

本机应用通过 SO_MARK 设置标记。TCP 发送采用当前连接的标记，UDP 和 RAW 已入队的数据报保留提交时的标记。跨接口流量可在[预路由链](#预路由规则)中设置标记。

应用提供源地址时直接用该源匹配规则。应用未指定源时，先沿无源限制的路径确定源，再用确定的源完成选路，两次查询使用相同标记。
本机发送和 `ip route get` 共用这一选择，改变出口不重新改选源。备选表的拒绝动作在显式绑定出口时仍生效。
两段查询参考 [Linux v6.12 IPv4 connect](https://github.com/torvalds/linux/blob/v6.12/include/net/route.h#L295)，本机流量使用回环身份对照 [Linux IPv6 输出](https://github.com/torvalds/linux/blob/v6.12/net/ipv6/route.c#L2464)。

用 `ip route get 203.0.113.9 from 192.168.50.10 iif eth1` 查询该流量的表、出口和网关。IPv6 使用 `ip -6 route get`。
用 `ip rule show` 与 `ip -6 rule show` 枚举当前规则。出厂和同步后的开发镜像均提供 BusyBox `ip`，入接口显示实际设备名。
带标记的路径查询使用支持 `ip route get … mark …` 的 iproute2 或直接提交 RTA_MARK，镜像内 BusyBox 的路径查询不接受 mark 参数。
点查复用实时选表、下一跳和入接口范围检查；转发停用时报告不可达，本机交付仍可查询。两族输入方向对照 [Linux IPv4](https://github.com/torvalds/linux/blob/v6.12/net/ipv4/route.c#L3075) 和 [IPv6](https://github.com/torvalds/linux/blob/v6.12/net/ipv6/route.c#L5723)。

- 持久配置、校验和设备匹配由 router-config 处理。设备缺席时绑定该入接口的规则暂退，重连按同一配置重投影；保存、备份与恢复使用原配置树。
- RIB 用同一求解器独立求解各表。直连观测只为递归下一跳提供证明，显式备选路由可覆盖同前缀的直连观测；各族同一执行组字典内的组身份不冲突。
- RIB 意图段为 `policy_routing::Tables` v2。u32 版本、规则段长度、规则段、u32 表数，随后按表号依次为 u32 表号及带 u32 长度的两族声明。
  执行侧复用同一规则段。u32 版本后为 40 字节规则，依次是 u32 优先级/入接口/表号、u8 前缀长度/地址族、两字节零、16 字节源地址（IPv4 补零）及 u32 标记和掩码。
- INET 的 SET_OPTION kind 26 在通用标量槽保留标记的 32 位，选项字节为零，查询编号为 34。授权在 Linux socket 边界检查，标记只由实际端点持有。
- NET 在同一写租约发布与撤销两族 FIB 和规则。规则按方向分段并由收包队列共享。独立收包线程可按原始源、入接口和标记查首条匹配规则。域线程只复用同一版本及同一条件的结果，按当前 FIB 继续尝试各表。
  每帧多预留 16 字节提示空间，无逐包分配。重组和重试按当前规则查表。整机测量规则扫描、提示失效和多表未命中的单播 pps、IMIX 及域锁时间。
- 固定行为参考 [Linux v6.12 规则查询](https://github.com/torvalds/linux/blob/v6.12/net/core/fib_rules.c#L275)。宿主网卡夹具覆盖配置导入正文、表未命中、规则命中、拒绝和撤销后两族实际出帧。

## 预路由规则

桌面[防火墙与 NAT](../../user/programs/network-manager/README.md#防火墙与-nat)编辑同一有序规则链、地址集与已有连接策略。审阅时由配置服务核对规则引用、链间跳转以及转换约束。
配置树的 firewall.prerouting 是有序入口链，使用同一 `ipconfig /import` 提交、保存和恢复。规则可同时匹配入接口、源网段、目的网段或目的地址集、目的服务和连接状态。
入接口引用 interfaces 中的稳定配置名，缺省匹配所有接口。可选的 source 使用 network 和 length 指定规范网段，直接指定的源和目的网段须同族。省略源或目的条件时，该地址不参与匹配。
set_mark 设置 u32 标记并继续。源网段和目的网段同时匹配时仍按规则声明顺序执行。源地址匹配语义参考 [nftables IP header expressions](https://netfilter.org/projects/nftables/manpage.html#IP_HEADER_EXPRESSION)。
可选的 transport 指定 TCP 或 UDP，并可指定非零 destination_port。服务条件匹配校验通过的外层传输头。ICMP 错误可由关联状态规则匹配。
accept 放行至选路，drop 静默丢弃，destination_nat、source_nat、masquerade 分别选择[固定目的转换](#固定目的地址转换)、[固定源转换](#固定源地址转换)和[自动源转换](#自动源地址转换)。这些动作均结束本次预路由。
入口链没有裁决时放行，未赋标时标记为零。
物理单播发往接口本机地址时，只有选中目的转换或已有映射的连接才进入转发裁决。其他本机服务继续按原接收规则交付。路径点查使用显式 RTA_MARK 模拟选路。

- router-config 解析设备引用。设备缺席时保留规则的声明位置，设备重连后按保存的配置重投影。RIB 只在原配置事务中转交链，链本身不改变候选路由。
- 正文以五个 u32 开头，依次为版本 14、规则数、地址集数、具名子链数和已有连接策略（0 重新判断，1 保留）。随后是每条 85 字节的规则，按入口链和按名排序的子链排列，链内保留声明顺序。
  规则字段为 u32 入接口、u32 动作参数、u8 族、u8 前缀长度、u8 动作、u8 连接状态及 16 字节目的字段。动作编号依次为 0 赋标、1 放行、2 丢弃、3 跳转、4 返回、5 固定目的转换、6 固定源转换、7 自动源转换。
  连接状态为 0 任意、1 新流、2 已建立、3 关联错误。之后 18 字节为源网段（u8 族、u8 长度、16 字节地址）。全零匹配任意源，IPv4 地址后补零。
  随后两个 18 字节字段按同一网段布局编码转换目标，固定地址的长度为地址位宽。第一个存放动作 5 或 6 的固定地址，其余动作全零。
  第二个只用于动作 5 的附加源转换。全零表示无，地址族 255 且剩余字节全零表示自动转换，其他值编码固定地址。
  固定转换端口写在 u32 参数的低 16 位，附加固定源端口写在高 16 位，零沿用原端口。自动源转换没有端口参数。
  末尾为 u8 传输协议（0 任意、6 TCP、17 UDP）和 u16 目的端口（0 任意）。计数页及其游标使用版本 9。
  入接口零匹配任意接口，1 表示设备缺席。动作参数随动作保存标记、非零子链下标、转换端口或零。目的地址族为 4 或 6 时匹配网段，IPv4 后补零；族为零时目的字段前四字节为集合下标。
  族为 255 匹配两族任意目的地址。集合和任意目的地址的前缀长度及未使用的字节均为零。
  规则后依次是 u32 入口规则数、各子链的 u32 名称长度与 UTF-8 名称和 u32 规则数、按名排序的地址集。入口链下标为零，子链从 1 起，集合从 0 起。
  每集为 u32 名称长度、UTF-8 名称、u32 成员数及成员记录。成员为 u8 地址族、u8 前缀长度及 16 字节地址。IPv4 后补零。所有整数为小端。
  未被引用的集合只保留在持久配置。NET 在发布前编译并验证跳转图。激活与同批选表规则共享发布点，撤销交换回前像。
- 放行的待发报文保留入站标记与分片进度。重试使用当前路由表，沿用原入站裁决。规则替换影响新收的报文。标记不写入报文头或 ICMP 引用。
- benchmark 决策。先查报文命中的源前缀及其祖先。每个匹配源组再查通用和指定接口的目的索引，启用状态匹配时至多再查两组。合并直接前缀和地址集候选，按全链顺序取最早的控制动作。
  服务匹配只查任意协议、实际协议和实际目的端口三类索引。纯服务过滤只解析报文，不建立连接项。未配置服务条件时保留原候选数量。
  只枚举该裁决之前的赋标，同时完成计数和最终标记选择。
  无可达赋标时跳过祖先遍历，分类不增加堆分配、新锁或全链扫描。
  入站分类开销纳入双栈 pps 和 IMIX，比较源不限、不同源网段并存和嵌套源前缀。宿主用例覆盖同一接口区分来源、双族重叠规则、地址集、实际出口和撤销。

### 调用防火墙子链

`firewall.chains` 按名称声明子链。`jump` 保存下一条规则的位置并进入目标链。显式 `return` 或读到子链末尾时，从调用者的下一条规则继续，已设置的标记继续生效。
任一子链放行或丢弃都会结束本次预路由。入口链返回时采用默认放行。行为对照 [Linux v6.12 nftables](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_tables_core.c#L286-L325)。

- 持久配置拒绝未知目标、循环和超过 16 层的调用。执行侧同样验证所有链的跳转图。准备失败时保留已生效配置，编译结果随现有事务发布或撤销。
- benchmark 决策。所有链共用现有前缀及地址集分类语义。仅在实际跳转时初始化固定返回栈，续评以保存的规则位置定位匹配项。报文路径不新增堆分配和锁。
  入口无法调用的子链保留规则描述，不建立匹配索引或启用连接跟踪。
  链嵌套、共享子链重复调用及返回后续评的成本随双栈 pps 和 IMIX 测量。

### 复用目的地址集

在 `firewall.address_sets` 声明具名的 IPv4、IPv6 网段列表。规则使用 `destination_set` 引用，或用 `destination` 和 `prefix_length` 直接指定目的网段。
网段必须规范。未知集合、重复配置名和混用两种目的条件均拒绝提交。空集合匹配不到报文，覆盖或重复成员只使命中的规则执行一次。具名集合语义参考 [nftables SETS](https://netfilter.org/projects/nftables/manpage.html#SETS)。

- 规则和集合成员在同一次执行事务发布。只改成员时，NET 复用原不可变规则索引，替换双栈集合索引并保留计数；撤销恢复旧成员。未改有效成员时保留当前版本。
- benchmark 决策。每个地址族共用一棵集合前缀索引，构建时去掉同一集合的重复和覆盖成员。报文只查目的地址所属集合，再和直接网段匹配一起选最早裁决。
  只有匹配到的集合查询规则组，命中的赋标按同一个截止顺序计数。地址集匹配与成员换版开销纳入规则规模、pps 和 IMIX 验收。

### 查询防火墙命中次数

`ipconfig /firewall` 显示入口及子链、链内序号、规则、报文数和 IP 字节数，包括设备缺席及从未命中的规则。每次实际执行的赋标、跳转、返回及裁决分别计数。
计数采用该次分类的 IP 长度，出口背压重试和分片发送沿用原裁决。计数语义参考 [Linux v6.12 nftables](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nft_counter.c#L17-L47)。

- 规则链独占计数。替换规则定义后从零计数，撤销恢复旧链及其计数。仅修改地址集成员时，同一条规则继续累计。两个 u64 值饱和增长，由原 NET guard 串行更新。
  保留旧规则的连接仍按旧规则判断，命中不计入当前版本。
- 原生安装和 RIB 配置能力使用操作码 12，收发长度前缀内联正文。Linux 设置端点使用操作码 23，沿用[授权管理信封](router-configuration.md#原生配置审阅与整份替换)。
  游标是 u32 版本 9、u64 链版本、u32 已读规则数。版本之外两个字段同时为零读取首页。规则或集合换版后重新读取首页。
  回复是 u32 版本 9、u64 链版本、u32 后续起点（零为结束）及 u8 记录数，再跟最多 64 条记录。每条为 85 字节规则、u64 报文数、u64 字节数和从一开始的 u32 链内序号。
  随后是所属子链、目的集合和跳转目标的三个名称字段，各以 u8 长度及 UTF-8 字节编码。缺席字段长度为零。整数均为小端。
- 每页在同一 NET guard 复制后再编码，页间计数可以增长。查询不清零计数。计数写入及多规则匹配的增量开销随双栈 pps 和 IMIX 一起测量。

#### 桌面计数订阅

网关通过同一查询每秒采样一页，先发完整规则页，之后只推送变化的绝对计数。规则换版时续页回到首页，发送新快照后才更新计数。
采样采用 [gNMI STREAM SAMPLE](https://github.com/openconfig/reference/blob/master/rpc/gnmi/gnmi-specification.md#352-sending-telemetry-updates) 的有界采样和省略重复值模式。

- 网关操作码 `0x80000001` 接收[按域内联请求](userspace-abi.md#网络管理入口)和计数游标。回复沿用 i32 状态头。成功后 0 表示保活，1 后跟游标和规则页，2 后跟 u64 规则版本、u64 行掩码和按位序排列的 u64 报文数与字节数对。
- 订阅沿同一观察权限和会话配额。每个会话仅持有上一页采样，连续 10 秒无更新发送保活。翻页或离开后关闭旧会话，已在途采样在原查询时限内结束。
- 每页最多 64 条，空闲时 UI 只等套接字就绪，不用后台工作线程。此功能在报文路径无新增工作。并发观察的每秒采样和管理消息开销随规则规模纳入验收。

### 桌面路由观察

- 域操作码 21 与授权设置操作码 26 读取单族的生效路径。请求由 u32 版本 1、u8 地址族、u32 路由位置和 u32 成员位置组成。位置从零开始，续页使用首条未返回的路径。
- 在同一 NET guard 按实际 FIB 位置读取至多 64 条路径和一条前瞻记录，路由和组成员均可直接续读。IPv6 接口通告和委派条目沿全量查询的同一迭代器附在其后。
  共享组中过期的出口按有序接口段跳过，成员权重保持原值。路由位置随实际 FIB 变化，两页之间没有冻结视图。
- 页头是 u32 版本、u8 行数、u8 后续标志及两个 u32 续页位置。每行是位置、目的前缀、表、度量、范围、来源、类型、首选源和实际下一跳，固定 96 字节。
  `router-protocol::routing` 拥有原生路由类型，管理与全量快照共用编码。界面的来源和范围显示参照 [rtnetlink UAPI](https://github.com/torvalds/linux/blob/v6.12/include/uapi/linux/rtnetlink.h#L2256-L2343)。
- 网关操作码 `0x80000003` 接收[按域内联请求](userspace-abi.md#网络管理入口)和同一个游标，先发完整页，之后发送页头和变化位置位图及对应行。沿[有界采样会话](#桌面计数订阅)每秒采样，离页即停止观察。
- benchmark 决策。页缓冲在取锁前预留，编码在锁外完成。常驻 FIB 无新增索引，报文路径无新增工作。百万前缀下并行采样和桌面交互仍纳入整机验收。[桌面入口](../../user/programs/network-manager/README.md#路由表)

## 转发连接状态

当对应地址族有 connection_state 条件时，转发入口验证完整 TCP、UDP 或 ICMP 报文。TCP 和 UDP 按地址及端口双向匹配；Echo 按发起地址、对端地址和标识符区分流。
原方向未成功转发回包时为 new。匹配有效流的首个回包与双向转发后的两个方向均为 established。无匹配请求的 Echo Reply 无连接状态。
IPv6 链路本地地址、零端口和校验失败的传输报文无连接状态，仍可按无状态规则过滤。

可分类为 related 的错误包括 IPv4 的不可达、超时和参数错误，以及 IPv6 的不可达、Packet Too Big、超时和参数错误。
外层目的须等于引用源，引用须含足够的原 TCP、UDP 或 Echo 头以匹配同域尚有效且已转发的方向。TCP 引用还核对所见序列范围。关联错误不建立流、不刷新期限。
类型、方向及外层目的校验参考 [Linux v6.12 ICMP 跟踪](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_conntrack_proto_icmp.c#L96)。

只有实际提交出口的有效报文才建立或刷新状态。待发包沿用入站裁决，重试时仍核对它所关联的连接身份及期限。TCP 还核对握手或窗口。迟到的包不能刷新已替换的连接。
Echo 和未见回包的 UDP 流空闲 30 秒退休。已成功双向转发的 UDP 流空闲 120 秒退休。换规则后，新报文按新规则和当前有效流分类。
期限参照 [Linux v6.12 Echo](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_conntrack_proto_icmp.c#L22) 和 [UDP 默认期限](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_conntrack_proto_udp.c#L25)。

TCP 从有效的初始 SYN 开始跟踪。匹配握手序号的反向报文可使用 established。完整握手之前，仅接受符合握手阶段及当前序列边界的报文。
双向记录实际转发的序列和确认边界、协商的窗口缩放与 FIN；超出边界的报文无连接状态。合法 RST 关闭通路，半关闭期间另一方向可继续发数据。
未收到回包的 SYN 重传保留原期限。TCP 首次握手、双向握手、已建立、FIN 和 RST 空闲期限分别为 120 秒、60 秒、5 天、120 秒和 10 秒。
严格起始和窗口规则参考 [Linux v6.12 TCP 跟踪](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_conntrack_proto_tcp.c#L788) 与 [RFC 7323](https://www.rfc-editor.org/rfc/rfc7323.html#section-2.2)。

- 状态和索引归 Forwarding。连接原键和 NAT 线上键按固定执行分区存放，共用同一个域内随机密钥。一轮查找用同一次哈希选择分区并查找该键关联的索引。
  需要跟踪连接时，队列线程可为直接承载的 TCP、UDP 计算原始双向键的散列。域线程确认同域及报文语义后复用它完成查找、预留和提交。NAT 别名解析出不同的原键时计算原键散列。分片重组、ICMP 引用和重试按实际键重新计算。
  在不同执行线程上，接收队列同时检查直接承载的 TCP 头、选项及段长，并在 UDP 提示的同一空间交付 TCP 段字段。域线程只有在确认同一帧的传输校验有效后才采用这些字段。
  当物理 RX 队列与域分属不同执行线程，且同地址族没有存续的 NAT 映射时，队列可为直接承载的 UDP 尝试一次非阻塞的原键分片加锁。锁内读取连接身份、方向、回包标记和期限，或记录查无匹配，随即释放。
  每帧暂存记录携带源及目的前缀提示、域身份、键散列，以及 TCP 段字段或 UDP 分片版本、连接身份及标志和期限。UDP 提示过期、不可用或需解析 NAT 别名时，域线程查询当前表。
  UDP 插入、删除、身份或方向变化、首次回包及缩短期限都会更新分片版本。单纯延长期限时，旧提示只在原期限内有效。分片版本耗尽后停止使用提示。
  域线程按域 guard → 单个分片的顺序访问连接，释放分片锁后才更新别名或到期索引、发布状态和发送报文。队列线程只读实际分片。TCP 连接判断和 NAT 别名查找仍由域线程执行。
  线上键可以跨分区指向原键。所有分区共用一百万条容量上限；新流在发送前预留实际分区的空间、到期和连接 ID 节点。提交或退休仍在同一个域 guard 内完成。
  到期节点归原连接分区，键仍为期限与连接 ID。连接 ID 索引指向双向键。延长只更新实际期限，FIN/RST 缩短期限时复用原节点。
  域以各分区首项的最小值决定唤醒时刻，从上轮的后继分区处理积压，每轮最多 64 项，每八项检查软截止。空分区释放表容量。整机比较集中到期和多分区同时到期时的锁时长、吞吐和输入延迟。
  TCP 的双向窗口单独分配，仅 TCP 流承担该空间。候选状态和新节点均在 TX 前预备，提交前失败时直接释放。
- benchmark 决策。无传输匹配、连接状态规则、NAT 规则或存续映射时跳过传输校验与流查找。只有同一完整报文的接收证明才允许省略软件 checksum。
  启用时测量传输校验、ICMP 引用解析、双向哈希查找、插入和超时回收。分别测量 TCP 队列预查与域内消费，以及 UDP 队列查找与域内版本核对的成本。
  整机验收比较不同执行线程数量下的提示命中、回退与锁竞争，覆盖 TCP、NAT 和单线程，并计入每帧增加的 24 字节暂存内存。并发双栈 pps 与百万流内存随整机验收。

### 分片流量过滤

某地址族启用服务匹配、连接状态规则或地址转换后，系统等到该族报文收齐才进行规则判断和完整的软件传输校验。首片和后续片可乱序到达。重叠、冲突或超时的报文丢弃。
一次规则命中按一个完整 IP 报文及其长度计数。IPv6 原子分片独立判定。

- Forwarding 独占转发重组队列，复用[本机重组](ip-reassembly.md)的区间、尺寸和期限检查，按网络域和实际入接口隔离，独立限额 128 个在途包和 4 MiB。
  转发片逐个保留原 IP 字节，完整报文仅用于分类。完全相同的片不重复储存。转发重组超时静默退休，参照 [Linux v6.12 IPv4 conntrack 重组超时](https://github.com/torvalds/linux/blob/v6.12/net/ipv4/ip_fragment.c#L115)。
- 规则放行后按偏移将原片交给转发，继续遵循出口 MTU、跳数和邻居规则。IPv4 可按出口 MTU 再分片，IPv6 原片逐个转发。
  所有片实际提交后才建立或刷新连接。背压时仅保留余片和当前偏移，继续执行原入站裁决及连接有效性检查。
- 接口停用或移除时退休相关未完整报文。关闭某族转发或连接状态判断时丢弃该族尚未通过规则的报文。仍启用状态判断时，完整包使用收齐时的规则。
- benchmark 决策。普通报文无需分片缓冲；原片按实际长度一次储存，分类时准备一份临时完整报文，发送时直接借用原片。
  整机验收比较顺序/逆序分片吞吐、与非分片混流的延迟及限额下的内存峰值。现有两网卡夹具覆盖双栈乱序回包、校验失败、TX 背压及原分片形态。

### 固定目的地址转换

管理员可用 `destination_nat` 将发往 LiteOS 接口地址或路由到 LiteOS 的 IPv4、IPv6 虚拟地址的流量转给同族后端。
规则有 TCP 或 UDP 条件时可指定后端端口。省略端口沿用原端口，ICMP Echo 保留标识符。后端回程须经过同一 LiteOS 网络域，虚拟地址由上游路由至 LiteOS。

- 规则只为新连接选择映射。入站目的地址在选路前改写，回包选路使用原报文源地址，发送时恢复客户端所见的地址和原端口。连接仍按当前规则过滤。
  两个流若会占用同一线上连接元组，后申请者拒绝。校验和无效、TCP MD5/AO 或 IPv6 Routing/AH 的报文不能使用该转换。
- 对接口本机地址，先识别已有映射或试判是否选中转换动作，再进入与普通转发相同的规则计数、选路和待发路径。
  普通本机服务、ARP、ND 和回环交付沿原入口。关闭转发时丢弃已选中转换的流量，其他本机服务仍可接收。
- netstack 的连接跟踪同时拥有原始连接与线上元组索引。正向和反向查询指向同一代连接，发送前预留索引，所有片提交后才发布。
  待发重试重新确认映射冲突与连接身份。映射随连接到期或清除，更新或撤销规则后已有映射继续生效。
- 相关 ICMP 错误按实际发出的方向匹配连接，调整外层地址、引用中的端点与可见校验和。中间路由器报告错误时保留其源地址。
  方向绑定和错误处理参照 [Linux v6.12 NAT](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_nat_core.c) 和 [RFC 3022](https://www.rfc-editor.org/rfc/rfc3022.html#section-4)。
- benchmark 决策。只有实际使用转换的流才占用双向映射索引。地址和端口改写在现有 TX 窗口完成，传输 checksum 使用 [RFC 1624](https://www.rfc-editor.org/rfc/rfc1624.html#section-3) 的增量更新。
  分片按原发送边界改写，背压时随原包保存改写值。双网卡夹具覆盖双栈 TCP/UDP、映射冲突、路径 MTU 错误、分片、背压、规则撤销及连接清除。吞吐及映射容量随整机验收。
  只有存在目的转换规则或存续映射的族检查本机目的。新连接的试判不更新计数，命中转换后进入正式求值。整机验收测量启用转换时本机 TCP/UDP 接收和转发混流。
  双网卡夹具使用绑定同一接口地址的 UDP socket 验证分片端口转发与本机服务共存，以及撤销规则后已有映射的双向转发。

### 固定源地址转换

管理员可用 `source_nat` 将指定 IPv4 或 IPv6 内网流量的源地址改为同族出口接口地址，或改为对端回程经 LiteOS 的其他地址。
带 TCP 或 UDP 条件的规则可指定固定源端口，省略端口时沿用原端口。ICMP Echo 沿用标识符。

- 选路采用转换前的源地址及当前报文标记，源地址和端口在提交出口时改写。回包在选路前恢复内网目的地址及端口。
  配置源地址是路由器接口地址时，已有映射在本机服务交付前处理回包。未命中已有映射的本机服务继续使用原入口。
- 源、目的转换使用同一连接映射、到期及碰撞校验。一条有序规则链的终止动作选定本次新连接的转换。映射存续期间，相关 ICMP 错误的外层目的、引用和校验和按实际发送方向还原。
  双网卡夹具覆盖出口接口地址上的双栈 UDP、端口保留和指定、分片回包、路径 MTU 错误。报文改写仍在已有 TX 窗口内完成。 [RFC 3022](https://www.rfc-editor.org/rfc/rfc3022.html#section-4)
- 固定转换若与线上连接元组冲突，拒绝新映射。

### 自动源地址转换

用 `masquerade` 让新 IPv4、IPv6 转发连接使用实际出口上的同族地址。选路仍使用原始源地址和标记。出口没有可用的同族地址时丢弃该报文。
IPv4 使用实际出口的接口地址，IPv6 优先使用该出口上仍有效的路由首选地址，其次按目的地址选择。两族都排除链路本地地址。
出口或地址变化后，新连接使用最新结果。未确认的待发转换在所选出口变化或地址已不可用时丢弃。已确认的连接沿用原映射，地址失效时可清除映射后重连。

- TCP、UDP 优先保留源端口。同一协议、出口地址、端口和对端元组发生冲突时，在 49152–65535 分配可用端口。
  查找覆盖整个区间，用尽则丢弃。等待邻居或发送窗口的候选也参与冲突判定，只有实际转发成功的连接才发布映射。ICMP Echo 保留标识符，冲突时丢弃。
  地址选择和元组保留顺序参考 [Linux v6.12 masquerade](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_nat_masquerade.c) 和 [Linux v6.12 NAT](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_nat_core.c)。
- 为本机地址建立新映射时，在同一个 NET 事务中检查 TCP 或 UDP 的本机端口绑定。自动转换跳过已有绑定，固定目标冲突时拒绝新映射。等待邻居或发送窗口的候选提交前重查。
- 本机 TCP、UDP 主动发包在实际选出源地址后检查已确认的 NAT 元组。隐式绑定跳过冲突端口，显式端口与同一远端发生冲突时返回 EADDRINUSE。使用相同端口访问其他远端仍可继续。
  配置为端口转发的入口服务仍按目的转换规则接管。
  待发本机 UDP 和 TCP 控制回复在提交前复核，避免释放原绑定后发送旧报文干扰新映射。映射到期后可立即复用元组。
  本机和转发共享线上冲突域的设计参考 [Linux v6.12 连接跟踪](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_conntrack_proto.c) 及 [NAT 元组冲突判定](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_nat_core.c)。
- benchmark 决策。新映射复用本次发送尝试选出的出口，提交时仍核对该出口和源地址的资格。每次重试重新选路。冲突探测复用连接索引及有界待发队列，无独立分配器或额外锁。
  端口协调只读现有 socket 与转换索引，无新分配或锁。没有已确认转换的地址族跳过本机元组查找。
  双网卡夹具覆盖两族 UDP 的两种启动顺序、待发报文和双向还原，以及已有 NAT 时本机 TCP 的端口选择和握手。整机测量新映射、分片及端口耗尽时的吞吐。

### 组合源和目的转换

`destination_nat` 的可选 `source` 可指定固定源地址和端口，或选择自动源地址转换。
内网客户端访问对外地址时，可以把目的端点转给同一内网的后端，并把源改为路由器的内网地址，使后端回包经路由器还原。
客户端仍通过对外地址和原服务端口通信。规则配置见 [ipconfig](../../user/libraries/network-config/README.md#内网访问对外地址)。

- 入口规则仍匹配原报文。选路使用原始源与改写后的目的，自动源转换随后使用所选出口地址。以同时应用两端转换后的线上元组检查冲突，提交和退休共用同一连接及同一对索引。
  两个方向以及相关 ICMP 的引用均从实际元组推导改写。后端发出的 ICMP 错误以对外地址为源，中间路由器发出的错误保留其地址。
  参考 [RFC 4787 §6](https://www.rfc-editor.org/rfc/rfc4787.html#section-6) 与 [Linux v6.12 NAT](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_nat_core.c)。
- benchmark 决策。复用原转发窗口、校验和增量更新及连接索引，组合转换不增加分配或锁。双网卡夹具覆盖 IPv4 固定源、IPv6 自动源、同接口回包与 ICMP 引用还原。
  双端转换吞吐随整机 NAT 验收测量。

### 更新已有连接的策略

`firewall.existing_connections` 选择新规则是否重新判断已有转发连接。默认 `reevaluate` 让新收到的双向报文按当前规则放行或丢弃。`preserve` 让已有跟踪记录的连接及其关联错误沿用各自原来的规则和地址集。
可以提前开启保留模式，让无需状态匹配的 TCP、UDP 和 ICMP Echo 转发也进入跟踪。旧策略的流量标记继续参与选路，命中不计入当前规则。没有跟踪记录的流量从新策略开始。

- 一条连接的线上映射在两个模式下都保持至关闭、清除或到期。修改 NAT 目标用于新的连接。新 TCP SYN 在旧会话关闭后可以复用原客户端端点，并按新规则重新选择映射。
  已准入且等待发送的报文保留提交时的裁决。配置撤销恢复原规则，对撤销前已实际发出的报文所建立的映射仍按正常生命周期处理。
  参考 [Linux v6.12 nftables 规则求值](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_tables_core.c) 与 [连接确认后的 NAT 行为](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_nat_core.c)。
- 保留边界在激活时取已确认连接的最大身份，以有序区间引用共享规则和地址集。同一连接状态只保存已有的身份，策略版本不复制到每条连接。
  事务预留区间节点，激活和撤销无需分配。区间最后一条连接退休后释放旧索引。确认重新判断模式时，已保留的策略在释放 NET 锁后回收。
- benchmark 决策。无赋标规则的链只搜索控制动作。默认模式不查询历史，保留模式按连接身份查找策略。历史规则内存峰值、最后一条连接关闭时的索引回收及含赋标与纯控制链的重载吞吐随整机验收测量。
  双网卡夹具覆盖多个保留版本、地址集变化、撤销两种模式、双向阻断和 TCP 复用端点后的新映射。

### 查询转发连接

获授权的观察者可用 `ipconfig /connections` 查看默认域，也可加 `/domain` 查询具名域。每条记录显示首发方向的端点、协议、状态及剩余空闲期限，过期记录立即从查询结果消失。
启用连接状态匹配或地址转换的地址族跟踪流量。地址转换连接仍显示转换前的端点。列表沿用 [Linux v6.12 conntrack](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_conntrack_netlink.c#L1117-L1175) 的实时遍历及过期过滤语义。

- netstack 拥有连接状态，routing-rib 经现有安装能力代转查询。router-config 只在获授权的设置端点提供此操作，复用[管理正文传输](router-configuration.md#原生配置审阅与整份替换)。
  原生安装与 RIB 配置能力使用操作码 8，收发长度前缀内联正文，无附带句柄。Linux 设置端点使用操作码 19，正文沿用 VMO/SCM_RIGHTS 的管理信封。
- 所有整数为小端。请求为 u32 版本 1、u64 实例和 u64 继续位置。两者同时为零开启查询。续页必须使用同一实例，重启后重新查询。
  回复为 u32 版本 1、u64 实例和 u64 继续位置（零表示结束），随后最多 64 条 56 字节记录，正文上限 3604 字节。
  记录包含 u64 ID、u64 剩余毫秒、u8 地址族（4/6）、u8 协议（TCP/UDP/Echo 为 1/2/3）、u8 状态（等待/已建立/关闭中/重置为 1–4）、u8 零及源、目的端点。
  每个端点为 u16 端口和 16 字节地址，IPv4 地址后补零。Echo 将标识符放在源端口字段，目的端口为零。
- 续页读取当前 ID 之后的记录，刷新空闲期限不重排。一次查询最多检查 256 个位置，过期过多时空页也可能带继续位置。每页反映查询当时的状态，跨页期间可出现新流或有旧流到期。
- benchmark 决策。每个新流多预留一个有序节点，到期索引的键缩短为期限和 ID。刷新不更新 ID 索引；插入和退休成本及内存随百万流验证测量。
  查询沿现有 NET guard 读取有界记录，释放 guard 后编码与 IPC，不全表复制，也不保留查询会话。

### 清除转发连接

管理员可用 `ipconfig /clear-connection` 清除查询结果中的单条连接。清除请求使用与查询相同的域、执行实例和连接 ID。过期、已清除或来自另一实例的身份返回 NOT_FOUND。
即使端点与协议相同，后续建立的连接也获得新 ID。按身份核对后清除的行为参考 [Linux v6.12 conntrack](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_conntrack_netlink.c#L1527-L1545)。

- 复用查询的授权通道。原生安装和 RIB 配置能力使用操作码 9，Linux 设置端点使用操作码 20。请求正文是 u32 版本 1、非零 u64 实例及非零 u64 连接 ID。
  原生成功仅确认状态。Linux 侧按管理信封确认，回复长度为零且不携带 fd。断线后重新查询当前连接状态。
- NET guard 下同时从流表、到期索引、ID 索引及待发队列移除该连接。取消尚未提交到出口的同一双向流报文，包括依赖该流的关联 ICMP 错误，并归还队列记账。
  后续报文按现行规则分类，首包仍可按规则建立新连接。正常到期与显式清除复用同一连接退休操作。
- benchmark 决策。显式清除沿 ID 索引定位，最多遍历 64 个待发项，不增加索引、节点或锁。仅排队重试的 UDP、Echo 及关联 ICMP 错误核对原流身份和期限，纳入转发背压测量。

### 实时跟踪转发连接

`ipconfig /watch-connections` 先显示当前列表，再报告新增、状态变化和移除。新增在首包成功提交到出口后发布，清除、到期及复用同一端点分别退休旧 ID。
活动流延长空闲期限不单独发布通知。事件带变化当时的状态，当前期限可查询。事件种类参考 [Linux v6.12 conntrack](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_conntrack_netlink.c#L679-L706)。

- 桌面观察沿同一游标和查询入口。每页保留 64 条和一条前瞻记录，受影响的页才重绘，移除记录后从页尾补齐。游标失效重读当前页，实例变化回到第一页。
  只读观察复用原有等待名额，客户端在界面事件循环等待 Unix socket 就绪；翻页保留在途等待，离页后不再发起等待。切换域立即清空旧页和游标。清除仍核对域、实例和连接 ID。
  桌面增量回放与页尾补齐的成本随连接规模验收，转发热路径没有新增工作。[桌面入口](../../user/programs/network-manager/README.md#转发连接)
- netstack 在已有 NET guard 下维护最近 1024 条变化；首次观察时预留环形存储，随网络域释放。每个观察者独立持有已应用的游标，读页不消费共享历史。
  观察者先取得起点，再按连接 ID 分页读取当前表，随后顺序应用起点后的变更。跨实例、游标超前或历史已覆盖时，回复新起点，观察者清空列表并重新查询。
- 原生安装及 RIB 能力用操作码 10 读取增量、11 取得等待能力。两者接收无句柄的长度前缀游标正文，即 u32 版本 1、u64 实例、u64 变更序号。全零读取取得初始起点。
  增量回复正文依次为 u32 版本 1、u64 实例、u64 最后序号、u8 记录数、u8 重同步标志，再跟最多 64 条记录。增量页内序号连续，重同步页不含记录。
  每条记录有 u8 种类。1 新增、2 更新各带 56 字节连接记录，3 移除带 u64 ID。正文最多 3670 字节，整数均为小端。
- 游标已读到末尾时，原生等待操作返回仅有 WAIT/TRANSFER 权限的 Event；落后时立即回复无句柄。读取后发生的变化与注册等待使用同一把 NET guard 串行化。
  同一位置的多个等待者共享一个 Event，首条后续变化置位并退休它。等待在 NET 锁外执行；其他观察者不会清除已有通知。
- Linux 设置端点用操作码 21 经[管理信封](router-configuration.md#原生配置审阅与整份替换)收发增量正文，用操作码 22 等待。
  等待使用[按域内联请求](userspace-abi.md#网络管理入口)携带 20 字节游标，成功只回复状态。linuxd 复用现有等待名额，已发出的等待最多占用名额 15 秒。读页无需占用等待名额。
  名额暂满时客户端间隔一秒继续读取同一域的增量并尝试登记。桌面切换域或退出时取消本地观察任务，已发出的等待由同一期限回收。
- benchmark 决策。未开始观察时不分配历史，转发确认仅检查是否有观察记录。开始后仅在新增、阶段变化和退休写入预留存储，下一条变化最多唤醒一次共享通知。
  状态变化速率、历史覆盖与十万级列表追赶成本纳入整机验收。

## 有界等待与调度

Forwarding 属于一个 NetworkStack，在原 NET guard 下独占，不增加锁、Atomic、全局状态或独立线程。
转发待发与连接跟踪分别记账。没有背压或邻接等待时，成功转发不建立报文队列节点、不复制原包到堆。

- 仅在 ARP/ND 未解析、TX 背压或本轮预算让出时捕获原包；两族合计最多 64 包/256 KiB，按实际 Vec capacity 和节点大小计费，五秒固定寿命。
  临时失败保留原包和下一未发 payload 偏移，TTL 不随重试反复递减；完成/丢弃/接口移除归还所有存储，取消不泄漏 ticket。
- 一轮转发 TX 与本轮 RX 使用同额预算，所有转发新包、旧待办及分片共用。先回收 TX completion，再服务旧待办，持续新流量不能抢光预算。
  预算耗尽立即续调度；真正的 ARP/背压等待使用一秒重试，ARP 消费或 TX 可用转换合并唤醒，不把正常分片让出变成秒级延迟。
- 错误只从原始包引用构造，IPv4/IPv6 分别最多 576/1280 字节；反向同样经当前 FIB/邻居/背压，IPv4 允许所需分片；不能继承输入口或 Identifier。
  后续片及 ICMP 错误不再产生错误；每域 token bucket 限制错误突发和持续速率，没有错误不额外轮询。
  本机错误交现有 RouteReplies，五秒内按本机发送预算尝试，超时释放；IPv4 自动标识与本机发送共用，正常 transit 路径不分配本机编号。
- `ProtocolDevice::reserve` 可在 RX 借用存续时申请独立的 TX ticket。NET guard 串行化设备状态，物理发送槽由所属 reservation 独占。
- 原生配置用一个双栈策略值交换前像。激活禁用时暂停所属族，保留回滚所需待办，确认才退休该族，另一族不受影响。FIB、策略选表、MTU 与接口变化在发布后唤醒发送，待发包重选出口，保留入站裁决与未发送区间。
- 独立链路通知合并为每域一个待更新位。域先清位再从驱动采样，期间到达的通知留给下一轮。安装后绑定补发通知，队列故障只额外检查出错接口。
  加权选路共用实际资格，断开时提前重试。载波代际变化退休旧邻接及分片，合并的断开和恢复也会重新解析。管理配置仍归原配置事务。
  [Linux v6.12 FIB 载波标志](https://github.com/torvalds/linux/blob/v6.12/net/ipv4/fib_semantics.c)

## 验证与成本

固定规则采用 RFC 791/792/1812、[RFC 8200](https://www.rfc-editor.org/rfc/rfc8200.html)、[RFC 4443](https://www.rfc-editor.org/rfc/rfc4443.html)、RFC 4007/4861；成熟对照固定 Linux v6.12 的 ip_options.c 与 ip6_output.c。
复用 netstack-unit 的既有两 NIC wire fixture、真实 NetworkStack/FIB/ARP 和生产 poll；不新增生产诊断入口或独立虚拟机。
用例保护跨接口转发、原头保留、TTL/DF/真实 MTU、copied 选项、重组后 payload、错误反射抑制，以及 ARP/TX 恢复和跨轮分片不重发/不重复减 TTL。
IPv6 用例保护真实 NS/NA、完整二层提交、扩展头不透明、非首片、逐跳选项/错误指针、Hop Limit/PTB/不可达、链路范围、ND 与 TX 恢复、独立开关及确认/回滚。
宿主用例不证明来宾多网卡、百万路由吞吐、完整 RFC 合规或与 Linux/RouterOS 性能等价。

benchmark 决策：新增实际转发热路径，完整系统可用后沿计划的多网卡、64-byte pps/IMIX、目标路由规模及按核扩展一起测量。
成本为 FIB 查询、固定头窗口及一次 RX→TX 拷贝。稳定流量每域轮次只读链路待更新位，逐包复用接口资格，无新锁或分配。整机对比持续转发和链路切换时的读取次数、吞吐与恢复时延。
双网卡夹具验证等待 TX 的 IPv4 报文在重试期限前切换到备用出口、路由丢弃后撤销也不会重发，以及 IPv6 出口不可用时报告不可达。
