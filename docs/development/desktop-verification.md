# 本机登录与桌面

产品入口为 `display-service → compositor → logon → 用户 desktop`。
`logon` 以初始受信任 Wayland 连接常驻；desktop 获得独立的 security-context Shell 连接。
窗口管理仍由 compositor 拥有，账户与会话生命周期由 logon 拥有。

## 首次运行

1. `make build-rootfs` 构建产品，`make run-gui` 启动图形实例；旧开发镜像先运行 `make sync-userland`。
2. 默认用户名 `root` 没有口令：开机直接进入桌面，Ctrl+Alt+Delete 的锁定与解锁也不再弹出登录对话框。
   可在 UART 恢复 shell 执行 `passwd root` 设置口令，或执行 `adduser <用户名>` 创建普通账户；nobody 保持锁定。
3. 账户有口令时，图形界面按 Ctrl+Alt+Delete，输入用户名与口令。登录后可通过同一序列锁定、注销、改密或关机。
   用户主目录必须存在；会话创建用户拥有的 0700 `/run/user/<uid>`。

`sync-userland` 安装账户工具；缺少 shadow 时创建空密码 root 默认，完整匹配旧出厂锁定模板时迁移到新默认，其他已有密码、自定义账户与主目录不被替换。
密码变更先验证当前密码与 shadow 最短改密间隔（UID 0 保留管理员例外），再调用固定 BusyBox passwd 进行带随机 salt 的 SHA-512 crypt 更新与文件锁定/替换。

## 当前可用范围

- 欢迎页（登录类对话框宽度与横幅位图一致）、SAS、密码登录/错误反馈、加载交接、安全页、锁定/解锁、更改密码、注销、关机与重启。
- 蓝色桌面、四个系统图标、28 像素任务栏、应用按钮分页、显示桌面、我的文档、UTC 时钟、ALSA 音量与静音。
- 托盘喇叭单击弹出贴着任务栏的小音量面板（滑块与静音，点外部或 Esc 关闭）；右键喇叭选"调整音频属性"才启动完整的 `sndvol` 窗口。
- 音量控制 `/bin/sndvol`（单列混音器：平衡、音量、全部静音；控制面板"声音和多媒体"的"声音"页可试听系统事件声音，"音频"页显示播放设备并打开它）与"关于 LiteOS"（`control-panel winver`）同样是独立程序；
  托盘小面板与它共用 `sndvol` 库的状态和布局。
- 任务管理器是独立程序 `/bin/taskmgr`，提供应用程序、进程、系统服务、性能与 GPU 五页；开始菜单、任务栏右键、Ctrl+Shift+Esc 与安全界面都只是启动它。
  应用列表走 foreign-toplevel，进程与系统总量读 procfs；原生系统服务经授权的 task-observer socket 查询，以 KOID 为身份；CPU 使用记录可切换总图/每个逻辑 CPU 一图，内存按量级显示单位，GPU 仅显示可读取的 DRM 统计。
- 桌面显示四个系统图标和 `~/Desktop` 里的条目，目录变化时自动刷新。图标可拖动并吸附网格，位置保存在
  `~/.config/liteos/desktop-icons`。图像与标题参与选择和拖放，格子留白按桌面处理，可右键排列图标、刷新或新建文件夹。
- 双击托盘时钟打开"日期/时间 属性"，按 timedate.cpl 对话框还原：“时间和日期”页有月份下拉、年份微调、CalWnd 月历、
  指针时钟与 hh:mm:ss 微调时间框，底部为当前时区；“时区”页为 Win2000 的 74 个时区、世界地图与“根据夏时制自动调节时钟”。
  时区写成 TZif v2 加 POSIX 规则（含夏令时切换）。默认 `/etc/localtime` 为北京时间（UTC+8，CST）；
  rootfs 指纹包含该文件，开发镜像同步保留用户已有选择。地图不按选中时区高亮调色板区域。控制面板另有"系统属性"（常规/网络标识/硬件三页：系统与版本、注册到、处理器与内存；
  计算机全名；设备管理器入口。网络标识的“属性 → 其它”可配置主 DNS 后缀，应用后更新计算机全名和 DNS 搜索。
  域成员身份、NetBIOS 名称、原版的用户配置文件和高级页没有对应功能）。
- 列表表头（任务管理器进程页、资源管理器“详细信息”）的列分隔线可拖动调整列宽，指针在分隔线上显示左右箭头（`wp_cursor_shape_v1` 的 `col_resize`）；状态栏面板宽度由文字量出，超出时截断成“...”，
  所有由数据或语言决定长度的文字统一走 `Painter::fit`/`text_fit`/`label_fit`。
- 鼠标滚轮：compositor 读 `REL_WHEEL`/`REL_WHEEL_HI_RES`，经 `wl_pointer.axis_discrete`/`axis`/`frame` 发给指针下的窗口，classic-ui 汇总为 `EventKind::Wheel`（档位，每档 3 行）；资源管理器（树与列表）、记事本、任务管理器、
  设备管理器、文件对话框、显示属性的颜色列表都支持。任务按钮带程序图标；资源管理器的文件、文件夹与磁盘"属性"是独立窗口（`control-panel properties`，可拖动，含大小、占用空间、时间戳、只读属性与磁盘容量饼图）。
- 右键菜单：任务栏空白处（层叠/横向平铺/纵向平铺、最小化所有窗口及对应撤销、任务管理器、属性）、任务按钮（还原/最小化/最大化/关闭）、桌面图标与桌面空白处
  按 shell32 菜单资源组织（见[外壳设计](../design/classic-desktop/shell.md)），排列图标与新建为级联子菜单。
  排列经授权的外壳协议由合成器执行，应用只使用标准 xdg 窗口接口。任务按钮翻页箭头只在放不下时出现。
- 开始菜单是 Windows 2000 经典布局（程序/文档/设置子菜单、运行、锁定、注销、关机），支持鼠标、方向键、Enter、Escape，点击外部关闭。
  Win 单独释放或 Ctrl+Esc 开关开始菜单；Win+R 运行、Win+E 我的电脑、Win+Break 系统属性、Ctrl+Shift+Esc 任务管理器。
  这些组合键由 compositor 在非独占、非安全界面时转给 desktop；Win 与其他键组合、点击或失焦会撤销单键开始菜单动作，重复事件不重复启动程序。
  关闭开始菜单后用标准 foreign-toplevel 激活当前栈中的活动窗口，不保存第二份焦点历史。
  当前单一 `run-gui` 实例已通过 SSH/RFB 核对这些快捷键：Win+E 打开我的电脑，Win 单键开关菜单，关闭后 Alt+D 能选中原窗口地址栏，
  Win+R 仅打开运行，Win+Pause 打开系统属性，从普通应用窗口按 Ctrl+Shift+Esc 打开任务管理器。该证据覆盖 AArch64、2x 缩放，未覆盖其他架构或缩放。
  Win+M/Shift+Win+M、Win+D 及快速启动“显示桌面”已接入合成器批量事务；本轮当前实例的交互验收见下述批量操作范围。
  Win+Tab/Win+Shift+Tab 选择任务按钮，Enter 或空格激活，Esc 返回当前活动窗口；方向键、Home/End、Shift+F10/菜单键操作选中的任务。
  选择保留到按键确认，不在松开 Win 时抢先激活；自动隐藏任务栏展开，焦点项位于其他按钮页时翻到该页，关闭的句柄不会被编号复用命中。
  Win+F 与开始菜单的“搜索 → 文件或文件夹”使用同一资源管理器搜索位置；基础搜索与验收边界见下文。
- 运行以当前用户执行 shell 命令，是外壳的 layer-shell 窗口（Top 层、锚定左下角、独占区 0 因而避开任务栏，可拖动标题栏移动，打开即获得键盘）；普通图形应用从公开 Wayland socket 连接，不能访问外壳权限。
- 任务按钮激活/恢复和最小化，应用任务窗口请求正常关闭；资源管理器（见[设计](../design/classic-desktop/explorer.md)）：
  ReBar 三行带区（菜单栏、标准按钮与工具提示、地址下拉与“转到”）与转动的品牌 logo、级联子菜单；
  Web 视图面板（窄窗口时隐藏）、各位置的详细资料列、“我的电脑”容量与饼图；
  回收站原位置/删除日期与清空/全部恢复/还原、网络和拨号连接、“浏览文件夹”对话框、三格状态栏与尺寸手柄。
- Desktop Entry 读取系统安装目录，支持 Application/Name[zh_CN]/Exec 与 Hidden/NoDisplay/Terminal；Exec 分词后直接 spawn，禁止 shell 展开。

空 shadow 字段只接受空输入且不弹出对话框，`!`/`*` 锁定值仍拒绝。散列认证仅支持本机 SHA-256/512 crypt，锁定、账户过期、密码过期与强制改密的账户拒绝图形登录；没有 PAM、远程域或拨号。
解锁接受原 UID 或本机 UID 0 管理员，其他普通账户不能接管既有会话；管理员解锁不改变原桌面的执行身份。
Terminal=true 桌面条目当前不显示；终端应用的使用与待验收范围见 [SDK 开发](ui-sdk.md#系统内终端)。
资源管理器的工具栏有悬停提示（停留 500 毫秒）。菜单键盘行为见[交互清单](../design/classic-desktop/interaction.md#菜单ownerclassic-ui开始菜单由-desktop-使用同一实现)。
共享控件：`classic-ui` 提供菜单栏状态机 `MenuBar`（资源管理器、任务管理器、记事本、媒体播放机、音量控制共用）、
文件打开/另存为对话框 `FileDialog`（记事本、媒体播放机）、单行输入框 `Prompt`（任务管理器的新任务）。
剪贴板与拖放使用标准 `wl_data_device_manager` v3。记事本使用文本选择，资源管理器通过 `text/uri-list` 向桌面拖放文件。
资源管理器支持多选：Ctrl 点击切换、Shift 点击选区间、Ctrl+A 全选，复制、剪切、删除、粘贴作用于全部选中项；重命名与属性只作用于焦点项。
窗口最小化与还原、最大化与还原有 150 毫秒的整窗缩放动画（标题栏、客户区与子 surface 同步）；最小化目标：任务栏经 `zwlr_foreign_toplevel_handle_v1.set_rectangle` 告知任务按钮位置；没有位置时取屏幕底边中部。
桌面设置：桌面右键或任务栏右键的“属性”、开始菜单“设置”打开控制面板的“显示”“任务栏”，写入 `~/.config/liteos/desktop.conf`；桌面外壳每个周期检查它的修改时间，
变化后重配任务栏图层（总在最前=Top/Bottom 层，自动隐藏=释放独占区并收成细线、指针进入展开、离开 400 毫秒后收起）并重画背景色与时钟。任务栏时钟、音量与任务按钮悬停约 0.5 秒显示工具提示（独立的小图层）。
桌面文件和文件夹可用 F2、右键“重命名”或慢速点击已选中的文件名进入原位编辑，支持鼠标定位光标和拖选文字。快速双击仍打开项目。新建文件夹后也进入标签编辑。
编辑时从另一个窗口创建文件，选中项与编辑内容应保留。若原项目被移走或替换为同名项目，桌面刷新应结束编辑并提示重新选择。
资源管理器 F2 编辑文件名后切换窗口，应提交名称；Enter 同样提交，Esc 保留原名。同名冲突提示关闭后，应可直接修改草稿并重试。
切换到其他应用后由资源管理器显示的错误框关闭时，应将焦点和窗口前景交回资源管理器；后台对话框关闭不能打断正在使用的其他应用。
新草稿开始、提交接受或失败后恢复编辑时，旧的异步文本粘贴应撤销。
桌面目录按空闲循环的 100 毫秒间隔检查，指针事件不会额外触发查询。
网格由实际工作区决定，不固定每列行数。核对短工作区、输出尺寸变化和自动隐藏任务栏切换：容量足够时新条目与越界保存项目可见，
方向键与整组拖动使用同一边界；配置变更取消旧坐标抓取，选择/编辑身份保持，临时重排不覆盖保存的位置。此项已做代码审查与 Clippy，动态模式切换仍待实际验证。
Delete、右键“删除”与拖入桌面回收站打开独立确认框。确认后执行同一套资源管理器回收站事务，取消保留原项目。
桌面多选：Ctrl 单击、Shift 矩形范围、Ctrl+A、Ctrl+方向键与 Ctrl+空格、空白处框选；Ctrl 框选切换、Shift 框选扩展，Esc 恢复原选择。
选中多项后按住其中一项开始拖动，选择不收缩；整组移动保留相对网格位置。目录刷新后按目标身份保留选择，不能把旧索引用于另一项。
复制、剪切和独立删除确认使用完整文件集合；单选与框选各验证一次跨窗口粘贴。多选拖入回收站取消后源文件保留，确认后全部回收，不额外打开浏览窗口。
关闭最后一个独立确认框后，不额外点击桌面即可继续用 Delete 处理原选择；安全登录界面的键盘优先级不变。
资源管理器支持单选和多选拖入桌面回收站。取消确认保留源文件，确认成功后打开的资源管理器通过目录通知刷新。
大批量拖放验收至少选中 65 项，确认框显示完整数量。另测达到 URI 字节上限的批次，超限时不执行任何删除。
资源管理器在读取新目录前注册变更通知，导航失败保留当前目录的监听。验收时在首次注册监听的边界创建文件，列表应直接显示该文件，无需 F5。
回收站按可见的本地卷项目切换空／满图标。验收时从第二块可写磁盘回收、还原，比较设备号和 inode，并检查已打开的回收站与桌面图标跟随变化。桌面右键“清空回收站”使用独立的永久删除确认框，空站时该命令禁用。
已打开的资源管理器复用目录通知，监听回收站的 `files` 与 `info`。可原地修改测试条目的 `.trashinfo`，确认原位置和日期随之刷新。
挂载和目录身份仍需定期发现。已有监听时每三秒检查一次拓扑，首次创建或监听不可用时沿用一秒检查；目录时间戳只在监听不可用时用于发现变更。
设备管理器 `/bin/devmgmt`：控制面板“系统→硬件”的按钮启动，按类别列出能从 `/proc/stat`、`/sys/block`、`/dev/dri`、`/dev/snd`、`/dev/input`（evdev 设备名）、`/proc/net/dev` 确认的硬件，双击看属性；内核没有统一的设备枚举，所以不全。只读。
网络：控制面板、开始菜单“设置”与“网上邻居”属性打开“网络和拨号连接”文件夹，按 `/sys/class/net` 列出“本地连接”。
  右键为 netshell 的禁用/启用、状态、属性；双击打开“本地连接 状态”（只有“关闭”，内含“属性”“禁用”）。窗口打开时随网卡更新连接图标、载波和速率，断线期间不显示正在计时；连接时长按当前 IPv4 配置计算。
  状态窗口发起禁用后仍可处理窗口事件，重复点击只提交一次；成功关闭窗口，失败显示错误并保留状态窗口。
  “本地连接 属性”（确定/取消）列出 Internet 协议 (TCP/IP)，其“属性”打开 TCP/IP 对话框：自动获得或指定 IP、掩码、网关与 DNS。
  “高级”提供原版 netcfgx 2322、2304 的 DNS 服务器列表和地址编辑，可继续添加服务器，并可填写“此连接的 DNS 后缀”。
  留空时使用 DHCP 选项 15。“附加这些 DNS 后缀(按顺序)”可添加、编辑、删除和排序系统搜索列表。
  自动模式先尝试主 DNS 后缀和各连接后缀，再按“附加主 DNS 后缀的父后缀”开关决定是否尝试主后缀的父级。
  添加、编辑、删除或移动条目后，
  逐层确定才提交到 router-config；任一层取消都丢弃该层草稿。常规页显示前两个手动地址，修改其他设置时保留后续地址。
  状态窗口保留 Windows 2000 的“常规”布局；LiteOS 的“详细信息”页另外显示当前接口的物理地址、IPv4 配置状态、IP、掩码、网关、DNS 服务器、
  DNS 后缀、DHCP 服务器及取得租约与到期的本地时间。租约时刻与 `ipconfig /all` 使用同一格式，无到期时间时显示“无限期”。
  断线或尚未分配 IPv4 时不呈现旧的地址和租约字段，已配置的 `/0` 掩码仍显示为 `0.0.0.0`。
  `ipconfig` 使用与桌面一致的连接名称和链路状态，已连接时显示生效的 IPv4 地址、掩码和网关。
  `ipconfig /all` 另显示网卡说明、物理地址、DHCP、DNS 服务器、连接后缀及搜索顺序，有生效租约时还显示 DHCP 服务器及本地租约时刻。
  `ipconfig /renew [连接名称]`、`ipconfig /release [连接名称]` 接受完整连接名称或含 `*`、`?` 的名称模式，也接受精确接口名（如 `eth0`）。
  省略名称时遍历启用 DHCP 的接口。释放后要执行续租才能重新取得地址。两条命令均需 netdev 权限。
  普通账户可查询只读状态。修改设置经 router-api（需要 netdev 组）交给原生 router-config 持久化设置并重新配置接口。DHCP 由原生 dhcp-client
  完成，resolvd 把生效的 DNS 服务器与搜索后缀写入 `/etc/resolv.conf`，禁用即关闭接口。musl 投影最多 3 个服务器及 247 字节的完整搜索域前缀，原生配置保留全部列表。查询调度由应用使用的解析器决定。
  连接快捷方式、多地址、DNS 动态注册、WINS 与 TCP/IP 筛选未提供。
  旧开发镜像的 `/etc/group` 属于用户数据，由管理员按需创建组及分配成员。
网络与设备管理器、记事本使用从原版 `netshell.dll`/`devmgr.dll`/`notepad.exe` 提取的专用图标，随受 Git 管理的资源集安装，来源见[资源清单](../design/classic-desktop/assets.md)。

## 批量窗口操作

MinimizeAll 的成员以合成器收到请求时的状态为准。先手动最小化 A，再 Win+M/Shift+Win+M，A 应保持最小化；
批量操作之后再手动最小化、还原或激活某窗口，撤销不覆盖该窗口的新选择。重复 Win+M 的空操作不清除上次可撤销记录。

## 转发负载下的桌面响应

2026-11-12 在四核 AArch64/HVF 来宾中测量。具名路由域的两块单队列网卡可双向转发 IPv4 和 IPv6 UDP。分配一个、两个转发专用 CPU，再恢复共享，双向转发均通过。

在同一拓扑上，共享 CPU 持续转发约 4.23 万包/秒，80 轮桌面操作均完成。由 QMP 注入输入并采样画面，测得空载时菜单、移动窗口和缩放窗口的 p95 分别为 43、16、28 ms，带载时为 120、53、72 ms。
停止流量后，中位延迟恢复至空载水平。带载的对照采样中，QMP `query-status` 与截图读取的 p95 分别为 0.36 ms 和 3.05 ms，高负载尾延迟仍待定位。

QEMU 11.1.2 的 `stream` 后端在对端带积压断开后会停止一侧发送。冷启动对照中，关闭前先读完积压，重连后两个方向的 IPv4 和 IPv6 都通过。
同样产生积压后直接关闭，重连后只有一个方向通过，故障出口的 `inuse` 保持 1，`used_idx` 保持 134，`last_avail_idx` 保持 135。
后端在关闭时移除可写通知，重连只登记可读通知，VirtIO 发送描述符因此等不到异步完成。持续负载测量保持对端连接，网卡链路切换另用实际支持该场景的后端验收。
[QEMU stream 断开与重连](https://github.com/qemu/qemu/blob/v11.1.2/net/stream_data.c#L85-L140)、[VirtIO 异步发送完成](https://github.com/qemu/qemu/blob/v11.1.2/hw/net/virtio-net.c#L2533-L2559)

接收缓冲改为整批归还后，以相同的双栈 UDP 负载对照，每个方向各发送 64 条流。每个版本空载及带载各执行 30 轮菜单、移动和缩放。
改动前后分别收到 715,860 和 689,464 个包，两轮速率均约 4.26 万包/秒。
带载样本的 p95 分别为菜单 143→128 ms、移动 66→47 ms、缩放 105→89 ms，菜单中位延迟为 65→71 ms。单轮对照尚无法确认稳定的桌面延迟改善。

移除合成器的同步层列表日志后，开始菜单带载中位延迟仍为 64 ms，空载为 25 ms。桌面验收由对话框上屏确认“运行”入口，冷启动后从该入口执行命令并核对了结果。

同一份新镜像以两块网卡的 `event_idx=off` 作为对照。关闭与启用事件索引时分别收到 698,884 和 671,753 个包，速率约为 4.36 和 4.54 万包/秒。停发并排空后，两种设置都转发了各方向、各地址族的首个 UDP 包。
每组带载 30 轮，菜单中位延迟从 69 ms 降到 47 ms，空载约 25 ms。菜单、移动、缩放的带载 p95 从 130、47、84 ms 降到 94、44、71 ms，距离空载响应仍有差距。
QEMU 11.1.2 的 `info virtio-status` 和 `x-query-virtio-status` 会使本测试实例退出。取样使用实际转发包及画面，成功轮次完成了停发后的首包检查。

两颗 CPU 的吞吐比回切的一颗高 46%。首次单核样本明显偏低，结果仅用于确认同一来宾内的多核扩展趋势。此次没有采集桌面延迟或真实网卡吞吐。

## 门禁

`make verify-runtime-desktop` 使用真实产品 logon/desktop/file-explorer，不用 UI 探针代替产品。
它向一次性镜像注入 alice/bob 与 root 的测试散列（产品 root 无口令会自动登录，不能走密码流程）、procfs 检查脚本与独立标准 ALSA C observer，绝不写入产品或开发账户。
冷启动 topology 复用 display_session 的 AArch64/HVF、2 CPU、1280×800，并通过共用 QEMU owner 添加 VirtIO Sound。

1. 欢迎、SAS、错误密码拒绝与正确密码；背景图标、任务栏像素和两个实际首帧 callback。
2. procfs 四个 UID/GID、补充组集合与运行时目录的真实 owner/mode。
3. 图标启动资源管理器（主目录显示为"我的文档"）、键盘选择、任务按钮最小化与恢复，开始菜单"运行"启动真实后台进程。
4. 验证更改密码后旧密码拒绝、新密码可解锁；普通其他账户拒绝解锁、UID 0 解锁保留 alice 会话；注销清空图层并终止后台组成员。
5. 托盘面板单击弹出与 Esc 关闭、右键菜单打开音量窗口；另用产品原样镜像验证无口令 root 开机直接进入桌面、锁定后解锁都不出现登录对话框。
6. 无权限账户打开音量窗口保持桌面正常；root 登录后拖动 slider、切换静音，独立 C 程序直接用 Linux headers 和 ioctl 读回真实 Master 值。

Wayland/控件协议回归仍由 [Wayland 门禁](wayland-ui-verification.md) 独立裁决。
首帧接管测试在一次性镜像中暂时不启动 logon，以逐像素验证交接画面；产品欢迎与完整会话由本门禁覆盖。
完整 `make verify` 串行包含这两个门禁；定向开发时不重复全量单测。

## 成本与安全所有权

- 没有内核热路径、锁或新 syscall。桌面按配置、输入、窗口列表变化和分钟更新合并失效窗口，每窗口最多一条在途 frame。
- ALSA UI 投影按 100ms deadline 读取，仅实际变化合并重绘；操作使用现有 control ioctl，无新增内核锁/热路径。布局由固定 Linux headers 的 C static assertions 与真实 UI 读回验证，不增加宿主 wall-clock 阈值。
- BMP V4 素材在启动期读取/校验并预乘 alpha，每帧复用；解码器有截断、大小和 alpha 测试，无新增独立 benchmark 阈值。
- 认证 crypt_r 是交互低频、由固定 musl 实现；错误后至少一秒重试窗口，不缓存密码。当前分配内的明文（含已删除尾部）在提交/取消/切换后 volatile 清空，不声称擦除此前已释放的旧分配。
- SAS 期间仅可信 Overlay 的来源优先级与输入屏障新增到 compositor 策略，不改变普通窗口布局或通用 kernel ownership。
- 光栅成本沿用 canvas/typeface 诊断 benchmark；交互门禁验证帧节流与更新正确性，不把截图正确性宣称为性能证明。

## 任务观测

`/bin/taskmgr --snapshot` 可从恢复串口查询同一系统观测链路。原生服务使用 KOID，Linux 进程使用 PID；
统计与权限边界见[原生任务观测](../architecture-contract/execution.md#原生任务观测)，内存字段见[观测口径](../architecture-contract/memory.md#观测口径)。
桌面门禁通过普通用户的真实 Run 启动正式 taskmgr 客户端，校验五个原生服务、独立 KOID、运行状态和可读资源量；
不使用测试专用生产入口。pidfd 生命周期由现有 Linux ABI fixture 与桌面结束操作验收。
