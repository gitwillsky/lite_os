# task-manager

- **类型**：程序（可执行文件）
- **作用**：任务管理器
- **产物 / 安装位置**：`/bin/taskmgr`
- **对应的 Windows 2000 组件**：taskmgr.exe
- **依赖**：classic-ui、classic-theme、canvas、typeface

沿用 Windows 2000 的菜单栏（文件、查看、窗口、帮助；"窗口"只在应用程序页出现）、三格状态栏，并增加独立 GPU 标签。

- 应用程序：foreign-toplevel 窗口列表，结束任务、切换至、新任务（以当前用户执行命令）。
- 进程：标准 procfs 的 Linux 兼容任务，包含类型、PID、CPU、累计 CPU 时间和内存；linuxd 工作线程默认折叠。
  空闲行为统计项，不是真实 PID0。CPU 以全机时间归一化并保留两位小数；相同 PID 的不同 starttime 不沿用旧样本。
- 系统服务：只读系统观测协议返回 root-server、driver-host、ext4d、netstack、linuxd 的真实 KOID、状态、CPU、累计 CPU 时间、内存及线程数。
  服务状态及指标读取失败显示不可用，不伪造零。关键服务不提供结束/重启操作，查询端也不持有管理 capability。
- 性能：CPU 总使用率、按实际逻辑 CPU 编号采样的曲线；“查看 > CPU 使用记录”切换总图/每 CPU 图。
  总进程数与线程数包含原生服务；linuxd 工作线程已经在服务中统计，不重复相加。打开文件数只统计 Linux 进程的文件描述符。
  内存使用显示已用物理内存/总物理内存与采样期最高用量，不称为 Windows 内存承诺。
- GPU：仿性能页的“设备/总数”统计分组与整行选择的客户端列表；按 DRM client-id 去重，列出缓冲占用与标准 `drm-shared-memory` 共享量，点列标题排序；私有缓冲合计只累加各客户端的非共享部分；与 CPU 采样共用后台刷新周期。跨客户端共享资源不能求和当作显存；未提供的指标隐藏，不显示占位或推测值。
- 内存展示：进程列、性能页、仪表和状态栏共用二进制单位，按数值自动选择 KiB、MiB、GiB 及以上单位；KiB 保留整数，其余保留一位小数，舍入到 1024 时提升单位。采样和排序始终使用原始 KiB 数值。
- 查看菜单的更新速度（高 0.5 秒、正常 2 秒、低 4 秒、暂停）控制采样间隔。

诊断通道可运行 `/bin/taskmgr --snapshot`，复用正式采样输出系统服务和兼容进程；无需连接图形会话。
内存列的准确口径：Linux 进程为应用 RSS，原生服务为映射范围内已有 RAM backing 的字节数；共享页可能重复计数，不能把所有行相加当作全机已用内存。
无独立应用地址空间的工作线程显示 `—`。结束普通进程使用采样时固定的 pidfd，并由内核检查权限；PID1、工作线程和统计项不提供结束操作。

没有的：选项菜单（总在最前、最小化时隐藏需要窗口层协议）、选择列、显示内核时间（内核没有分开的内核/用户时间统计）、层叠/平铺。
