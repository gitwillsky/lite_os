# DNS 转发契约

## 执行与配置边界

- `dns-cache` 是受监督的原生执行服务。其工厂 `liteos.network.DnsCache` 只授权给 router-config，服务自身只接收 NET 能力。`resolvd` 继续负责桌面应用的 `/etc/resolv.conf` 投影。
- 工厂接受版本化的完整执行配置，指定下游接口及其实际地址，以及有序的上游解析器。监听使用真实接口和明确的 IPv4/IPv6 地址，地址必须已经可用。监听 UDP/TCP 53，不使用通配地址。
- 单个会话拥有监听和缓存，关闭控制能力或 NET 退出时释放全部资源。暂停会清除在途查询和客户端流，直到配置 owner 释放暂停能力。
  替换时先预备新增监听，成功后退休已删除监听并保留未变化的监听。上游集合或次序变化时丢弃原缓存。
- 持久配置来自 `dns.forwarding`，监听及链路本地上游均用配置接口名引用设备。监听须引用同一配置中的静态地址，实际 ifindex 只在执行时解析。
  既有导入、校验、对比、保存、备份及开机加载共用该配置对象。禁用或拔出全部下游时停止监听，设备恢复后按原配置重建。
- 接口变更前暂停受影响的 DNS 会话，文件和 NET 决定确认后再替换执行设置。失败撤销完成才恢复旧会话，结果不明时保留暂停和重试截止。
  执行服务退出时由同一配置事件循环重建，状态快照在待确认期间报告 Applying。停用先确认监听已关闭，再释放会话。
- 在 DHCPv4 的 DNS 选项或 IPv6 下游通告的 DNS 列表中填写该接口上的监听地址，客户端即可使用同一缓存。IPv6 通告提供独立寿命并支持撤回。见[下游路由通告](ipv6-link.md#下游路由通告)。

## 查询与缓存

- packet-wire 校验问句、记录信封和压缩名称边界。执行器匹配已关联上游端点及事务 ID、操作、问句和查询类。每个 UDP 尝试使用独立的随机非特权端口和事务 ID。
- TCP 客户端直接走上游 TCP。UDP 上游返回 TC 后改用同一上游的 TCP，其他失败在总超时内尝试后续解析器，全部失败返回 SERVFAIL。UDP 收发保守限制 EDNS 回复大小为 1232 字节。
- TCP 采用 DNS 长度前缀，支持客户端在同一连接顺序查询和流水发送。每条下游连接同时处理一个问题，以读侧背压约束积压。上游 TCP 当前按事务建立，尚未合并并发请求或复用连接。
- 缓存按域名、类型、类及 DNS/EDNS 查询语义复用完整回复。截断、认证或带专用 EDNS 选项的回复不缓存。TTL 按单调时钟减少，否定回复须含 SOA。
- 缓存同时限制记录数与保留字节，命中更新最近使用顺序且不分配。缓存和转发共用 UDP 过大处理，保留问句及必要 OPT，提示客户端改用 TCP。
- 服务转发普通单问题 QUERY。事务签名、动态更新、区域传输及本地 DNSSEC 验证不在此执行服务的边界内。
- 整机验收覆盖双栈 UDP/TCP、截断、地址变化及上游故障。分别测量缓存命中与未命中的延迟、内存和 CPU，测量上游连接建立成本和有界并发下的客户端响应。
