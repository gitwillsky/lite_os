# 双栈单播转发契约

本文件拥有原生 NET 的 IPv4/IPv6 单播跨接口执行、有界等待与错误返回；路由来源/选路仍见[RIB 与执行 FIB](ipc-network.md#rib-候选目录)。
当前已接通生产 NIC 接收、同域 FIB 选择、出口邻居解析及实际 TX；尚未完成来宾多网卡和成熟路由器互通验收，不声明完整双栈路由系统已交付。

## 入口与职责

- inet::poll 对发往本接口单播 MAC 的已分类 IPv4 做唯一 FIB 目的分类；本机、广播、多播仍交本机入口，其他目的交 inet::forward。
  ARP 地址不能伪装成待转发 IPv4；VLAN 与回环不进入物理转发入口。RX 仍由原 token 消费和归还，AF_PACKET 在同一次消费中观察原始帧。
- 目的分类只属于同一帧、同一 NET guard，直接交给本机 ingress 使用，避免为新增入口重复查询本机收包的目的；不是另一份长期路由缓存。
- IPv6 批解析仅确认固定头和数据报长度；发往本接口单播 MAC 的非本机单播进入转发，普通本机/ND/组播仍走原入口。低于 IPv6 最小 MTU 的接口不接收 IPv6。
- RoutingTable/FIB 仍是唯一出口选择；按当前源/目的选择加权成员，不缓存跨事务路由、邻接或设备身份。下一跳/接口变化后的重试重新查询当前 FIB。
- 两族单播转发默认启用，面向路由器用途；仅同一域的实际合格接口可用。默认参考固定 RouterOS 的 IPv4/IPv6 Settings，不据此声明兼容其全部运行参数。
  独立开关沿同一[原子配置事务](router-configuration.md#双栈转发开关)生效；IPv6 NA 的 Router 位来自当前执行策略，不复制到地址 owner。

## IPv4 执行与报文语义

1. 接收先验证完整 IPv4 头与 checksum，排除非法源、回环/多播/保留源及 FIB 已知本机/广播源；不以 transport checksum 作为路由器的转发前提。
   目的路由的丢弃不回错误，禁止与不可达使用不同错误；TTL 到期返回 Time Exceeded，DF 超出出口实际 MTU 返回 Fragmentation Needed 及 MTU。
2. 正常转发不分配：原包借用 RX，头最多 60 字节的栈窗口；TTL 减一，保留 DSCP/ECN、Identification、上层 payload、选项与分片语义。
   超 MTU 且允许分片时按八字节边界切分，保留原分片偏移与 MF；非首片将非 copied 选项改为 NOP，保持头长和 copied 选项，与 Linux v6.12 ip_options_fragment 的处理一致。
3. Record Route 写实际出口地址；Timestamp 支持时间、地址加时间及指定地址，非 UTC 计时显式置高位，满选项递增 overflow，溢出/非法指针返回 Parameter Problem。
   源路由默认拒绝并返回 Source Route Failed；未知已通过 framing 的选项按原值保留，不擅自执行其策略。
4. IPv4 发送按网关族借出口的 ARP 或 ND，IPv6 网关只决定 Ethernet 目的 MAC，EtherType 与报文仍为 IPv4。出帧共用实际 reservation/commit。
   主机与转发共用 packet-wire 的分片窗口，完整 options/载荷仍借用原包，不经丢失 options 的 Repr 重编码；真实提交失败不能提前推进游标。
   IPv6-only 出口的本机 IPv4 流量可使用同域其他启用接口的合格 IPv4 地址，仍优先采用绑定源或首选源；没有源时报地址不可用。

## IPv6 执行与报文语义

1. Ipv6Datagram 只提供完整固定头/长度；本机 Ipv6Packet 另校验完整扩展链，ICMP 引用不冒充完整包。转发只处理首个逐跳头，Destination/Routing/AH/Fragment 及不认识的上层保持不透明。
   Hop-by-Hop 的未知选项按高两位决定跳过、丢弃或返回 Parameter Problem；错误指针来自唯一格式库。非首分片照常转发，不等待终点重组，不检查/修复上游 transport checksum。
2. 全局目的按原始源/目的选择当前 IPv6 FIB 和加权成员；链路目的限定接收 zone，带链路源/目的的报文不得跨接口，超范围返回 Destination Unreachable code 2。
   源为未指定、组播、回环、mapped 或当前本机地址时拒绝；禁止路由返回管理员拒绝，丢弃路由不反射错误，无可用路由返回不可达。
3. Hop Limit 仅在转发时减一；到期返回 Time Exceeded。出口超实际 MTU 返回 Packet Too Big 与 MTU；路由器不分片，原始片头、标识、流标签、Traffic Class 与 payload 保持。
4. ND/NUD 只归实际出口的地址 owner。正常解析命中直接写最终 DMA：Ethernet 写完整二层帧，IP-medium 只写 IP；转发明确关闭 TX checksum 重算。
   解析创建了立即工作时让出并回投，不能等待下一次外部 timer；真正 ND 等待及 TX 背压沿原有界队列，恢复后重新选路且不再次递减 Hop Limit。
   备用路径实际提交后，可按现有节奏在原首选网关所属接口登记复探。TX 拒绝或背压时不登记。
5. 错误最多为 IPv6 最小 MTU 1280 字节，引用修改前原包，源取反向当前出口的合格地址。错误与 Redirect、无法确定上层、非唯一源不反射新错误；资源不足丢弃，不伪报远端不可达。

## 策略选路

使用现有 `ipconfig /export` 导出完整配置，在根级添加 `policy_routing`，然后通过同一 `ipconfig /import` 提交。
`tables` 每项包含表号 `id` 及采用[静态路由格式](router-configuration.md#静态路由配置)的 `routes`；表号非零且不得占用 253–255。
`rules` 每项包含 `priority`、`source`、`prefix_length` 和目标 `table`。缺省 `origin` 为 `forwarded`，可用 `ingress` 引用 `interfaces` 中的配置名。
`origin: "local"` 匹配本机单播，不填 `ingress`。任意源用 `0.0.0.0` 或 `::` 加 `prefix_length: 0`。本机规则在 Linux 规则列表显示为 `iif lo`。
规则优先级在 1–32765 内全局唯一，数字越小越先尝试。源网段、入接口及标记条件都须匹配。表无可用路由时继续，显式丢弃或拒绝时结束。
系统先处理本机地址，规则均未命中时使用主表。可用可选 u32 字段 mark 和 mark_mask 匹配报文标记。指定标记并省略掩码时匹配全部位，
包括显式指定的零。掩码必须非零，标记在掩码以外的位必须为零。两个字段均省略时匹配任意标记。掩码比较对照 [Linux v6.12](https://github.com/torvalds/linux/blob/v6.12/net/core/fib_rules.c#L244)。

本机应用通过 SO_MARK 设置标记。TCP 发送采用当前连接的标记，UDP 和 RAW 已入队的数据报保留提交时的标记。跨接口流量可在[预路由链](#预路由规则)中设置标记。

应用提供源地址时直接用该源匹配规则。应用未指定源时，先沿无源限制的路径确定源，再用确定的源完成选路，两次查询使用相同标记。
本机发送和 `ip route get` 共用这一选择，改变出口不重新改选源。备选表的拒绝动作在显式绑定出口时仍生效。
两段查询参考 [Linux v6.12 IPv4 connect](https://github.com/torvalds/linux/blob/v6.12/include/net/route.h#L295)，本机流量使用回环身份对照 [Linux IPv6 输出](https://github.com/torvalds/linux/blob/v6.12/net/ipv6/route.c#L2464)。

用 `ip route get 203.0.113.9 from 192.168.50.10 iif eth1` 查询该流量的表、出口和网关。IPv6 使用 `ip -6 route get`。
用 `ip rule show` 与 `ip -6 rule show` 枚举当前规则。出厂和同步后的开发镜像均提供 BusyBox `ip`，入接口显示实际设备名。
带标记的路径查询使用支持 `ip route get … mark …` 的 iproute2 或直接提交 RTA_MARK，镜像内 BusyBox 的路径查询不接受 mark 参数。
点查复用实时选表、下一跳和入接口范围检查；转发停用时报告不可达，本机交付仍可查询。两族输入方向对照 [Linux IPv4](https://github.com/torvalds/linux/blob/v6.12/net/ipv4/route.c#L3075) 和 [IPv6](https://github.com/torvalds/linux/blob/v6.12/net/ipv6/route.c#L5723)。

- 持久配置、校验和设备匹配由 router-config 处理。设备缺席时绑定该入接口的规则暂退，重连按同一配置重投影；保存、备份与恢复使用原配置树。
- RIB 用同一求解器独立求解各表。直连观测只为递归下一跳提供证明，显式备选路由可覆盖同前缀的直连观测；各族同一执行组字典内的组身份不冲突。
- RIB 意图段为 `policy_routing::Tables` v2。u32 版本、规则段长度、规则段、u32 表数，随后按表号依次为 u32 表号及带 u32 长度的两族声明。
  执行侧复用同一规则段。u32 版本后为 40 字节规则，依次是 u32 优先级/入接口/表号、u8 前缀长度/地址族、两字节零、16 字节源地址（IPv4 补零）及 u32 标记和掩码。
- INET 的 SET_OPTION kind 26 在通用标量槽保留标记的 32 位，选项字节为零，查询编号为 34。授权在 Linux socket 边界检查，标记只由实际端点持有。
- NET 在同一写租约发布与撤销两族 FIB 和规则。每条规则只存一次，按本机输出和转发分段；发送与重试只扫描所属段，规则查询按优先级合并。
  不新增报文分配或锁。每条规则增加一次掩码比较，队列中的数据报和 socket 回复需保留 32 位标记。规则扫描及二次查找成本纳入单播 pps 和 IMIX 测量。
- 固定行为参考 [Linux v6.12 规则查询](https://github.com/torvalds/linux/blob/v6.12/net/core/fib_rules.c#L275)。宿主网卡夹具覆盖配置导入正文、表未命中、规则命中、拒绝和撤销后两族实际出帧。

## 预路由规则

配置树中的 firewall.prerouting 为有序规则链，使用同一 `ipconfig /import` 提交、保存和恢复。规则按目的网段或具名地址集、可选入接口和可选连接状态匹配双栈单播转发流量。
入接口引用 interfaces 中的稳定配置名，缺省匹配所有接口。set_mark 设置 u32 标记并继续。accept 放行至选路，drop 静默丢弃，两者均结束本链。
第一个命中的放行或丢弃裁决生效，沿用裁决之前最后设置的标记。没有裁决时放行，未赋标时标记为零。裁决顺序参考 [nftables](https://manpages.debian.org/bookworm/nftables/nft.8.en.html#VERDICT_STATEMENT)。
本机服务收包不受此链影响。路径点查使用显式 RTA_MARK，模拟该标记下的选路，无需执行入站规则。

- router-config 解析设备引用。设备缺席时保留规则的声明位置，设备重连后按保存的配置重投影。RIB 只在原配置事务中转交链，链本身不改变候选路由。
- 链正文以三个 u32 开头，依次为版本 6、规则数和地址集数。每条规则 28 字节，依次为 u32 入接口、u32 标记、u8 族、u8 前缀长度、u8 动作（0 赋标、1 放行、2 丢弃）、
  u8 连接状态（0 任意、1 新流、2 已建立、3 关联错误）及 16 字节目的网段（IPv4 补零）。族为零时表示地址集，长度为零，目的字段仅前四字节为集合下标。
  入接口零匹配任意接口，1 表示设备缺席且规则不参与转发分类。地址集紧跟规则，按配置名升序排列。每集为 u32 名称长度、UTF-8 名称、u32 成员数及成员记录。
  成员为 u8 地址族、u8 前缀长度及 16 字节地址。IPv4 后补零。所有整数为小端。未被任何规则引用的集合只保留在持久配置。
  放行和丢弃规则的标记字段必须为零。
  两个空段表示清除。NET 在发布前编译，缓存首个裁决及此前是否有赋标。激活与同批选表规则共享发布点，撤销交换回前像。
- 放行的待发报文保留入站标记与分片进度。重试使用当前路由表，沿用原入站裁决。规则替换影响新收的报文。标记不写入报文头或 ICMP 引用。
- benchmark 决策。无状态分类查通用和指定接口两组前缀索引，按状态匹配时至多再查两组。取最早裁决后沿已匹配的前缀祖先枚举其前的赋标，一次完成计数及最终标记选择。
  无可达赋标时跳过祖先遍历，分类不增加堆分配、新锁或全链扫描。
  入站分类开销纳入双栈 pps 和 IMIX。宿主用例覆盖双族重叠规则、放行前赋标、静默丢弃、实际出口和撤销。

### 复用目的地址集

在 `firewall.address_sets` 声明具名的 IPv4、IPv6 网段列表。规则使用 `destination_set` 引用，或用 `destination` 和 `prefix_length` 直接指定目的网段。
网段必须规范。未知集合、重复配置名和混用两种目的条件均拒绝提交。空集合匹配不到报文，覆盖或重复成员只使命中的规则执行一次。具名集合语义参考 [nftables SETS](https://netfilter.org/projects/nftables/manpage.html#SETS)。

- 规则和集合成员在同一次执行事务发布。只改成员时，NET 复用原不可变规则索引，替换双栈集合索引并保留计数；撤销恢复旧成员。未改有效成员时保留当前版本。
- benchmark 决策。每个地址族共用一棵集合前缀索引，构建时去掉同一集合的重复和覆盖成员。报文只查目的地址所属集合，再和直接网段匹配一起选最早裁决。
  只有匹配到的集合查询规则组，命中的赋标按同一个截止顺序计数。地址集匹配与成员换版开销纳入规则规模、pps 和 IMIX 验收。

### 查询防火墙命中次数

`ipconfig /firewall` 按配置顺序显示规则、报文数和 IP 字节数，包括设备缺席及从未命中的规则。每次入站分类对实际执行的各条赋标、放行或丢弃规则分别计数。
计数采用该次分类的 IP 长度，出口背压重试和分片发送沿用原裁决。计数语义参考 [Linux v6.12 nftables](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nft_counter.c#L17-L47)。

- 规则链独占计数。替换规则定义后从零计数，撤销恢复旧链及其计数。仅修改地址集成员时，同一条规则继续累计。两个 u64 值饱和增长，由原 NET guard 串行更新。
- 原生安装和 RIB 配置能力使用操作码 12，收发长度前缀内联正文。Linux 设置端点使用操作码 23，沿用[授权管理信封](router-configuration.md#原生配置审阅与整份替换)。
  游标是 u32 版本 2、u64 链版本、u32 已读规则数。版本之外两个字段同时为零读取首页。规则或集合换版后重新读取首页。
  回复是 u32 版本 2、u64 链版本、u32 后续起点（零为结束）及 u8 记录数，再跟最多 64 条记录。每条为 28 字节规则、u64 报文数、u64 字节数及 u8 集合名长度和 UTF-8 名称。
  直接网段的名称长度为零。集合名称最长 255 字节。整数均为小端。
- 每页在同一 NET guard 复制后再编码，页间计数可以增长。查询不清零计数。计数写入及多规则匹配的增量开销随双栈 pps 和 IMIX 一起测量。

## 转发连接状态

当对应地址族有 connection_state 条件时，转发入口验证完整 TCP、UDP 或 ICMP 报文。TCP 和 UDP 按地址及端口双向匹配；Echo 按发起地址、对端地址和标识符区分流。
原方向未成功转发回包时为 new。匹配有效流的首个回包与双向转发后的两个方向均为 established。无匹配请求的 Echo Reply 无连接状态。
尚未重组的分片、IPv6 链路本地地址、零端口和校验失败的报文无连接状态，仍可按无状态规则过滤。

可分类为 related 的错误包括 IPv4 的不可达、超时和参数错误，以及 IPv6 的不可达、Packet Too Big、超时和参数错误。
外层目的须等于引用源，引用须含足够的原 TCP、UDP 或 Echo 头以匹配同域尚有效且已转发的方向。TCP 引用还核对所见序列范围。关联错误不建立流、不刷新期限。
类型、方向及外层目的校验参考 [Linux v6.12 ICMP 跟踪](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_conntrack_proto_icmp.c#L96)。

只有实际提交出口的有效报文才建立或刷新状态。待发包沿用入站裁决，重试时仍核对它所关联的连接身份及期限。TCP 还核对握手或窗口。迟到的包不能刷新已替换的连接。
Echo 和未见回包的 UDP 流空闲 30 秒退休。已成功双向转发的 UDP 流空闲 120 秒退休。换规则后，新报文按新规则和当前有效流分类。
期限参照 [Linux v6.12 Echo](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_conntrack_proto_icmp.c#L22) 和 [UDP 默认期限](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_conntrack_proto_udp.c#L25)。

TCP 从有效的初始 SYN 开始跟踪。匹配握手序号的反向报文可使用 established。完整握手之前，仅接受符合握手阶段及当前序列边界的报文。
双向记录实际转发的序列和确认边界、协商的窗口缩放与 FIN；超出边界的报文无连接状态。合法 RST 关闭通路，半关闭期间另一方向可继续发数据。
未收到回包的 SYN 重传保留原期限。TCP 首次握手、双向握手、已建立、FIN 和 RST 空闲期限分别为 120 秒、60 秒、5 天、120 秒和 10 秒。
严格起始和窗口规则参考 [Linux v6.12 TCP 跟踪](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_conntrack_proto_tcp.c#L788) 与 [RFC 7323](https://www.rfc-editor.org/rfc/rfc7323.html#section-2.2)。

- 状态和索引归 Forwarding。每域用随机密钥的哈希表管理双向键，容量上限一百万条；新流在发送前预留哈希表、到期和连接 ID 索引空间，满额或资源不足时拒绝。
  到期索引使用期限和连接 ID，连接 ID 索引指向双向键。延长只更新实际期限，FIN/RST 缩短期限时复用原到期节点。每轮最多处理 64 项，最后一条退休后归还哈希表容量。
  TCP 的双向窗口单独分配，仅 TCP 流承担该空间。候选状态和新节点均在 TX 前预备，提交前失败时直接释放。
- benchmark 决策。无连接状态规则时跳过传输校验与流查找。只有同一完整报文的接收证明才允许省略软件 checksum。
  启用时测量传输校验、ICMP 引用解析、双向哈希查找、插入和超时回收。并发双栈 pps 与百万流内存随整机验收。
  当前未提供转发分片跟踪、NAT 或多核分片。

### 查询转发连接

获授权的管理员可用 `ipconfig /connections` 查看默认网络域正在跟踪的有效连接。每条记录显示首发方向的端点、协议、状态及剩余空闲期限，过期记录立即从查询结果消失。
只对启用连接状态匹配的地址族跟踪流量。列表沿用 [Linux v6.12 conntrack](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_conntrack_netlink.c#L1117-L1175) 的实时遍历及过期过滤语义。

- netstack 拥有连接状态，routing-rib 经现有安装能力代转查询。router-config 只在获授权的设置端点提供此操作，复用[管理正文传输](router-configuration.md#原生配置审阅与整份替换)。
  原生安装与 RIB 配置能力使用操作码 8，收发长度前缀内联正文，无附带句柄。Linux 设置端点使用操作码 19，正文沿用 VMO/SCM_RIGHTS 的管理信封。
- 所有整数为小端。请求为 u32 版本 1、u64 实例和 u64 继续位置。两者同时为零开启查询。续页必须使用同一实例，重启后重新查询。
  回复为 u32 版本 1、u64 实例和 u64 继续位置（零表示结束），随后最多 64 条 56 字节记录，正文上限 3604 字节。
  记录包含 u64 ID、u64 剩余毫秒、u8 地址族（4/6）、u8 协议（TCP/UDP/Echo 为 1/2/3）、u8 状态（等待/已建立/关闭中/重置为 1–4）、u8 零及源、目的端点。
  每个端点为 u16 端口和 16 字节地址，IPv4 地址后补零。Echo 将标识符放在源端口字段，目的端口为零。
- 续页读取当前 ID 之后的记录，刷新空闲期限不重排。一次查询最多检查 256 个位置，过期过多时空页也可能带继续位置。每页反映查询当时的状态，跨页期间可出现新流或有旧流到期。
- benchmark 决策。每个新流多预留一个有序节点，到期索引的键缩短为期限和 ID。刷新不更新 ID 索引；插入和退休成本及内存随百万流验证测量。
  查询沿现有 NET guard 读取有界记录，释放 guard 后编码与 IPC，不全表复制，也不保留查询会话。

### 清除转发连接

管理员可用 `ipconfig /clear-connection` 清除查询结果中的单条连接。请求必须提供执行实例和连接 ID。过期、已清除或来自另一实例的身份返回 NOT_FOUND。
即使端点与协议相同，后续建立的连接也获得新 ID。按身份核对后清除的行为参考 [Linux v6.12 conntrack](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_conntrack_netlink.c#L1527-L1545)。

- 复用查询的授权通道。原生安装和 RIB 配置能力使用操作码 9，Linux 设置端点使用操作码 20。请求正文是 u32 版本 1、非零 u64 实例及非零 u64 连接 ID。
  原生成功仅确认状态。Linux 侧按管理信封确认，回复长度为零且不携带 fd。断线后重新查询当前连接状态。
- NET guard 下同时从流表、到期索引、ID 索引及待发队列移除该连接。取消尚未提交到出口的同一双向流报文，包括依赖该流的关联 ICMP 错误，并归还队列记账。
  后续报文按现行规则分类，首包仍可按规则建立新连接。正常到期与显式清除复用同一连接退休操作。
- benchmark 决策。显式清除沿 ID 索引定位，最多遍历 64 个待发项，不增加索引、节点或锁。仅排队重试的 UDP、Echo 及关联 ICMP 错误核对原流身份和期限，纳入转发背压测量。

### 实时跟踪转发连接

`ipconfig /watch-connections` 先显示当前列表，再报告新增、状态变化和移除。新增在首包成功提交到出口后发布，清除、到期及复用同一端点分别退休旧 ID。
活动流延长空闲期限不单独发布通知。事件带变化当时的状态，当前期限可查询。事件种类参考 [Linux v6.12 conntrack](https://github.com/torvalds/linux/blob/v6.12/net/netfilter/nf_conntrack_netlink.c#L679-L706)。

- netstack 在已有 NET guard 下维护最近 1024 条变化；首次观察时预留环形存储，随网络域释放。每个观察者独立持有已应用的游标，读页不消费共享历史。
  观察者先取得起点，再按连接 ID 分页读取当前表，随后顺序应用起点后的变更。跨实例、游标超前或历史已覆盖时，回复新起点，观察者清空列表并重新查询。
- 原生安装及 RIB 能力用操作码 10 读取增量、11 取得等待能力。两者接收无句柄的长度前缀游标正文，即 u32 版本 1、u64 实例、u64 变更序号。全零读取取得初始起点。
  增量回复正文依次为 u32 版本 1、u64 实例、u64 最后序号、u8 记录数、u8 重同步标志，再跟最多 64 条记录。增量页内序号连续，重同步页不含记录。
  每条记录有 u8 种类。1 新增、2 更新各带 56 字节连接记录，3 移除带 u64 ID。正文最多 3670 字节，整数均为小端。
- 游标已读到末尾时，原生等待操作返回仅有 WAIT/TRANSFER 权限的 Event；落后时立即回复无句柄。读取后发生的变化与注册等待使用同一把 NET guard 串行化。
  同一位置的多个等待者共享一个 Event，首条后续变化置位并退休它。等待在 NET 锁外执行；其他观察者不会清除已有通知。
- Linux 设置端点用操作码 21 经[管理信封](router-configuration.md#原生配置审阅与整份替换)收发增量正文，用操作码 22 等待。
  等待携带 20 字节内联游标，成功只回复状态。linuxd 复用现有在途等待名额，等待最多 15 秒，超时后重新检查游标。读页无需占用等待名额。
- benchmark 决策。未开始观察时不分配历史，转发确认仅检查是否有观察记录。开始后仅在新增、阶段变化和退休写入预留存储，下一条变化最多唤醒一次共享通知。
  状态变化速率、历史覆盖与十万级列表追赶成本纳入整机验收。

## 有界等待与调度

Forwarding 属于一个 NetworkStack，在原 NET guard 下独占，不增加锁、Atomic、全局状态或独立线程。
转发待发与连接跟踪分别记账。没有背压或邻接等待时，成功转发不建立报文队列节点、不复制原包到堆。

- 仅在 ARP/ND 未解析、TX 背压或本轮预算让出时捕获原包；两族合计最多 64 包/256 KiB，按实际 Vec capacity 和节点大小计费，五秒固定寿命。
  临时失败保留原包和下一未发 payload 偏移，TTL 不随重试反复递减；完成/丢弃/接口移除归还所有存储，取消不泄漏 ticket。
- 一轮转发 TX 与本轮 RX 使用同额预算，所有转发新包、旧待办及分片共用。先回收 TX completion，再服务旧待办，持续新流量不能抢光预算。
  预算耗尽立即续调度；真正的 ARP/背压等待使用一秒重试，ARP 消费或 TX 可用转换合并唤醒，不把正常分片让出变成秒级延迟。
- 错误只从原始包引用构造，IPv4/IPv6 分别最多 576/1280 字节；反向同样经当前 FIB/邻居/背压，IPv4 允许所需分片；不能继承输入口或 Identifier。
  后续片及 ICMP 错误不再产生错误；每域 token bucket 限制错误突发和持续速率，没有错误不额外轮询。
  本机错误交现有 RouteReplies，五秒内按本机发送预算尝试，超时释放；IPv4 自动标识与本机发送共用，正常 transit 路径不分配本机编号。
- ProtocolDevice 的共享 TX 申请只为 RX 借用仍存续时申请独立 ticket；NET guard 仍串行化设备状态，安全性来自各 reservation 的独占生命周期，不共享同一个可写槽。
- 原生配置用一个双栈策略值交换前像；激活禁用时暂停所属族，保留回滚所需待办，确认才退休该族，另一族不受影响。路由/策略改变和撤销均重试现有队列，不保存过期出口。

## 验证与成本

固定规则采用 RFC 791/792/1812、[RFC 8200](https://www.rfc-editor.org/rfc/rfc8200.html)、[RFC 4443](https://www.rfc-editor.org/rfc/rfc4443.html)、RFC 4007/4861；成熟对照固定 Linux v6.12 的 ip_options.c 与 ip6_output.c。
复用 netstack-unit 的既有两 NIC wire fixture、真实 NetworkStack/FIB/ARP 和生产 poll；不新增生产诊断入口或独立虚拟机。
用例保护跨接口转发、原头保留、TTL/DF/真实 MTU、copied 选项、重组后 payload、错误反射抑制，以及 ARP/TX 恢复和跨轮分片不重发/不重复减 TTL。
IPv6 用例保护真实 NS/NA、完整二层提交、扩展头不透明、非首片、逐跳选项/错误指针、Hop Limit/PTB/不可达、链路范围、ND 与 TX 恢复、独立开关及确认/回滚。
宿主用例不证明来宾多网卡、百万路由吞吐、完整 RFC 合规或与 Linux/RouterOS 性能等价。

benchmark 决策：新增实际转发热路径，完整系统可用后沿计划的多网卡、64-byte pps/IMIX、目标路由规模及按核扩展一起测量。
成本为 FIB 查询、固定头窗口及一次 RX→TX 拷贝；网关扩宽按共享成员承担，前缀记录宽度不变。每包只选择一个邻居表，无额外锁或分配；整机性能仍待验收。

## 未完成范围

VRF、NAT 与有状态防火墙、二层桥/VLAN、其余转发参数、ICMP Redirect、IPv4 源路由策略/其余选项、多播路由及多核数据面仍在路由计划内。
主机协议与唯一 ARP 机制当前仍使用原接口引擎；原生主机栈替换及移除 smoltcp 的目标不变，不能据此把现有引擎固化为最终实现。
