# 网桥与 VLAN

`router-config` 持有稳定配置，`netstack::inet::switching` 在同一网络域独占运行时端口配置、生成树和动态 MAC 表。
`packet-wire` 负责 Ethernet、802.1Q 和 BPDU 字节格式，NIC 拥有 DMA 和发送窗口。配置见[桌面网络管理器](../../user/programs/network-manager/README.md#网桥与-vlan)和[命令行](../../user/libraries/network-config/README.md#网桥与-vlan)。

## 二层转发

1. 成员端口在 IP 接收前交给二层 owner，使用原 RX 借用并保留 AF_PACKET 可见的原帧。物理成员不启动自己的 DHCP、ARP、ND 或 RA。移出网桥后恢复按接口配置处理。
2. 单层 802.1Q C-tag 使用帧的 VID。无标签和 VID 0 使用端口 PVID。端口须是该 VLAN 的成员。VID 4095、S-tag 和多层标签不准入。出站按端口的成员设置加标签或去标签，带标签时保留 PCP 和 DEI。
3. 学习键为网桥、VID 和合法单播源 MAC。地址移到新端口时更新归属。已知单播只发到指定合格端口，同端口目的过滤。未知单播、组播和广播只发往同网桥、同 VLAN 的合格端口。两个隔离端口之间不交换帧。
4. 端口移除、关闭或载波换代后退休该端口的学习项。已学习地址空闲 300 秒过期。每域最多 8192 项，满表或新节点分配失败时未学习的目的继续按未知单播处理。
   老化计时按最早登记期限唤醒。已刷新地址到期时重排原节点，其余按预算回收。目的查找始终按实际有效期判断。[Linux v6.12 FDB 老化](https://github.com/torvalds/linux/blob/v6.12/net/bridge/br_fdb.c#L502-L543)
5. `01:80:c2:00:00:00` 至 `01:80:c2:00:00:0f` 的链路本地帧不泛洪。生成树 BPDU 从物理成员直接投递给该桥的控制状态。

VLAN 成员关系、受控泛洪和端口隔离对照 [IEEE 802.1Q](https://www.ieee802.org/1/pages/802.1Q.html) 及 [Linux v6.12 bridge](https://docs.kernel.org/6.12/networking/bridge.html)。

## 生成树

1. 一座桥默认启用一棵覆盖所有成员 VLAN 的生成树。桥标识由配置优先级和成员的最小有效 MAC 组成。根端口按根桥、总路径代价、上游桥与端口、本地端口顺序选取。
2. BPDU 使用未加标签的 802.3 LLC 帧，入口不受 VLAN 成员或数据转发状态限制。阻塞端口不学习也不转发数据。学习端口可学习源地址，只有转发端口可转发数据。
3. 点到点链路可以通过提议和确认快速进入转发。根端口确认前关闭其他非边缘指定路径。备用端口保持阻塞，满足链路和对端状态条件时接替失效的根端口。
4. 未完成握手的端口依次经过阻塞与学习的转发延迟。显式边缘端口可立即转发，收到有效 BPDU 后失去边缘资格。收到传统 STP 消息的端口使用该链路的传统 BPDU 和时钟。
5. 载波换代、拓扑变化及新树切换退休相关学习项。控制发送使用独立的有界预算和每端口发送限额。发送窗口不足时定时重试，静默链路也会定时发出 BPDU 和退休过期信息。

`inet::timing` 查询交换域的定时工作。协议轮次在接收数据前更新端口状态，在接收前后各推进控制发送。网卡适配层只在提交发送窗口成功时返回确认，生成树据此记录已发出的提议。

协议依据见 [IEEE 802.1D-2004](../standards-baseline/network.md#报文字节格式)。较新 BPDU 的共同树字段按 802.1D 读取。本期仅支持单树。

## 配置事务

成员引用现有接口配置名。设备不在时保留持久成员意图，再次出现时解析新的接口身份。每个物理端口只能加入一座网桥，单域最多 256 个成员。
桌面加入已配置三层地址的物理端口前要求确认清除原设置，成员关系和配置清除在同一草稿审阅提交。取消或校验失败时沿用原决定。
执行正文版本 5 的整数使用小端序。头部为 u32 版本、u16 网桥数、u16 网关数、u8 投影标志及三个保留零字节。
每座桥有 u16 优先级、u8 RSTP 开关和一字节保留零，按 1 起始的桥编号索引。
网关按桥号、VID 排序。定长头依次为 u16 网桥、u16 VID、16 字节零填充接口名、4 字节 IPv4 地址、u8 IPv4 前缀长度、u8 保留零、u16 IPv6 地址数，
u32 候选接口号、u16 MTU、u8 载波样本、u8 保留零、u16 最大 RA 间隔、u16 默认网关寿命、u32 DNS 地址数。未解析身份的绑定槽为零。
定长头后是 IPv6 地址行及每行 16 字节的 RDNSS 地址。IPv6 地址与 RA 字段沿用接口配置的格式。
端口按接口索引排序。每项为 u32 接口、u16 网桥、u16 PVID、u16 VLAN 数、u8 标志（bit0 隔离、bit1 边缘、bit2 点到点）、u8 保留零、u16 端口号、u32 路径代价。
VLAN 成员为升序 u16 VID，最高位表示去标签。PVID 为零表示拒绝无标签数据入口。头部零网桥、无端口表示清除。多余字节、重复端口及非法 VLAN 拒绝。
沿[同一配置租约](router-configuration.md#复合网络执行批次)预备、激活、确认或撤销。撤销归还原成员和仍有效的学习项，并重新收敛原生成树。等价配置保留学习表和生成树状态。

PROJECT_BRIDGES(13) 在同一授权链上只读解析 VLAN 接口。版本 1 请求为 u32 版本、u64 桥正文长度、u64 物理接口计划长度，依序传桥正文和可选接口计划 VMO。
回复为 u64 长度及单个同长度的桥正文 VMO。NET 依据候选桥和物理计划给出 ifindex、MTU 与载波样本，不分配接口或占用租约。
配置 owner 用投影解析接口引用，RIB 用同一正文计算候选可达性。NET 预备时重新校验身份和 MTU。拓扑或计划失配时返回重试，活动接口、路由和规则保持原状。

有桥正文时，RIB 以候选 VLAN 接口覆盖活动 VLAN 地址和接口事实。保留同身份、同地址且仍有载波的 IPv6 资格，新地址为 Tentative。
无接口的网关与待撤销的旧地址不提供递归可达性，普通物理接口和回环继续使用已有候选覆盖规则。
完整配置批次通过现有接口行携带每个已解析 VLAN 的下游委派，空集合撤回旧分配。NET 只允许该行补充委派，拒绝静态事实冲突、重复身份及已退休的接口。
候选网关、静态地址和委派一起准备和撤销。仅更新租约时沿同一接口行提交，保持网桥拓扑和静态策略。
租约更新读取已确认的下游身份，配置事务结果不明时等待重放。
名称引用与运行时身份分别参考 [RFC 8343 §3.2](https://www.rfc-editor.org/rfc/rfc8343.html#section-3.2) 和 [RFC 8342 §5](https://www.rfc-editor.org/rfc/rfc8342.html#section-5) 的配置与运行状态划分。

## VLAN 网关

1. 管理配置按桥和 VID 指定静态 IPv4/IPv6 地址与接口名。VLAN 名称和物理接口配置名称在同一命名空间内唯一，可被静态路由、选表和防火墙规则引用。执行层在同一租约预备接口、更新直连路由和规则。
   激活前接口不可查询。删除后待确认的接口仅保留给回滚。
2. 新接口使用该 VLAN 首批可用成员中的最小有效 MAC。已存在的同一接口保留 MAC。MTU 使用成员中最小的 L3 MTU。没有已解析成员时保留配置意图，已有接口失去载波。
3. 单播目的为网关 MAC 时交给该 VLAN 逻辑接口。广播和组播也可送本地协议栈，按原准入规则继续桥接。阻塞端口和非成员 VLAN 都不能向逻辑接口递交报文。
   网关仅在所属 VLAN 应答其 IPv4 地址的 ARP 查询。
4. 逻辑接口共用常规 ARP、ND、分片、IP 转发、策略与 AF_PACKET 路径。出站按该 VID 查询同一 MAC 表，按物理端口成员设置封装。逻辑载波随可转发成员变化，断链及成员重配时退休旧队列。
5. 名称和 VID 相同的 VLAN 网关保持接口身份，桥的排序或成员变化不会重新分配 ifindex。未解析的网关暂不参与选路，绑定该接口的防火墙规则不会匹配任何入口。
6. VLAN 可配置独立的 DHCPv4 池及 IPv6 路由通告。DHCP 池由配置服务按实际接口绑定，在地址和接口变更确认后生效，租约可按 VLAN 接口名查询。
   RA 可发布静态及上联委派前缀、默认网关和 RDNSS，启用 IPv6 转发后才发布。保留 VLAN 并停用 RA 时可发送撤回，删除 VLAN 后客户端的旧设置按已通告寿命到期。
   [DHCPv4](ipc-network.md#dhcpv4-下游地址分发)、[IPv6 通告](ipv6-link.md#下游路由通告)

## 性能与验收

无桥端口不分配学习节点。二层接收批省去主机头部解析和入口 TX 预约。已知单播通过有界查找定位出口，泛洪和 IP 转发共用本轮发送预算，背压或预算耗尽按尽力交付处理。
出站直接填 NIC 窗口，每个实际出口复制载荷一次，不复制输入帧或新增逐帧锁。单标签开销计入驱动帧容量，VirtIO 可提交 1518 字节。吞吐、泛洪与学习开销纳入整机多网卡基准。
宿主网卡夹具覆盖标签转换、VLAN 与端口隔离、地址迁移、回滚及链路本地帧过滤。两桥双链路夹具覆盖 BPDU 帧格式、广播去重、断链后双向流量切换及传统拓扑通知的应答。
生成树选路只在载波、收到的新选路信息或超时改变有效路径时重算。规模基准覆盖桥端口扫描和拓扑变化时的学习表重建。来宾 VirtIO、第三方网桥互通与实机接收过滤待整机验收。
每个学习项一个期限节点，常规刷新只更新归属和实际期限。普通轮次只检查缓存的最早期限。整机比较满表空闲唤醒、刷新吞吐、集中到期时的域锁时长和桌面输入延迟。
配置了三层接口的 VLAN 各自预备有界收发槽。L2 纯交换不经过这些槽。逻辑收发各增加一次到接口槽的复制，不新增逐帧分配或共享锁。无出口接受时保留背压队首，已部分发送的泛洪不重放。
整机基准应覆盖纯交换和跨 VLAN 路由的吞吐、队列背压和内存。宿主双栈夹具覆盖网关与策略同批发布、静态路由、过滤计数、标签转换、发送恢复和网关撤销。
逻辑 AF_PACKET 发送直接写入合格网卡的发送窗口。只有全部合格出口完成提交才确认探测成功，背压时调用方可重试。
地址分发夹具覆盖带标签的 DHCPv4 探测与租约、背压、VLAN 隔离，以及 IPv6 默认网关、前缀和 DNS 的通告及停用。
委派夹具覆盖同一中继上的两个 VLAN 分配不同前缀，续租换号及配置移除后检查标签、通告与路由撤回。租约变更只在控制面读取一次接口快照，复用 IPv6 选路与通告，性能纳入现有转发基准。
